# 현재 Expo 탭 탐색기

메뉴 영역의 `재료 설정`(`recipe_ingredients`)은 `/recipes/ingredients`의 재료 마스터 설정 화면을 연다.
부자재 관리처럼 검색·카테고리 배지·기준 단가·수정/삭제·등록 버튼을 제공하며 기존 식재료 훅과 등록/수정 화면을 사용한다.
프로토타입에 없는 AppMap 탐색 항목이므로 원본 audit 집합 검증 후 `appmapOnly`로 추가한다.

메뉴·식재료·부자재 관리는 `managementGroups`로 하위 화면을 묶는다. 목록/등록/상세/수정(해당 기능이 있는 관리만)/카테고리 편집/목록 편집을 실제 Expo 경로로 연결하고, 하위 화면에서도 상위 관리 탭을 유지한다. 중복 메뉴·부자재 카테고리 상단 탭은 숨긴다.
더보기·항목 메뉴·수정 하위·삭제 확인은 기존 Expo 버튼을 열고 결과를 관측한다. 항목 메뉴는 텍스트를 가진 목록 행을 선택하여 아이콘 전용 헤더 ⋮와 구분한다. 영업 중 수정은 확인창에 머물고, 영업 전/종료 후에는 수정 화면 진입을 확인한다. 삭제 확인을 확정하지 않는다. 메뉴 목록 삭제는 영업 중·브레이크 중 차단되므로 해당 상태의 삭제 확인 미노출은 정상이다. 카테고리 ×는 빈 카테고리의 삭제 확인 또는 사용 중인 카테고리의 삭제 불가 안내를 연다.

부자재 관리 하위에 추가·수정 페이지를 제공한다. 추가는 `/recipes/material-edit`, 수정은 관리 목록의 실제 항목에서 기존 영업 상태 확인을 거쳐 `/recipes/material-edit?id=…`로 이동한다. MY에서도 같은 관리·입력폼을 사용한다. 기존 `material_add`·`material_edit` 팝업 링크는 호환을 위해 남기되 실제 페이지 전환을 관측하며, 카테고리 선택만 공용 선택 시트로 표시한다.

부자재 상세는 목록의 ‘자세히 보기’에서 `/recipes/material-detail?id=…`로 연결된다. AppMap 관리 하위 ‘상세’와 ‘더보기’는 같은 실제 경로와 헤더 세로 ⋮를 열며 수정·삭제·닫기를 관측한다. 자동 열기는 삭제를 확정하지 않는다.

관리의 목록·카테고리 편집에는 저장 확인 탭을 제공한다. 첫 항목을 키보드 동작으로 아래로 옮겨 화면 초안만 바꾼 후 저장 확인창을 열고 멈춘다. 확인창의 저장 버튼은 자동으로 누르지 않으며 1개 이하 목록에서는 이동할 순서가 없어 열리지 않는다.

발주 메인의 '미 선택'은 샘플 전용 항목이다. 현재 발주 후보의 발주 완료 페이지에 선택 가능한 구매 옵션 2개(1kg·28,000원 / 3kg·78,000원)를 제공하지만 초기에는 아무 옵션도 선택하지 않으며 DB 저장은 차단한다.

재고 수정 샘플은 서버 시계·재고 발생시점 조회를 허용한다. 로컬 DB에 inventory_event_occurrence_context가 없어 404가 난 경우에만 stock_change 화면·하위 팝업에서 미실사 예시 응답을 제공하고, 서버 미지원 안내를 표시한다. 인증·권한·서버 오류는 예시로 덮지 않으며 실제 입고 저장은 계속 차단한다.

발주 후보의 주문하기는 실제 `/orders/place?ingredient=…` 페이지로 이동한다. 구매처 선택 시트에서 옵션을 고르면 본문에 구매 링크를 표시한다. 기존 앱맵 주문하기 항목도 페이지 이동 후조건으로 검증한다.

매출관리는 현재 피드와 작성 화면을 분리해 표시한다. `매출 작성` 아래의 `목록`에는 정렬·작성 상태·영업일 분류를 두고, `작성 상세`에는 매출 미리보기·판매 수량·기타 매출·추가 지출·내역 삭제 확인·재고 부족 안내를 둔다. 현재 흐름에서 진입하지 않는 옛 손익 상세와 과거 판매 수정 화면은 전체 인벤토리에만 보존한다.
