# 전수조사 Finding 및 처리 현황

## 수정 완료

1. 세금 별도 판매에서 세금을 0으로 만들던 DB 계산을 수정했다. 순매출은 판매가를 유지하고 세금은
   고객 결제액과 납부 부채에 더한다.
2. 과거 국제 기타매출 수량을 원본 snapshot 기준으로 복원했다.
3. v2 세금 snapshot이 없는 과거 판매는 legacy 채널 세금과 구성 항목을 사용한다.
4. 메뉴 없는 매장도 사용자 채널을 지정한 기타매출·추가 지출만 저장할 수 있다.
5. 메뉴 과세 예외는 판매일 이하의 가장 최근 적용일만 선택한다.
6. 중지·삭제 메뉴의 과거 정정은 기존 확정 수량 이하를 허용하고 증가만 차단한다.
7. 채널별 부자재비는 메뉴별 단가와 해당 채널 판매수량으로 직접 귀속한다.
8. 수정 중 매출 미리보기는 먼저 저장한 최신 서버 계산값을 연다.
9. 세금 상세 화면은 legacy와 국제 판매가 섞여도 서버 전체 합계를 숨기지 않는다.
10. ING-05의 실제 재고 수정 경로와 소스 컴포넌트 결속을 바로잡았다.
11. 고정 지출 기준이 비어 있으면 메뉴 손익 추이에 과거 월 비율이나 0%를 기록하지 않는다. 필수 월을
    입력한 시점에 실제 비율로 첫 계산 기준선을 만든다.
12. 매출 초안의 메뉴 세금을 1개 세액×수량으로 계산하지 않고, 봉인된 구성 세금의 반올림 전 금액을
    확정 원장과 같은 채널 판매 총액 기준으로 반올림한다. 초안과 확정 합계를 회귀시험으로 고정했다.
13. AppMap의 과거 추가 지출 추가·삭제 표면은 현재 매출 작성 시트로 재결속했다. 재고 부족 배지와
    메뉴 매출 펼침은 독립 팝업에서 제거하고, 고정 지출 항목 추가는 실제 설정 화면으로 옮겼다.
14. MY-11 구매처 목록·추가·이름 변경·삭제 확인을 실제 화면과 공용 Sheet로 검증했다. 최신 자동
    인벤토리의 207개 표면 모두 직접 시험 파일에 연결된다.
15. 0128 이전 판매에서 현재 채널명을 이관한 행과 이후 판매 저장 시점 snapshot을 구분한다. 세금
    상세은 이관 행에 `채널명 이관 당시 기준`을 표시해 복원할 수 없는 과거 이름을 판매 당시 이름으로
    단정하지 않는다.
16. 매장 영구 삭제 cascade 중 `settings` 기준 변경 트리거가 이미 삭제 중인 매장에 쓰기 잠금을
    다시 걸어 FK 오류를 내던 경합을 수정했다. 기준 변경·발행 트리거는 부모 매장이 존재할 때만
    잠금과 재계산을 수행하고, 매장 삭제 자체의 cascade는 정상 완료한다.
17. 발주 묶음을 항목별 순차 E7 호출에서 요청 키가 있는 원자 RPC로 바꿨다. 응답 유실은 로컬 저널과
    서버 결과 조회로 먼저 확인하고, 같은 키 재호출·payload 충돌·다건 부분 실패·실제 2세션 경합을
    회귀시험으로 고정했다. 발주만으로 재고·단가·원장을 바꾸지 않는 불변식도 함께 확인했다.
