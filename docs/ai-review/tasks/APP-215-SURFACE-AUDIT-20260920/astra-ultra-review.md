# Astra Ultra 독립 검토

기준일: 2026-09-20  
범위: 판매 채널·세금·매출 초안·업그레이드 원장, 읽기 전용 소스와 SQL 재현

## Finding

| 심각도 | Finding | 처리 |
|---|---|---|
| P1 | 국제 기타매출 snapshot의 `quantity`를 `qty`로만 읽어 이관 수량이 1로 바뀜 | 0135에서 `quantity` 우선·`qty` 호환으로 원본 snapshot 재구성, 이관 데이터 회귀 추가 |
| P1 | 모든 과거 판매를 v2로 바꾼 뒤 v2 세금 snapshot이 없는 행의 legacy 세금을 무시 | v2 부재 시 legacy 채널 snapshot 우선 사용, legacy 구성 항목도 breakdown에 포함 |
| P2 | 메뉴가 없는 사용자 채널 매장은 기타매출·지출만 저장할 수 없음 | 빈 `p_items`를 동적 계약으로 판정, 기타매출 저장 회귀 추가 |
| P2 | legacy 판매의 세금 합계는 있으나 항목 상세가 빈 배열 | legacy component snapshot 합산 경로 복원 |
| P2 | 수정 뒤 미리보기가 마지막 저장 응답을 표시 | dirty 상태에서 서버 저장 후 권위 preview를 열도록 변경 |
| P2 | 초안과 확정의 세금 반올림 단위가 다름 | 미해결. 초안은 단가 기준, 확정은 채널 총액 기준인 경로를 하나로 합치는 후속 변경 필요 |
| P2 | legacy+국제 혼합 기간에서 앱이 legacy 세금을 숨김 | 화면이 서버 전체 summary를 항상 표시하고 국제 line은 상세로만 표시 |

추가로 `tax_exclusive`를 세금 0으로 처리하던 구현이 프로젝트 절대 계약과 충돌함을 확인했다.
0135에서 세전 순매출은 유지하고 세금을 고객 결제액에 더하는 공식을 복원했다.

이 문서는 Astra Ultra의 읽기 전용 검토 결과를 사람이 읽기 쉽게 옮긴 기록이다. Fable 검수 결과가
아니며, 전체 네이티브 화면 실행을 수행했다는 뜻도 아니다.
