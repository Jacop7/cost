# SIGNUP-FIRST-ACCESS-20260915 검수 근거

## 판정

한국 첫 출시에서 앱 안 이메일 회원가입을 필수로 제공한다. 기존의 운영자 사전 발급·초대 전용
결정은 최신 사용자 결정으로 폐기했다. 회원가입 → 세션 또는 이메일 확인 대기 → 사용자 검증 →
기존 매장 선택 또는 최초 매장 등록 → 업무 화면 진입은 로컬 구현과 시험을 마쳤다.

현재 판정은 **로컬 구현·대상 검증 완료, 출시 승인 전**이다. 호스티드 Auth·메일·법률 문서·대상
빌드 smoke와 동일 입력 판본의 전체 게이트, Fable 독립검수는 남아 있다. Fable 작업
`SIGNUP-FIRST-ACCESS-20260915` r001을 시작했지만 실행기가 `PROVIDER_HARD_CAP_UNAVAILABLE`로
Claude 호출 전에 중단했으므로 검수 결과나 Finding은 생성되지 않았다.

## 오류·재시도·격리 계약

- 빈 값, 8자 미만 비밀번호, 비밀번호 확인 불일치는 Auth 호출 전에 막는다.
- 이메일은 앞뒤 공백을 제거하고, 비밀번호 두 필드는 가린다.
- 잘못된 이메일, 약한 비밀번호, 요청 과다, 가입 비활성, 일반 제공자 오류와 네트워크 예외를 안전한
  사용자 문구로 바꾼다. 제공자 원문과 이메일 존재 여부는 표시하지 않는다.
- 가입 실패 뒤 입력과 가입 화면을 보존해 다시 제출할 수 있다.
- Auth가 세션을 반환하지 않으면 이메일 확인 안내를 표시하고 로그인으로 돌아간다.
- Auth가 세션을 반환하면 저장된 세션을 다시 읽고 `getUser`·stores를 검증한다.
- 로그아웃·다른 사용자·다른 매장·같은 사용자의 새 로그인 세대에서 이전 쿼리를 취소하고 캐시를
  비운 뒤 새 화면을 연다. 토큰 갱신만으로는 불필요한 세대 변경을 만들지 않는다.
