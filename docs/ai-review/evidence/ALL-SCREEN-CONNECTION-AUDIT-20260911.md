# 전체 앱 연결 검수 — 진행 중

## 판정 기준

검수 대상은 레시피만이 아니라 식재료·레시피·발주·매출관리·MY 전체다. 페이지 진입, 하단 결과 영역, 카드·버튼 이동, 팝업, 저장/오류/재시도/취소 후 경로를 각각 검사한다. 페이지가 열리거나 라우트가 존재하는 것을 기능 완료로 판정하지 않는다.

2026-09-11 현재 prototype/registry에는 화면 62개·팝업 상태 123개, 총 185항목(숨김 3)이 있다. buildModel의 경로 미매핑은 0이다. destination의 실제 데이터 모드 분류는 direct 172, unavailable 9, alternate 4이다. **이는 정적 메타데이터 결과이지 172개 실동작 통과가 아니다.** 모든 팝업의 직접 조작 검수는 아직 진행 중이다.

기존 페이지 진입 결과는 SCREEN-RENDER-HOTFIX-20260911.md를 참고한다. 본 문서는 그 결과를 전체 기능 통과로 확대하지 않는다. 운영 배포 미실행. 이번 검수에서 저장·삭제·취소 등 실제 원장 변경은 하지 않았다.

## 미연결로 오판하면 안 되는 상태

- 구매 링크 있음/없음: 실제 데이터에 의존하며 상태를 만들기 위해 데이터를 삭제하지 않는다.
- 최근 기록 더보기: 사용자가 삭제한 기능, 취소 버튼으로 대체. 복구 대상 아님.
- 입고 실패·단가 급등·판매 부족·설정 저장 완료: 실제 쓰기/오류 결과에 의존하므로 미구현으로 단정하지 않는다. 격리된 시험 경로 필요.
- 과거 판매 저장: 기존 장부는 즉시 정정, 장부 없는 날만 확인. 코드에 명시된 분기이며 무조건 확인창 누락으로 분류하지 않는다.
- 단가 산출 전·고정지출 없음: 정상적인 데이터 불확정과 계산 함수 누락을 구분해야 한다.

2. 모든 화면의 하단까지 결과 행과 조건부 섹션 점검. 준비 중 검색 결과만으로 전수검수 완료하지 않는다.
3. 실제 로컬 DB 함수 목록과 모든 화면의 RPC 의존성 대조. 프런트 구현/DB 미반영을 분리한다.
4. 쓰기 확인은 격리 시험·기존 승인된 DB 절차로 수행. 실제 재고/원장 보존.
5. 수정 우선순위와 최소 배포 의존 범위 산출 후 exact SHA 시험·독립검수·CI·배포 가드. 본 문서는 완료/배포 승인 아님.
