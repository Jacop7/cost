## 범위와 확정 동작

식재료 구매 가격·개당 용량·단가, 메뉴 판매가·기준 인분·목표 순이익률, 부자재 선택·추가·제거·금액, 고정지출 항목·금액·매출 분모, 세금 항목·요율·가격 기준·납부 주체의 연결 변경을 점검했다. 분류표는 `docs/식재료-레시피-수정내역-최종기획.md` §14가 권위이며, 표에 있다고 모든 가능한 입력을 시험했다는 뜻은 아니다.

- 영업 전·종료 후에는 현재 메뉴 기준에 반영한다. 영업 중·브레이크에는 시작 스냅샷을 보존하고 종료 후 최종 변경을 반영한다. 서버 영업 상태 전환 시 하위 메뉴 기준 쿼리도 갱신한다.
- 식재료 직접 구매 가격·용량 수정은 현재 기준단가와 연결 메뉴 원가·손익을 갱신한다. 다음 성공한 입고·부분 입고·취소는 실입고 평균으로 전환한다. 메뉴 판매가를 임의로 변경하지 않는다.
- 메뉴 기준 인분·목표율만 바뀐 경우도 반영 대기 이력에 포함한다. 같은 금액의 항목 구성 교체는 이력에 남기고 무변경 저장은 사건·판본·추이를 늘리지 않는다.
- MY 세금·국가 화면은 시장·세금의 두 판본을 검사하는 원자 저장을 공유한다. 메뉴별 명시 과세·분류 선택·기본값 상속을 구분하고 새 프로필로 유효한 선택을 승계한다.
- 적용되지 않는 세금 변경은 메뉴 대기를 만들지 않는다. 표시 이름·같은 과세 상태의 상속·다른 과세 상태로 적용 범위 확대는 실제 해당 메뉴 계산이 같으면 정보성 이력이다. 새로 영향을 받는 메뉴에는 재무 사건을 남긴다.
- 고정지출은 당월 모든 메뉴에 전파한다. 다른 월 정정은 해당 월 손익·설정 이력에 기록하고 현재 메뉴의 대기를 만들거나 현재 가격으로 과거 메뉴 추이를 합성하지 않는다.
- 과거 원장·종료 스냅샷·기존 유실 연결은 추정 복구하지 않는다. 원격 DB·Git 커밋·푸시는 이번 단계에서 수행하지 않는다.

## 적용·잔여 검증

개발 DB에 0215~0227 적용을 완료했다. 백업은 `before-tax-linked-0215-1789203529468.sql`, 실행·검증 영수증은 `tax-linked-local-receipt.json`이다. 기존 데이터 18개 테이블의 행 수·해시 불변을 확인했다(새 기본값 컬럼 inherit_default만 비교에서 제외). 관련 함수 24개의 본문·소유자·보안 모드·권한은 두 격리 DB와 일치한다. 두 기존 함수의 CRLF/LF 및 ACL 배열 순서 차이 때문에 최초 원시 비교는 실패했고, 줄바꿈만 LF로 정규화하고 ACL을 집합으로 비교하여 일치를 확인했다. 원시 해시 차이와 최초 실패 로그는 보존하며 바이트 동일로 표현하지 않는다. PostgREST 스키마 캐시를 갱신했다. 실제 사용자 시험 저장·과거 데이터 재계산은 하지 않았다.

권한 감사 목록 동기화는 Claude R11에서 DB16/34의 정확한 계약과 일치, 신규 P1/P2 없음으로 확인했다. 별도 인벤토리 강화·중복 상한의 단일 출처화 권고는 후속 사항이다.

실제 Expo 조회에서 ROOT가 현재 세액 1,091원/판매가 12,000원과 예약 MY 요율 8.6580%가 혼합되는 문제를 발견했다. 메뉴 세금 상세를 현재 quote·시장·구성·해석된 treatment로 통일하고, 0228로 현재 과세 분류를 같은 RPC 문맥에 추가했다. 시험 86에서 프로필 변경 없이 메뉴 과세 선택만 변경하면 종료 후에도 0원으로 남는 추가 반례를 확인했고, 0229로 종료 후 기준일에 해당 프로필의 메뉴 예외 적용일을 포함했다. 수정 전 실패 → 22단언 통과를 확인했다. 두 변경은 같은 일회성 Astra 검사의 후속 메시지 및 Claude R12에서 신규 P1/P2 없음으로 재검수했다.

0228~0229도 백업 `before-current-tax-context-0228-1789204026232.sql` 후 개발 DB에 적용했다. 최종 버전은 **20260912000229**, 영수증 `current-tax-context-local-receipt.json`의 기존 데이터 18개 테이블 불변 및 정규화한 함수·권한 일치를 확인했다. Expo 실제 세금 상세는 1,091원·세금 제외 10,909원·적용 요율 9.0909%로 일치한다. 사용자 데이터로 저장/영업 전환을 시험하지 않았다.

미해결 제한: 커밋에 결속된 3표면 바이트 증빙은 현재 미커밋 작업 트리와 맞지 않는다. 과거 참고 가격 수정·유실된 부자재 연결은 소급 추정하지 않았으며, 구형 시장 단독 RPC는 초기 설정 호환을 위해 남아 있으나 실제 앱 진입은 원자 저장만 쓴다. 이 보고서는 실기기·접근성 전체 검수나 운영 배포 승인이 아니다.

최종 업그레이드 검사에서 0188의 기존 함수가 CRLF일 때 0217의 다중 행 앵커가 맞지 않는 추가 오류를 발견했다. 원격 미배포 0217의 market 함수 정의·앵커·치환문을 CRLF→LF로만 정규화했으며 정확히 1개라는 가드는 유지했다. 시나리오 23에 SQL77 원자 세금 저장과 SQL86 종료 후 과세 반영 시험을 추가했다. 기존 개발 DB에는 0217을 다시 적용하지 않았다. 격리 DB 트랜잭션에서 수정된 변환을 실행하고 rollback한 결과 개발 DB의 정규화된 함수 본문·소유자·권한과 동일했다(`217-normalization-equivalence.json`). 같은 일회성 Astra 후속 검수에서도 새 P1/P2 없음과 CRLF/LF 동일 동작을 확인했다.

최종 작업 트리 소스·시험·검수·실행 로그 해시는 `.codex/material-history-20260912/final-linked-source-manifest.json`에 보존한다. 이 목록은 미커밋 작업 트리 증거이며 커밋 결속 3표면·실기기 증빙을 대신하지 않는다.

Claude R13에서도 0217 정규화와 시나리오23 보강에 신규 P1/P2 없음으로 검수했다. R13이 읽은 시점에는 실행 로그가 미완료였으므로 실행 통과는 Claude 판정으로 인용하지 않는다. 이후 ROOT가 종료 코드 0·행동 시험 6파일 통과·임시 DB 정리를 직접 확인했다. 줄바꿈 관용구 통일 및 향후 SQL 언어 함수까지 CRLF 주입을 넓히는 P4 권고는 후속 사항으로 보존한다.

앞선 R6의 미세 반올림 경계 추가 검토, 마감 추이 원인의 식재료명·단가 출처 표시, R12의 면세 화면에서 비적용 primary 법정 세율 행 표시 등 세부 UX 권고는 이번 완료 범위에 포함하지 않는다. 기본 세금 구성은 현재 견적에서 읽으므로 예약 값 혼합은 해소됐지만, 이 권고까지 해결했다고 표현하지 않는다.
