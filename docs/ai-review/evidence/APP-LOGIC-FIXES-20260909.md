# 앱 기능 감사 후 공용 조회 갱신 결함 수정

- 요청: 전체 기능 감사에서 확인된 결함 중 진행 중인 Expo UI 수정과 충돌하지 않는 부분을 수정한다.
- 선행 감사: [전체 기능 감사](./APP-ALL-FUNCTION-AUDIT-20260909.md). 선행 감사와 원본 시험 결과는 수정하지 않았다.
- 범위: 공용 쿼리 무효화와 도메인 저장 훅. 화면·컴포넌트·테마·Expo 설정·DB 스키마는 이번 작업에서 수정하지 않았다.
- 상태: 제품 결함 3건 수정, 앱 시험 242개 통과. 필수 전체 검증은 기존 실패 2단계가 남아 있으며, 전체 기능 정상 또는 프로젝트 완료 판정이 아니다.

수정 후 1회 조회를 검증했다. 서버 계산, RPC 인자와 저장 값은 바꾸지 않았다.

## 변경 분리와 검수 상태

최신 `origin/main` `59738f43d300e8febc119744b122b4d399f3f15b`를 부모로 한 로컬 브랜치
`codex/app-cache-invalidation-fixes`에 위 3개 파일만 커밋 `0171ddf05fb6ae5ef0418b85ebc4d79471293bcf`로
보관했다. 임시 Git index로 내용을 구성했으며, 사용자가 작업 중인 체크아웃·HEAD·기존 index의
바이트 hash는 전후 동일하다. 증거는 `branch-receipt.json`이다. 현재 작업본에도 수정이 남아 있으므로
UI 작업 도중 다른 브랜치로 전환하거나 같은 변경을 중복 적용할 필요가 없다.

실행 시험은 권위 작업 루트의 작업본에 대한 결과이며, 별도 커밋의 exact-SHA CI 결과가 아니다.
원격 push, main 합류와 배포는 하지 않았다. 소스 322개의 감사 전후 hash 비교에서 제품 변경은
공용 로직 2개 파일로 한정됐다(`source-integrity.json`, `source-integrity-final.json`). 테스트 파일은 새로 추가했다.

독립검수 작업 패킷은 `docs/ai-review/tasks/APP-LOGIC-FIXES-20260909/task.json`이다.
저장소 실행기가 실제 결제 상한을 보장하지 못해 Fable 호출 전에 중단했다. 정확한 비용 위험 승인
기록이 없으므로 soft-budget 허용을 임의로 만들거나 Opus 승계로 우회하지 않았다. 독립검수 종결과
보호 게이트 통과를 주장하지 않는다.

## UI 수정과 겹치는 미수정 결함

나머지 APP-AUDIT-01~07, 11~13의 10건은 화면·시트 내부의 계산·입력·상태 로직을 수정해야 한다.
사용자가 Expo를 수정 중이라고 알려왔고 정확한 파일 범위가 확인되지 않아 이번 공용 로직 수정에서
제외했다. 음수 재고 보정, 세금·손익 계산, 설정 판본 충돌, 고정지출 오류 복구, 부자재 단가 반올림,
새 레시피 미리보기, 과거 조회 오류 처리, 통화 소수 입력, 부자재 손익 누락, 폐기 이력 금액 문제는
선행 감사에 남아 있다. 해결 또는 독립검수 종결로 표시하지 않는다.
