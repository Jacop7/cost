# 전량 차감·폐기 결과 복구 검수 — 2026-09-14

## 발견과 수정

FN-ING-007/008에서 1,000g을 전량 차감하거나 폐기한 뒤 서버 응답만 유실되면,
재진입 시 재고는 0인데 화면의 양수 수량 검증 때문에 이전 요청의 결과 확인에도 도달하지 못했다.
기존 요청 보관·서버 resolver가 있어도 화면의 접근 경로가 막혔던 문제다.

수량 요청 helper와 훅에 수량 없는 hasPending/resolvePending 경로를 추가하고,
화면에 미확인 요청이 있을 때 ‘이전 처리 결과 확인’을 제공한다. 저장소 확인이 실패한 경우에도
결과 확인 경로를 남긴다. 현재 재고 0/음수, 빈 수량·사유에서 이전 결과만 확인할 수 있다.
새 차감·폐기의 양수 수량·확인 재고·사유·최신 조회 검증은 유지한다.

서버는 기존 resolve_stock_quantity를 사용한다. 옛 처리 수량이나 사유를 영구 보관·재전송하지 않는다.
같은 사용자·매장·재료 범위와 정확한 키만 정리하고, 이전 요청의 종류가 폐기라면 차감 화면에서
확인했더라도 폐기 전파를 사용한다. 결과 확인 뒤 최신 상세가 관찰되기 전 새 쓰기를 허용하지 않는다.
화면·사용자·매장·재료·모드 전환 뒤의 늦은 완료가 새 화면을 이동시키지 않는다.

제품 변경은 stockQuantityOperation.ts, ingredients/hooks.ts, StockChangeScreen.tsx의 세 파일이다.
새 DB migration·RPC·금액 계산 변경은 없다. UI 작업에서 제거한 예상 손실 설명 문구는 복원하지 않았다.

## 현재 판정과 제한

전량 응답 유실 복구의 해당 반례는 수정했고 관련 앱 시험을 통과했다.
정적 경합 후보는 재현하지 못한 것이 아니라 실제 이전 응답·새 응답을 제어한 시험에서 기존 차단을 확인했다.
원장 중복·재고 CAS·종료 키 거절의 서버 계약은 기존 00008 및 별도 DB 시험 근거를 참조한다.
이번 화면 변경만으로 서버 모든 경합·실제 Web Locks·기기 저장소를 다시 검증했다고 주장하지 않는다.

실제 기기 증빙, 최종 전체 verify, 정식 독립검수는 별도 미완료다. 다른 과제의 Fable 하드캡 확인 제한이나
내부 보조 검토를 이 후보의 정식 Fable PASS로 쓰지 않는다. 원격 배포와 사용자 거래 실행은 없다.
