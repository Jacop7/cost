# 판매 초안·부분 저장 검수 — 2026-09-14

## 발견과 수정

대상은 오늘 판매·기타 매출·추가 지출과 종료 영업일 정정이다. 판매 중지된 메뉴의 기존 판매행을
모든 저장에 다시 보내면 다른 정상 메뉴나 기타 매출·지출의 변경까지 서버에서 거절됐다.
메뉴 수량은 선택한 행만 보내고, 기타 매출·지출만 바꿀 때는 메뉴 배열을 비워 기존 판매를 보존한다.
재고 부족과 명시적인 판매 중지의 구분, E8/E9 증분 원장 계산은 그대로다.

편집 중 다른 기기의 저장을 재조회했을 때 오래된 초안에 새 revision이 붙는 경계도 재현했다.
오늘 판매·추가 지출·지난 장부는 편집을 시작한 사용자·매장·날짜·기준 판본을 보관한다.
다른 판본을 관찰하면 기존 초안을 자동으로 최신값에 합치지 않고 다시 확인·입력하게 한다.

기타 매출·지출의 서버 저장 후 응답만 유실되면 최신 배열에 같은 입력을 더해 중복 등록할 수 있었다.
첫 전송 때 만든 목표 배열과 판본을 재시도에 사용한다. 요청 중 입력·중복 호출을 막으며,
이미 전송한 입력으로 닫았다가 다시 열었을 때 추가 금액을 그대로 재사용하지 않는다.
전송 전 취소한 입력은 기존 사용성을 유지한다. 서버 판본 충돌은 재조회·재확인 대상으로 처리한다.

지난 장부 정정은 날짜와 첫 편집의 원본 장부를 고정한다. 저장 후 새 revision을 읽기 전까지
이전 캐시로 새 편집을 시작하지 않는다. 비어 있는 장부의 최초 생성 확인에도 같은 기준을 적용한다.
사용자·매장·날짜가 바뀌거나 화면을 닫은 뒤 도착한 완료 콜백은 새 화면을 닫거나 이동시키지 않는다.

제품 변경은 SalesHomeScreen.tsx, SalesExpenseScreen.tsx, SalesPastEditScreen.tsx다.
서버 API·계산 공식·세금·원장 스키마는 변경하지 않았다. 공통 세션 캐시 격리는 별도 작업이다.

## 판정과 남은 범위

재현한 초안·응답 유실·부분 저장 경계는 수정했고 관련 앱 및 실제 DB 계약 검사를 통과했다.
공통 세션 초기화·로그아웃·다른 사용자 로그인 중 캐시 격리는 SESSION-CACHE-OWNERSHIP-20260914에서
추가로 재현하여 수정 중이다. 이 증거로 해당 세션 경계까지 완료했다고 판단하지 않는다.

정식 독립검수와 최종 전체 verify는 별도 미완료다. 과거 다른 후보의 제공자 제한을 이 후보의
독립검수 성공으로 기록하지 않는다. 실제 사용자 판매 입력·원격 DB 배포는 하지 않았다.
