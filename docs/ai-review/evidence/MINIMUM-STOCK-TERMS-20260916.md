# 최소재고 명칭 전수 조사 · 2026-09-16

사용자 요청에 따라 현재 제품의 재고 기준량 명칭을 **최소재고**로 통일했다.

## 조사 범위와 결과

- 저장소의 앱 소스·시험·공용 패키지·도구·현행 문서·프로토타입·DB migration·과거 검수 기록을 검색했다. 개발 임시 산출물 `.tmp`, `.codex`, 의존성·빌드·Git 내부는 제품 대상에서 제외한다.
- 최초 검색에서 관련 문구가 있던 저장소 파일은 204개였다. 현행 35개 파일의 162개 문구를 치환하고 생성 레지스트리는 생성기로 갱신했다. 나머지 168개는 DB 및 과거 문서·백업·검수 원본으로 분류했다.
- 추가로 축약형 `안전 {수량} 미달`을 발견해 재료 카드에서도 `최소재고 {수량} 미달`로 통일했다.
- 현재 앱·AppMap·현행 정본 HTML·확정안·UI 가이드·기능정의서에 기존 제품 명칭은 남아 있지 않다. 옛 이력의 표시 변환과 그 시험에서만 이전 문자열을 입력으로 유지한다.

| 표시 위치 | 반영 범위 |
|---|---|
| 재료 목록 | 부족 카드의 축약 라벨, 전체 부족 재고 필터 안내 |
| 재료 등록·수정 | 필드명, 접근성 라벨, 음수·빈 값 검사 안내, 충돌 시 최신값 안내 |
| 재료 상세 | 최소재고 수량 칩 |
| 발주 | 후보 사유, 빈 목록 안내, 현재 재고와 비교하는 기준 수량 |
| MY 알림 | 아침 발주 요약 항목과 설명 |
| 매출 재고 확인 | 기준 수량 라벨; 판매 필요 수량·부족 판정은 유지 |
| 수정 내역 | `safety_stock` 시스템 필드명과 해당 필드가 대표인 정형 요약의 표시 변환 |
| AppMap·정본 프로토타입 | 탐색 설명, 용어 사전, 폼·카드·알림·예시 |

## 보존 범위

`safety_stock`, `safetyStock`, `below-safety` 등 식별자, 비교 연산자, 단위·환산·수량·발주 계산은 바꾸지 않았다. 사용자 이름·메모·변경 전후 값 및 DB 원장 원문도 유지한다. 과거 migration의 이력 라벨은 수정하지 않고 앱의 읽기 경계에서 의미 키를 확인해 표시한다. 백업·과거 캡처·검수 기록은 당시 상태의 증거로 보존한다.

## 확인과 제한

- 관련 모바일 9파일 152시험 통과. 카드·재고 상태 2파일 17시험도 통과했다(두 실행에 `stockStatusContract` 3시험이 중복되므로 합산 고유 시험은 166개).
- AppMap 48시험 통과. core 269시험 통과·13개 건너뜀.
- 실제 Expo 390px 웹 미리보기에서 재료 목록·상세·발주 후보의 최소재고 표시를 확인했다.
- 레지스트리 생성 성공. 검사 모드는 기존 미커밋 migration 전이 증빙 때문에 실패했다.
- 모바일 타입 검사는 이번에 수정하지 않은 `ingredients/hooks.ts`의 `record_current_quick_inbound` RPC가 DB 생성 타입에 없어 실패했다.
- 이전 발주 작업의 전체 verify는 이 변경 전에 시작된 실행이므로 이 명칭 변경의 전체 검증 증거로 사용하지 않는다. 현재 판본 전체 verify 및 네이티브 재캡처·독립검수는 미완료다. 직전 Fable 요청이 `PROVIDER_HARD_CAP_UNAVAILABLE`로 차단된 상태에서 제공자 제한을 우회하지 않았다.
- 조사 목록·시험 로그: `.codex/minimum-stock-20260916/`. 전체 게이트 통과나 배포 완료를 의미하지 않는다.
