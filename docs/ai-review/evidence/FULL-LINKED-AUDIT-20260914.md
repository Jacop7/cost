## 검사 한계와 재실행

- 최초 전체 실행은 ①·⑥ 통과, ②·③·④·⑤ 실패였다. ②의 facade 수, ③의 변경 소스 위치/hash는 수정했다. ④는 같은 클러스터에서 다른 업그레이드 검사가 이전 전역 역할을 재생성한 충돌, ⑤는 다른 작업의 로컬 Supabase 종료 영향이 포함돼 독립적으로 다시 실행한다. 최초 실패 로그는 보존한다.
- 최신 전체 앱 재검증 `.codex/full-linked-mobile-final-confirmed.log`: 130파일 1,452통과·4개 DB 전용 제외. 마지막 no-DB 실행에서 비동기 삭제 확인 시험 1건이 실패해 이를 확인창 handler 반영까지 기다리도록 보완한 뒤 전체 앱을 다시 검증했다. 메뉴 DB 왕복 12/12, DB/core 국가·통화 parity 13/13도 `.codex/full-linked-db-tail-continued.log`에서 통과했다.
- 네트워크 미연결 `costkeep-linked-audit-20260914` 임시 컨테이너와 합성 seed만 사용해 `.codex/full-linked-verify-isolated-20260914.log`로 6단계 전체를 재실행했다. 사용자 거래 데이터는 복사하지 않았고 auth 컬럼 모양만 재현했다. 해당 실행은 ③·④·⑤ 실패이며 이후 항목별 보완/재검증은 위 표로 구분한다.
- 단가 표시 수정 뒤 전체 mobile 127개 파일 1,438 통과·4 환경 전용 시험 제외였다. 이후 추가한 매출/채널 회귀 10개도 통과했고 최종 전체 실행에 포함한다.
- 현재 작업 트리 hash를 갱신한 터치 소스 검사 통과. 네이티브 기기 증거는 기존 4건 advisory 상태이며 새 캡처·터치 검사를 했다고 표시하지 않는다.
- 화면 레지스트리 재생성 뒤 `three-surface-byte-artifacts-check.mjs`의 기존 contentSha256과 달라졌다. 해당 검사기의 `--write`는 현재 exact HEAD와 clean worktree를 요구한다. 현재 여러 기존 사용자 변경을 포함한 작업 트리이므로 커밋하지 않고 해시를 임의 교체하지 않았다. 기능 연결 orphan 0과 별도로 이 필수 바이트 증빙 게이트는 미완료이며, 검수·선별 커밋 후 공식 생성기로 갱신해야 한다.
- 국제 통화의 전체 목록 전환·입력 표기 확대는 `docs/국가-통화-세금-국제출시-기획안.md` §4.2의 단계 경계를 따른다. 단가 자릿수 설정으로 원장 통화나 과거 금액의 단위를 바꾸지 않는다. 본 검수는 모든 미래 국가 화면의 출시 완료를 의미하지 않는다.

## 검사 도구 자체의 보완

- ACL 보안 시험은 테스트용 shim/canary를 사용한다. 격리 DB 접속용으로 상속된 비밀번호 환경변수가 PGPASSFILE 테스트를 방해하므로 시험 시작에서 접속 환경을 비운다. 제품 ACL 스크립트의 거부 조건은 유지했다. `.codex/full-linked-acl-harness.log` 통과.
- 재료 경합 시험의 2초 고정 대기 대신 B 세션의 실제 Lock 대기를 확인한 후 A 세션을 해제한다. 타임아웃/원장 검증은 유지한다. `.codex/full-linked-ingredient-concurrency.log` 15개 시나리오 통과.
- 0198 migration 보존 시험은 최신 영업일 `effective` 응답에 복제된 추가 `category_id`도 비교에서 정규화한다. 전후 JSON 차이는 해당 추가 필드 하나임을 확인했다. 원장/계산 값은 계속 전체 비교한다. LF/CRLF·잘못된 anchor·재적용 거부 7개 통과. `.codex/full-linked-db-tail.log`.
- 첫 후속 세금 계약 실행은 격리 컨테이너용 관리자 환경변수 누락으로 실패했다. 환경을 전달한 재실행은 0201→0202 응답·권한·데이터 보존, 실패 rollback, LF/CRLF 및 실제 2세션 예약 변경을 통과했다. `.codex/full-linked-db-tail-continued.log`. 최초 실패를 제품 통과 증거로 쓰지 않는다.
- 업그레이드 25번은 영업 중 seed를 유지한 채 00003 재고 전환에 도달해 정상 보호 장치에 막혔다. `upgrade-check.sh`가 0237뿐 아니라 00003 앞에서도 예상 거부 사유를 확인하고 공용 `close_business_day_row`로 샘플 영업을 종료한 뒤 진행하도록 보완했다. 제품 guard나 과거 스냅샷은 우회하지 않는다. 공식 스크립트의 현재 helper와 25·26 블록을 그대로 추출해 재실행했으며, 실행하지 않은 1~24를 재통과로 표시하지 않았다.
