# 연결 변경 Astra Ultra 독립 검수 부록 — 2026-09-12

## 판정과 범위

0225 교차 검수에서 추가로 발견한 **P2 적용 범위 확장의 반영 대기 오탐은 0227에서 해결 확인**했다. 이번 0227/시험 85 및 원래 반례의 재검수 범위에서 새 P1/P2는 발견하지 못했다.

[기존 보고서](LINKED-CHANGE-ASTRA-ULTRA-20260912.md)는 그대로 보존한다. 기존 7건의 처리 상태를 다시 작성하거나 이번 검사로 전체 조합·전체 게이트·배포 완료를 주장하지 않는다.

이번 검수는 사용자가 명시한 **이번 검사 한정 Astra Ultra 예외의 연속**이다. 기본 모델, 프로젝트 모델 계획, 다른 작업 정책, 상시 Fable 독립검수 정책을 변경하지 않았다. 검수자는 소스·DB·설정·시험·Git을 변경하거나 다른 검수 엔진을 호출하지 않았고, 이번 요청에서 허용한 이 부록 한 파일만 신규 작성했다.

## ASTRA-08 — P2 · 다른 과세 상태로 범위를 넓힐 때 기존 메뉴를 재무 변경으로 판단 · 해결

반례는 과세 메뉴에 이미 적용되던 추가세의 `applies_to_treatments`를 `['taxable']`에서 `['taxable','exempt']`로 변경하는 경우다. 해당 과세 메뉴의 금액은 같지만 0225 재무 비교에는 전체 배열이 남아 `affects_sales=true`를 만들었다. 최초 읽기 전용 확인에서 11,000원 포함가·기본 10%·추가 2%의 순매출은 양쪽 9,822원, 세금은 양쪽 1,178원이면서 재무 변경 판정은 true였다.

[0227:15](../../../packages/db/supabase/migrations/20260912000227_tax_projection_null_and_scope.sql#L15)은 메뉴별 적용 여부를 먼저 필터한 뒤 재무 비교에서 `applies_to_treatments`를 제외한다. 따라서 같은 메뉴의 재무 의미는 유지하면서 다른 과세 상태로 확장된 전체 범위는 원본 규칙의 정보성 이력에 남는다. 실제로 새로 포함되는 메뉴는 필터 결과에 항목이 추가되므로 재무 변경 판정이 유지된다.

[시험 85](../../../packages/db/tests/85_tax_scope_projection.sql)는 영업 전·open·break·종료의 4개 상태에서 다음을 확인한다.

- 이미 과세되던 메뉴의 재무 사건 수는 증가하지 않는다.
- 새로 추가세 적용 대상이 된 면세 메뉴에는 재무 사건이 생긴다.
- 전체 적용 범위 변경은 정보성 `tax_rules` 이력에 보존된다.
- 기존 기본값 상속 선택, 무변경 저장, 오래된 판본 거부 계약도 유지된다.

ROOT가 생성한 [수정 전 로그](../../../.codex/material-history-20260912/scope-projection-before.log)에서 기존 과세 메뉴의 재무 사건 불변 단언 실패를 확인했고, [수정 후 로그](../../../.codex/material-history-20260912/scope-projection-after.log)에서 **25개 단언·1/1 SQL 파일 통과**를 확인했다. 시험 실행 주체는 ROOT이며 검수자는 로그와 소스·단언을 대조했다.

## null 입력과 읽기 전용 확인

[0227:6](../../../packages/db/supabase/migrations/20260912000227_tax_projection_null_and_scope.sql#L6)과 [0227:17](../../../packages/db/supabase/migrations/20260912000227_tax_projection_null_and_scope.sql#L17)은 두 비교 helper 모두 실제 JSON 배열만 `jsonb_array_elements`에 전달한다. SQL null·JSON null 등 배열이 아닌 입력은 빈 배열로 정규화된다. 이 helper는 변경 비교용이며 과거 판매 계산이나 원장 값을 재작성하지 않는다.

설치 함수의 null 방어 포함 여부를 확인한 격리 DB `fresh_linked_astra_20260912`에서 `BEGIN READ ONLY` 안의 SELECT로 아래 결과를 확인하고 롤백했다. DB 쓰기나 회귀 시험 실행은 하지 않았다.

| 확인 항목 | 실제 결과 |
| --- | --- |
| 기존 과세 메뉴의 필터 후 재무 규칙 변경 | false |
| 새로 포함된 면세 메뉴의 필터 후 재무 규칙 변경 | true |
| 두 helper의 SQL null·JSON null 4개 입력이 모두 빈 배열로 반환 | true |

0225~0226의 앞선 교차 검수에서는 비적용 항목/동일 과세 상속의 정보성 처리와 현재 월에 한정한 고정지출 추세 기록을 확인했다. 0226의 다른 월 최초 저장 반례는 `fixed-month-before.log` 실패와 `fixed-month-after.log` 통과를 대조했고, 해당 델타에서 기존 7건의 추가 회귀는 발견하지 못했다.
