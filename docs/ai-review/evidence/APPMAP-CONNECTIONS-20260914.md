# AppMap 전체 연결 검수 — 2026-09-14

범위: 로컬 AppMap 8091과 실제 Expo 8094의 화면·하위 페이지·팝업 진입. DB 쓰기 검증이나 네이티브 기기 증빙을 대신하지 않는다.

## 발견 및 수정

- 재료 목록 관측 RPC를 `ingredient_list_v2`까지 지원해 상세·수정·내역의 실제 ID 연결 복구.
- 구매 링크의 상품명·구매처·새 구매처 등 변경된 접근성 이름과 입고 복구 확인창을 현재 컴포넌트에 맞춤.
- 미리보기의 미확정 입고 저장소를 메모리로 격리해 실제 미확정 입고를 읽거나 덮어쓰지 않음.
- 부자재 제거 조건을 화면 단위로 한정. 함께 사라졌던 매출 재료별 차감 상세를 복구하고 옛 부자재 상세는 통합 재료 상세로 연결.
- 제거한 화면을 전체 목록 및 개수에서도 제외. `화면 + 팝업 = 전체` 집계 일치.
- 메뉴 재료 카드가 접힌 경우 먼저 펼친 뒤 사용량 팝업을 엶. 이미 펼쳐진 경우 그대로 사용.
- 입고 급등 샘플은 현재 ‘입고 완료’ 확인창 버튼을 구분하여 선택.
- 지출 추가·삭제 샘플은 편집 가능한 영업일 상태로 제공. 실제 쓰기는 계속 차단.
- `store_configuration_history`는 조회 RPC로 허용. 세금 저장 결과 샘플은 현재 국제 세금 계약의 확인·결과 표시를 사용하며 서버로 저장하지 않음.
- 세금 수정 내역, 고정 지출 수정 내역, 국가·통화 설정, 메뉴 세금 상세 4개 화면과 수정 내용·세금 확인·시뮬레이션 4개 팝업을 앱맵에 추가.
- 0건 수정 내역의 짧은 본문을 로딩 중으로 오판하던 글자 수 제한 제거. 렌더링·진행 표시·진행 중 조회로 준비 여부 판정.

## 실행 증거

Codex in-app browser의 CUA 브라우저 API로 실행했다. 처음 노출되던 194개를 순회하고 수정·퇴역 경로를 재검사했다. 최종 DOM 전체 목록 200개 ID를 실제 관측 결과와 대조하여 누락 0, 진입 성공 200개를 확인했다. 최종 구성은 화면 74개 + 팝업/상태 126개이며 숨김 경로 7개가 포함된다.

- 직접 연결 195개, 대체 이동/인라인 2개, 명시적 샘플 결과 3개. ‘원본 팝업 200개 구현’이라는 의미가 아니다.
- 샘플 결과 3개: 입고 요청 실패 후 복구 확인, 입고 단가 급등, 세금 저장 결과. 실제 처리하지 않음.
- 대체 표시 2개: 안전재고 이하 목록 이동, 언어 미리보기 인라인 표시.
- 실제 데이터 모드 10개: 재료 수정 메뉴·재고 내역·구매 내역·재료 수정 내역·메뉴 수정·메뉴 수정 내역·세금 수정 내역·고정 지출 수정 내역·국가/통화·메뉴 세금 상세. 0건 세금 수정 내역까지 정상 진입.
- `node --test scripts/appmap/model.test.mjs scripts/appmap/samples.test.mjs`: 41/41 통과. 별도 실행 로그 `.codex/appmap-all-tests.log`.
- 실제 저장·삭제·발주·입고·판매·취소를 실행하지 않았다. 확인창 열기까지만 검증하거나 샘플 쓰기 차단 아래 결과를 확인했다.

## 검수 범위 제한

이 결과는 AppMap 탐색 연결 검수다. 전체 `pnpm verify`는 기존 재고 복원 작업에서 별도 실행 중이며, 기존 소스/기기 증빙 및 업그레이드 실패가 있어 전체 게이트 통과로 표현하지 않는다. 독립 Fable r1은 정식 작업/장부 준비 후 시도했으나 `PROVIDER_HARD_CAP_UNAVAILABLE`로 외부 호출 전에 중단됐다(`.codex/appmap-all-fable.log`). 독립 검수 통과 결과는 없다.
