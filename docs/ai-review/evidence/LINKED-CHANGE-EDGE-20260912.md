# 변경 전파 추가 독립 실행 관찰

검수 요청 이후 Codex가 직접 수행한 추가 조사다. 공식 요구사항은 `docs/식재료-레시피-수정내역-최종기획.md`이며 이 파일은 실행 증거의 해석만 기록한다.

대상: 독립 DB `fresh_linked_audit_20260912`, 0208 후보 포함. 실제 사용자 데이터 변경 없음. 입력 `.codex/material-history-20260912/edge-probe.sql`, 출력 `edge-probe.log`. 트랜잭션 ROLLBACK, 프로세스 종료 0. 4개 영업 상태 × 7개 시나리오 = **28개 관찰**이며 28개 정상 동작 통과라는 의미가 아니다.

## 별도 회귀 시험

- `packages/db/tests/67_application_status_summary.sql`: 가격 대기 후 이름 수정, 20건 밖 대기 사건, 다음 페이지 동일 요약, 브레이크, 종료 해제, 매장 권한 경계 10개 단언 통과.
- 전체 SQL **69/69 파일 통과**, `.codex/material-history-20260912/status-db-all.log`, 26.9초.
- 모바일 타입 검사 및 UI **29/29 통과**, `status-type.log`, `status-ui-tests.log`.
- 기존 검수 입력 파일과 후보/시험/로그 해시는 `linked-review-input-hashes.json`에 저장했다. 추가 관찰 파일은 원래 검수 요청 SHA에 포함되어 있지 않다.

전체 verify·신규 네이티브 실측·배포·공식 독립 검수 게이트 완료를 의미하지 않는다. 0208은 로컬 개발 DB에 적용하지 않은 후보다.

## 코드 대조에서 보완한 해석

`20260820000063_entity_change_events.sql:17` 이후 주석은 12,000→20,000→12,000으로 원복해도 두 수정 사건은 당일 매출에 미반영이므로 값의 일치가 아닌 기준 확정 시각으로 판정한다고 명시한다. 따라서 원복 후 대기 true를 곧바로 결함으로 세지 않는다. 상단 요약의 의미를 이 계약과 함께 Claude에 대조 요청한다.

현재 `ChangeSource`는 direct/inbound/ingredient/fixed_cost만 선언되어 있다. tax/material 자동 사건 추가 시 DB enum과 TS 타입·출처 설명·집계·조회 경로를 함께 확장해야 한다. 화면 배지만 추가해서 DB 이력 누락이 해결됐다고 볼 수 없다.

## 화면 갱신 재현 및 수정

- `settingsSaved`의 메뉴 수정 내역 누락, 영업 종료 시 설정 이력 대기 요약 누락을 실제 QueryClient/도메인 훅 시험으로 재현했다. `cache-before.log` 3개 실패 → 공통 쿼리 무효화 보완 후 `cache-after.log` 17개 통과.
- 자동 종료 조회 경로는 recipes/internationalTax만 갱신하던 상태였다. `poll-before.log`에서 open/break→closed 2개 실패를 재현한 뒤, 수동 전환과 같은 소비 쿼리를 갱신하도록 공통 `invalidateBusinessDayConsumers`를 추가했다. 현재 실행 중인 business-day 쿼리는 제외해 자기 취소·재조회 반복을 방지한다. 상태·서버 날짜·영업일 ID/영업일 날짜 변화가 있으면 갱신하고 동일 상태 재조회는 반복 갱신하지 않는다.
- `poll-after.log` **22개 통과**: 영업 중/브레이크에서 서버 종료 감지, 금액 재조회, 식재료·메뉴·세금·고정지출·부자재 이력 및 매출 캐시 갱신, 추가 영업 상태 쓰기 없음, 동일 상태의 불필요한 재조회 없음.
- R1 F6 중 ‘settingsSaved가 configurationHistory도 누락’은 오탐으로 반박했다. `qk.configurationHistory=['settings','configuration-history']`는 기존 `qk.settings` 접두 무효화에 이미 포함된다. 메뉴 `changes/recipe` 누락과 자동 종료 소비 쿼리 누락은 실제 결함이다.
- 사용자 실제 된장찌개 매장은 2026-09-12 06:32:06 UTC 개장한 open 상태다. 참고 가격 수정은 06:32:39 UTC로 개장 후이지만 현재 원가 입력 계약에서는 매출 영향 사건이 아니다. 따라서 해당 변경의 대기를 캐시 수정만으로 만들 수 없다. 가격 기준 계약과 자동 사건 생산 경로 보완이 별도로 필요하다.

## 2026-09-12 R5 후 실행 상태

- 위 0208 미적용·69파일 결과는 당시 관찰 기록이다. 현재 개발 DB는 백업 후 0213까지 적용됐다. `linked-local-apply.log`에 0209~0213 적용과 executor CREATE 권한 미보유가 기록되어 있다. 타입 재생성 완료. 원격 적용이나 과거 사용자 데이터 복구는 수행하지 않았다.
- R1~R5 원본을 보존했다. R5의 0원 부자재 연결 정상화 검수는 새 P1/P2 없음이다. 기존에 유실된 연결은 근거 없이 자동 복구하지 않는다. 원래 검수 입력 71번(21단언) 이후 추가한 no-op/receipt replay·자유입력 0원 단언까지 최신 71번은 29단언 통과했다(`zero-material-r5-followup.log`).
- 앱의 `draftStore.ts` 상세 불러오기, `RecipeAddScreen.tsx` 제출 매핑, `writeContract.ts`의 `recipePayload`는 연결 항목을 금액으로 필터링하지 않는다. 연결 항목은 material_id/qty로 직렬화하고 금액은 서버가 결정한다. 이는 소스 대조이며 이번 턴의 실제 기기 터치 증거로 표현하지 않는다.
- 최종 격리 DB 회귀 **74/74 파일**, 관련 수정내역 앱 시험 **47/47**, DB 타입 재생성 후 모바일 타입 검사 통과. 최신 migration/함수/시험/SQL 로그 지문은 `linked-final-db-manifest.json`에 다시 캡처했다. 웹 번들은 앞선 동일 UI 소스로 통과했다.
- 전체 verify는 앞선 0208 판본에서 시작한 장시간 업그레이드 검사이므로 최종 0213 전체 게이트 증거가 아니다. 커밋 바이트 결속을 비롯한 미완료 범위를 유지한다. 새 네이티브 검수·공식 CLI 독립검수·커밋·푸시는 수행하지 않았다.
- 구매 가격/용량의 메뉴 원가 전파와 국제 세금 자동 이력은 여전히 미완료다. 직접 수정 단가와 이후 입고 평균의 우선순위는 사용자 답변 대기다. 전수 범위는 공식 기획 §14 분류표에 정리했으며 분류표의 모든 조합이 실행됐다는 의미는 아니다.
