0. 개요 · 표기법
앱의 모든 화면 이동(네비게이션)과 데이터 전파(이벤트)를 화면 ID 기준으로 명세한다. 개발 시 라우팅 테이블과 상태 갱신 로직의 단일 기준이 된다.
화면 ID 체계
ORD- 발주 현황 탭 / ING- 식재료(잔여) 탭 / RCP- 레시피 탭 / MY- 마이페이지 탭
유형: 화면(풀 페이지) / 시트(바텀시트 팝업 — 닫으면 호출 화면으로 복귀)
전파 이벤트: E1~E7 — 화면 이동 없이 데이터가 갱신되는 흐름

4. 데이터 전파 이벤트 (E1~E7)
화면 이동 없이 백그라운드로 갱신되는 흐름. 각 이벤트는 트랜잭션으로 처리해 화면 간 정합성을 보장한다.
ID
 | 트리거
 | 갱신 대상 (순서대로)
 | 
E1
 | 입고 확정 (ORD-03)
 | 재고 미개봉 +실수량 → ING 뱃지 재판정 → 구매 이력(=최근 주문) 추가 → 평균·기준 단가 재계산 → 가격 추이 점 → 영향 레시피 손익 재계산(변동 시 주황 점) → 월 재료비 합산 → ORD 카드 완료 이동·후보 해소 → (평균 ±15% 시) 급등 알림
 | 
E2
 | 폐기 (ING-04)
 | 폐기량 기록 → 실측 로스율 재계산 → 기준 단가 보정 → 영향 레시피 손익 → 재고 개수 차감·뱃지
 | 
E3
 | 레시피 저장/수정 (RCP-03)
 | 손익 재계산 → 순이익률 추이 파랑 점(저장일) → 리스트 정렬·경고 뱃지 갱신
 | 
E4
 | 고정 지출 저장 (MY-02)
 | 고정지출률·1,000원당 재계산 → 전 레시피 손익 재계산 + 회색 점 일괄 → 월 손익 리포트 생성/갱신
 | 
E5
 | 재고 수정·실사 (ING-04)
 | 개수 보정 → 뱃지 재판정 → (안전재고 미달/곧소진 시) 발주 후보 생성
 | 
E6
 | 레시피 계산 실행 (ORD-04)
 | 식재료별 필요량 역산 → 잔여 환산 비교 → 부족분 후보 생성/합산(사유 병기) — 동일 기간 재실행 시 갱신
 | 
E7
 | 발주 등록 (ORD-02)
 | ‘발주됨’ 레코드 생성 → 도착 대기 목록 추가(도착 예정일 정렬) → 후보 상태 ‘주문함’ 전환 — 재고·단가는 변동 없음
 | 

전파 원칙
재고·단가·이력은 오직 E1(입고 확정)·E2/E5(재고 수정)에서만 변한다 — 등록(E7)은 기록일 뿐.
손익에 영향을 주는 모든 이벤트(E1~E4)는 순이익률 추이에 원인 색 점을 남긴다(재료=주황, 레시피=파랑, 고정=회색).
 | 
5. E2E 시퀀스 (화면 단위)
5.1 하루 루틴
아침: ORD-01 후보 탭 — 곧소진·안전재고 후보 확인 (필요 시 ORD-04로 레시피 계산 추가)
후보 카드 [같은 곳 주문] → 외부 주문 → ORD-02 등록(도착 예정일 내일) → E7
도착 시: ORD-01 대기 탭 → ORD-03 입고 확정 → E1 전파
마감: ING-01/04 — 완전소진·폐기(E2)·실사(E5)로 재고 마감
5.2 월초 루틴
MY-02 전월 복사 → 항목 수정 → 저장 → E4 (전 레시피 손익 갱신)
RCP-01 ‘순이익률 낮은순’ → 미달 메뉴 RCP-02 확인 → RCP-05 시뮬레이션 → RCP-03 판매가 수정(E3)
MY-07 월 손익 리포트 확인
5.3 신메뉴 출시
ING-03 신규 재료 등록(+ING-05 링크) → RCP-03 레시피 작성(미존재 재료는 즉석 등록 크로스 플로우)
권장가 참고해 판매가 확정 → 저장(E3) → ORD-04 계산으로 첫 발주 후보 → ORD-02 등록 → ORD-03 입고
5.4 원가 급등 대응
E1 중 급등 알림 → ING-02 가격 추이 확인 → 영향 메뉴 RCP-02 → RCP-05 시뮬레이션 → 판매가 인상(E3, 추이 파랑 점) — 전 과정이 점(추이) 근거로 남는다.

흐름도 다이어그램(레인형 맵)은 대화 내 위젯으로 제공되며, 본 문서의 1~4장이 그 상세 명세다. 상세 로직은 ①~④, 데이터 모델은 ⑤, 케이스 검증은 ⑥을 참조.
