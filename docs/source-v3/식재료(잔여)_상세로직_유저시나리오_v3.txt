0. 설계 대원칙
이 앱의 모든 페이지는 다음 한 문장의 원칙 위에서 동작한다.
핵심 성공 방정식
백엔드(저장) = 1인분 · 최소단위(g/ml/개) 표준화
프론트(입력) = N인분 · 구매단위(박스/통/단) 자율화
→ 사장님은 익숙한 단위로 편하게 입력하고, 시스템이 1인분·최소단위로 쪼개어 저장·계산한다.
 | 

‘식재료(잔여)’ 페이지는 이 원칙의 출발점이다. 여기서 등록된 단가·단위·로스율 데이터가 레시피 원가와 발주량 계산의 기준값이 되며, 동시에 현재 남은 재고를 실시간으로 보여주어 ‘무엇을 얼마나 더 사야 하는가’의 1차 판단을 책임진다.
1. 페이지의 역할과 데이터 흐름상 위치
‘식재료(잔여)’는 두 가지 성격을 한 화면에 통합한다. ① 식재료 마스터(단가·단위·로스율 등 기준정보 원장)와 ② 실시간 잔여재고(현재 남은 수량·상태)다. 마스터가 ‘이 재료는 1g당 얼마인가’를 정의한다면, 잔여재고는 ‘지금 몇 개(통·포장) 남았고 더 사야 하는가’를 답한다.
1.1 앱 전체 데이터 흐름
[1단계] 식재료 등록  →  단위당 구매원가 · 로스율 · 안전재고 설정   ◀ 본 페이지
        ↓
[2단계] 메뉴/레시피 등록  →  N인분 입력 → 1인분 자동 환산 → 원가·마진율 산출
        ↓
[3단계] 발주 관리  →  판매 예측 인분수 입력 → 총 필요량 합산 → 잔여 차감 → 부족분 올림 발주
 | 

본 페이지가 다른 페이지에 공급하는 값: ‘기준 단가(원/최소단위)’는 레시피 페이지의 원가 계산에, ‘현재 잔여량·안전재고·최소발주단위’는 발주 현황 페이지의 부족분 산출에 직접 연결된다.
2. 데이터 모델 (식재료 마스터 + 잔여재고 통합)
하나의 식재료 레코드는 ‘기준정보(마스터) 영역’과 ‘재고 영역’으로 구성된다. 두 영역을 한 테이블로 통합 관리하되, 화면에서는 목적에 따라 나눠 보여준다.

재고 단위 설계 결정 — ‘개수(개당 용량 단위)’ 기반
잔여재고는 %나 g가 아니라 ‘개수’로 관리한다 — 미개봉 N개 + 개봉중 0/1개(4.7절).
이유: ‘몇 개 남았나’는 세기만 하면 되어 빠르고 정확하다. 안전재고·발주도 개수로 판단.
단, 원가·레시피 소요량은 g/ml 단가를 그대로 쓰며, 필요 시 개수 × 개당 용량 × (1−로스율)로 환산한다.
 |

추가 방법(링크 붙여넣기 시트): URL 붙여넣기 → 상품명·구매처(도메인 자동 인식)·브랜드·용량-금액을 자동 추출해 ‘자동’ 뱃지와 함께 채움 → 확인·수정 후 등록(자동은 초안, 확정은 사람). 실패 시 같은 칸 수동 입력.
등록 전 환산 단가를 즉시 계산해 ‘평균 대비 ▲33%’ 같은 비교 뱃지 표시 → 비싼 옵션인지 등록 전에 판단.
주문 연결: 옵션 카드의 [주문하러 가기] → 외부 앱/사이트로 이동. 돌아와 발주 완료 등록에서 같은 옵션을 고르면 필드 자동 채움.
최저가 강조: 옵션별 용량-금액으로 환산단가를 계산해 ‘최저가 옵션’에 배지를 표시한다.
단종·품절 옵션은 ‘보관(숨김)’ 처리. 가격이 오래되면 ‘확인 필요’ 표시로 갱신을 유도한다.

‘구매 옵션·링크’ vs ‘구매 이력(8.6)’ — 무엇이 다른가
구매 옵션·링크 = 앞으로 살 수 있는 후보 목록(고정·링크 포함). 가격은 정가 또는 최근 확인가.
구매 이력 = 실제로 산 결과(날짜·수량 포함). 평균단가 계산의 근거.
연결: 옵션을 골라 발주 완료를 등록하면 → 그 건이 구매 이력에 쌓이고 → 평균단가에 반영된다.

3. 화면 구성 (UI 레이아웃)
화면은 위에서부터 ‘요약 헤더 → 검색/필터 → 식재료 카드 리스트 → 플로팅 등록 버튼’ 순으로 쌓인다. 카드를 누르면 상세, 길게 누르거나 우측 버튼으로 빠른 입고/실사가 가능하다.
3.1 상단 요약 헤더 (대시보드 띠)
총 등록 식재료 수 / 그중 ‘부족’·‘소진임박’ 개수를 색상 배지로 요약(예: ‘부족·소진임박 3 — 다진마늘, 양파, 두부’처럼 품목명도 함께 표시) + ‘발주하기’ 바로가기.
‘부족 N건’ 배지를 누르면 부족 항목만 필터링되어, 바로 발주 판단으로 넘어갈 수 있다.
우측에 ‘발주 현황으로 부족분 보내기’ 바로가기 버튼(부족 항목 일괄 전달).
3.2 검색 / 정렬 / 필터
검색: 식재료명 부분일치(초성 검색 지원 권장).
정렬: 재고 상태순(부족 우선) · 이름순 · 최근 입고순 · 단가 높은순.
필터: 분류별(채소/육류/수산/양념/공산품), 상태별(부족·소진임박), 거래처별.
상위 카테고리 탭: 검색 위에 좌우 스크롤 탭으로 ‘전체 + 카테고리’를 두어 한 번에 분류 전환. 기존 ‘그룹 아코디언’은 탭으로 대체. 맨 끝 [편집]으로 사용자가 추가·이름변경·순서 변경 가능.
기본 카테고리 12종(수정 가능): 축산-계란 · 수산-해조류 · 농산(신선) · 곡물-견과-분말 · 유제품 · 냉동식품 · 소스-유지류-장류 · 향신료-허브 · 음료-주류 · 상온가공-건식 · 두부-발효식품 · 베이커리.

3.4 상세 / 편집 화면
헤더에 식재료명 옆 ‘카테고리 뱃지’, 잔여 줄 우측에 ‘상태 뱃지(충분/부족/소진임박)’를 둔다. 본문은 아래 순서로 쌓는다.
잔여(수량): ‘미개봉 N · 개봉 M (총 X, 개당 Y[g/ml/개])’ + 우측 [수정] 버튼 → 재고 수정 팝업(4.7).
단가: 구매이력 기반 평균 + 최저·최고·최근 뱃지, 기준단가(로스 반영)를 함께 표시.
기준정보: 로스율(추정·실측), 안전재고/최소발주(동일 단위). 개당 용량·최소단위는 잔여 줄에 드러나므로 생략.
메모: 자유 메모(거래처 특이사항·품질·대체재 등). 카드에는 메모 아이콘.
구매 옵션·링크: 구매식재료명·구매처·브랜드·용량-금액·링크 목록(2.3절), 최저가 뱃지·바로 주문.
구매 가격 변동(시세): 입고 단가(원/단위) 추이 꺾은선 + 평균선·최저·최신·평균대비 변동%. 점 탭 시 해당 입고로 이동.
기간별 집계: 입고 데이터는 raw로 쌓고, 조회 기간(1주일·2주일·1개월·3개월·6개월·12개월)에 따라 점을 묶어 보여준다 — 기간이 길수록 일→주→월 평균으로 집계해 점 개수를 일정하게 유지한다.
최근 주문/입고 내역: 날짜·구매처·금액·환산단가 표(맨 아래). 입출고·폐기·실사 히스토리도 함께 조회.
‘이 식재료가 들어가는 메뉴’ 역참조 — 단가를 바꾸면 영향 메뉴·마진율 변화 미리보기(레시피 연동 후).
3.5 신규 등록 화면
필수는 식재료명·카테고리·개당 용량 3가지. 단위 관련 UI는 ‘개당 용량’ 한 줄(입력칸+단위 셀렉박스)이 전부다.
식재료명 입력 → 카테고리 셀렉박스 선택(기본 12종 + 맨 아래 ‘카테고리 편집’). 카테고리에 따라 로스율 기본 제안값이 바뀐다.
개당 용량 = 입력칸 + 단위 셀렉박스(g·kg·ml·L·개). kg·L은 자동 환산(1kg=1,000g), ‘개’는 포장당 개수(계란 1판=30, 낱개 기본 1). 가격은 선택 — 넣으면 ‘1g당 ○원’ 단가 미리보기가 즉시 계산되고, 비우면 첫 입고 때 자동 반영. (수량은 등록이 아니라 입고에서.)
로스율(선택, 카테고리 기본 제안: 잎채소 10~15%, 통생선 40% 등) — 폐기 기록이 쌓이면 실측값으로 자동 보정(4.7).
안전재고·최소발주(같은 단위, 개수 스테퍼) → 메모(선택) → 구매 옵션·링크(선택, 링크 붙여넣기 시트) → 저장. 잔여는 0에서 시작, 첫 입고 등록 시 증가.

4. 핵심 연산 로직
4.1 단위 환산 + 로스율 (net 기준)
구매 단위를 최소단위로 풀고, 로스율만큼 폐기를 반영해 ‘실제 쓸 수 있는 양’과 ‘그 양 기준 단가’를 구한다.
공식
사용가능 용량(net) = 구매 용량 × (1 − 로스율/100)
기준 단가(원/최소단위) = 구매 가격 ÷ 사용가능 용량(net)
 | 
예시 ① 대파: 1단(1,000g)=4,000원, 로스율 15% → net 850g → 단가 4,000 ÷ 850 ≈ 4.71원/g
예시 ② 식용유: 1통(18,000ml)=45,000원, 로스율 0% → 단가 45,000 ÷ 18,000 = 2.5원/ml
4.2 기준 단가 → 레시피 1인분 원가 연결
본 페이지의 단가는 레시피 페이지에서 다음과 같이 소비된다(참고용).
공식
1인분당 소요량 = 레시피 입력 소요량 ÷ 기준 인분(N)
1인분 원가 = Σ (1인분당 소요량 × 식재료 기준 단가)
마진율(%) = (판매가 − 1인분 원가) ÷ 판매가 × 100
 | 
4.3 잔여재고 차감 로직 (입고 · 소진 · 실사)
재고(개수)는 네 가지 이벤트로 변한다: 입고확정 · 소진 · 폐기 · 실사. 평소 화면 표시는 개수이며(4.7절), 아래 표의 g(용량) 계산은 레시피 연동·원가 비교용 ‘환산 레이어’다. 모든 변화는 히스토리에 한 줄씩 남긴다.
이벤트
 | 발생 시점
 | 잔여량 계산
 | 
입고(+)
 | 입고 확정
 | 미개봉 개수 += 입고 수량  (용량 환산: += 구매용량 × (1−로스율))
 | 
소진(−)
 | 개봉 통 다 씀
 | 개봉중 → 소진, 미개봉에서 1개 개봉  (레시피 연동 시: 용량 −= 1인분 소요량 × 인분수)
 | 
폐기(−)
 | 상해서/남겨서 버림
 | 개봉(또는 미개봉) 제거 + 남은 양을 폐기량으로 기록 → 실측 로스율(4.7) 반영
 | 
실사(=)
 | 재고 조사 보정
 | 개수를 실측값으로 덮어쓰기 (차이는 ‘조정’으로 기록)
 | 

예시(개수): 대파 1단 입고 → 미개봉 +1통. (원가 환산 시 net 850g.) 레시피 연동 시 판매분만큼 용량이 자동 차감된다.
4.4 재고 상태 판정 (안전재고 기준)
상태
 | 색상
 | 판정 조건
 | 
충분
 | 초록
 | 잔여량 ≥ 안전재고
 | 
부족
 | 노랑
 | 0 < 잔여량 < 안전재고  → 발주 후보로 자동 분류
 | 
소진임박/품절
 | 빨강
 | 잔여량 ≤ 0  또는  소진 예상일 ≤ 내일 (일평균 소진량 기준)
 | 

소진 예상일 = 현재 잔여량 ÷ 일평균 소진량. 예) 잔여 250g ÷ 일평균 600g ≈ 0.4일 → 내일 품절 예상 → 빨강.
개수 기반으로 운영하면 동일하게 ‘남은 개수 ≤ 안전재고 개수’로 부족을 판정한다(4.7절). 위 g 기준 설명은 용량으로 환산해 비교할 때 적용된다.
4.5 원가 변동 감지 & 마진 경고
입고/단가 수정 시 직전 단가와 비교해 변동률을 계산하고 히스토리에 기록.
변동률이 임계치(예: ±15%) 이상이거나 영향 메뉴 마진율이 목표 미만으로 떨어지면 이름 옆 빨강 경고 아이콘 표시.
예시: 대파 4,000→5,000원(+25%). 제육볶음(판매가 9,000원) 원가 6,591→6,627원, 마진율 26.8%→26.4%로 하락 → 경고 노출.
4.6 발주 현황 페이지 연동
개수 기반에서는 발주량 = max(0, 안전재고 개수 − 남은 개수)로 바로 떨어진다. 아래 g·올림 공식은 레시피로 필요량을 용량(g)으로 산출하는 경우(향후)에 쓰며, 실제 발주 올림·전송은 발주 페이지가 처리한다.
부족분 → 발주량 변환
부족량(net) = max(0, 필요량 − 현재 잔여량)        (필요량 = 안전재고 또는 예측 소요량)
부족량(gross) = 부족량(net) ÷ (1 − 로스율/100)     (사올 때는 손질 전 양으로 환산)
최종 발주량 = Ceil( 부족량(gross) ÷ 최소 발주 단위 )  → 올림
 | 
예시: 내일 제육 30인분 예상 → 필요 net 900g, 잔여 250g → 부족 net 650g → gross 765g → 1단(1,000g) 기준 올림 = 1단 발주.
4.7 잔여 관리 — 개수 기반 + 재고 수정·폐기
재고는 %가 아니라 ‘개수’로 관리한다. ‘식용유 50%’보다 ‘식용유 2통 반’이 더 자연스럽고, 눈대중 % 입력의 번거로움·부정확함을 없앤다. 구조는 ‘미개봉 개수 + 개봉 1개’로 단순하다. 이 절이 재고·발주 판단의 기준이며, 단가는 원가 계산용으로 별도 유지된다.
(1) 잔여 표기 — 단위 라벨 없이 숫자 + 개당 용량
표기 형식: ‘미개봉 N · 개봉 M (총 X, 개당 Y[g/ml/개])’. 0도 그대로 표시(예: 미개봉 0 · 개봉 1).
두 가지 단위 구분: 기준 단위(g/ml/개)는 개당 용량의 단위 셀렉박스에서 자동 결정되어 ‘개당 Y’에 따라붙는다. 구매단위 라벨(통·단·망)은 표시에서 빼고, 설정에서 옵션으로 켤 수 있다(향후).
‘곧 소진’ 플래그: 개봉분이 거의 비면 [곧 소진]을 한 번 탭 → 발주를 앞당긴다(0/1 단순 플래그, %는 입력하지 않음).
(2) 재고 수정 팝업 (직접 입력)
잔여 줄 우측 [수정] → 바텀시트 팝업이 올라온다. 평소 화면은 잔여만 깔끔히 보이고, 조작은 팝업 안에서만 일어난다.
미개봉 +/−, 개봉 +/− 스테퍼로 개수를 직접 보정(실사).
‘개봉분 남은 양(선택)’을 g/ml로 직접 입력 가능(예: ≈ 700 / 1,000).
완전소진 vs 폐기: 완전소진 = 다 씀(로스 0). 폐기 = 남은 양을 버림(‘남은 양이 로스로 누적돼 실측 로스율(예: 13.2%)로 자동 보정됨’ 안내를 시트에 노출).
폐기 → 실측 로스율
폐기 시 ‘버릴 때 남아 있던 양’을 확인·수정해 기록 → 그 양이 폐기량(로스)으로 누적된다.
실측 로스율(%) = 누적 폐기량 ÷ 누적 구매량 × 100.
등록 시 추정으로 넣은 로스율(예: 15%)을 실측값으로 자동 보정 → 원가·발주 환산이 더 정확해진다.
 | 
(3) 개수 ↔ 용량·원가 환산
환산 공식
총 잔여량(net) ≈ (미개봉 + 개봉) × 개당 용량 × (1 − 로스율)
예) 식용유 미개봉 2 + 개봉 1, 개당 18,000ml, 로스율 0% → 약 54,000ml
개봉분 ‘남은 양’을 입력했다면 그 값으로 더 정확히 환산한다.
 | 
(4) 발주 연동 — 안전재고는 뱃지 전용
안전재고/최소발주는 동일 단위(개수): 통·단 섞임 없이 같은 구매단위 개수로 설정. 안전재고는 잔여 줄에 ‘/ 안전 N’으로 쓰지 않고, 상태 뱃지(충분/부족/소진임박)를 켜는 용도로만 쓴다.
발주 판단: 남은 개수 ≤ 안전재고 개수 → 발주 후보. ‘빠른 점검’ 모드로 개수만 탭해 모은 뒤 발주 완료 등록(8장)으로 연결.
4.8 단위 시스템 & 환산 (마이페이지 설정)
어떤 단위로 입력해도 내부 저장은 g·ml·개로 통일한다 — 그래서 단가·원가·발주 계산 로직은 하나로 동작한다. 단위 시스템 설정은 ‘개당 용량 셀렉박스에 어떤 단위를 보여줄지’만 바꾼다(기본: 미터법).
시스템
 | 무게
 | 부피
 | 조리컵
 | 
미터법(기본)
 | g · kg (1kg=1,000g)
 | ml · L (1L=1,000ml)
 | 200ml (사용자 설정)
 | 
미국식

 | 

조리스푼은 모든 시스템 공통 — 큰스푼 15ml · 작은스푼 5ml.
컵·스푼은 레시피 재료량 입력의 보조 단위(입력 즉시 ml 자동 환산). 식재료 등록·재고에는 쓰지 않는다.
셀렉박스 목록: 미터법 g·kg·ml·L·개 / 미국식·영국식 oz·lb·fl oz·pt·qt·gal·개. ‘개’는 모든 시스템 공통.

5. 유저 시나리오
시나리오 A — 신규 식재료 등록 (영업 준비 단계)
상황: 사장님이 새 거래처에서 ‘대파 1단 4,000원’에 들여오기로 하고 앱에 등록한다.
동작: 식재료(잔여) → 우하단 [+] → 이름 ‘대파’, 분류 ‘채소류’, 최소단위 ‘g’ 선택.
동작: 개당 용량 ‘1,000g’, 가격 ‘4,000원’(선택) 입력 → 화면에 ‘1g ≈ 4.71원(로스 반영)’ 프리뷰.
동작: 로스율 ‘15%’(잎채소 기본 제안 수락), 안전재고 ‘1단(개수)’, 최소발주단위 ‘1단’ 입력 후 저장.
결과: 카드가 리스트에 추가되고, 이 단가가 이후 모든 ‘대파 포함 메뉴’의 원가 계산 기준이 된다.
시나리오 B — 아침 재고 점검 & 부족 식별
상황: 출근 직후 오늘 장사 전에 무엇을 사야 할지 확인한다.
동작: 식재료(잔여) 진입 → 정렬 ‘재고 상태순’ → 부족(노랑)·소진임박(빨강) 항목이 최상단에 모인다.
동작: 헤더의 ‘부족 5건’ 배지 탭 → 부족 항목만 필터.
결과: 대파(개봉중 1통/안전 2통), 양파 등 부족 목록 확인. ‘발주 현황으로 보내기’로 한 번에 전달.
시나리오 C — 재구매 후 입고 처리
상황: 청과에서 대파 2단을 새로 받아왔다.
동작: 대파 카드 우측 [입고] → 구매 단위 기준 ‘2단’ 입력.
처리: 미개봉 +2통으로 갱신(개봉중 1통은 그대로). 원가 환산 시 net 1,700g 추가.
처리: 단가가 직전과 다르면 변동률 기록, 입고일 자동 갱신.
결과: 상태가 ‘충분(초록)’으로 바뀌고 히스토리에 입고 1줄 추가.
시나리오 D — 재고 실사 보정 (장부와 실제가 다를 때)
상황: 마감 때 대파가 생각보다 많이 남아 장부(차감 누적)와 실제가 어긋났다.
동작: 대파 카드 [실사] → 실측 개수 입력(예: 미개봉 1통 + 개봉중 1통).
처리: 개수를 실측값으로 덮어쓰고, 장부값과의 차이를 ‘조정(±)’ 한 줄로 히스토리에 남긴다.
결과: 폐기·서비스·계량 오차가 누적 왜곡되지 않도록 주기적으로 바로잡는다.
시나리오 E — 원가 상승 → 마진 경고 대응
상황: 대파 시세가 단당 5,000원으로 올라 입고하며 단가를 수정.
동작: [입고] 또는 상세에서 가격 ‘5,000원’으로 수정.
처리: +25% 변동 감지 → 대파 카드에 ▲빨강 경고, 상세의 ‘영향 메뉴’에 제육볶음 마진율 하락 표시.
결과: 사장님이 판매가 조정·레시피 변경 등 의사결정. 단순 발주앱을 넘어 ‘경영 관리’ 가치 제공.

8. 발주 완료(입고) 처리 — 식재료 기준
실제 ‘발주(주문)’ 행위는 이 앱 밖에서 이뤄진다. 사장님은 평소 쓰던 발주앱·사이트·전화로 주문하고, 이 앱에는 ‘무엇을 · 어디서 · 얼마에 · 얼마나’ 발주했는지만 기록(등록)한다. 즉 앱의 역할은 발주서 전송이 아니라 ‘구매 사실의 장부화 + 재고·단가 자동 반영’이다.
이 섹션의 범위
이 앱은 발주서를 생성·전송하지 않는다. 외부에서 주문한 내역을 ‘등록’만 한다.
등록 기준은 두 가지 — 식재료 기준 / 레시피(메뉴) 기준. 본 섹션은 식재료 기준만 다룬다.
레시피(메뉴) 기준 등록은 ③ 발주 현황 문서 4.3에서 정의한다(필요량 역산 일괄 생성).
 | 
8.1 등록 기준 선택 (식재료 기준 / 레시피 기준)
발주 완료 등록 화면 진입 시 상단 탭으로 기준을 먼저 고른다.
식재료 기준 : ‘대파 1단, 양파 5kg’처럼 산 재료 단위로 직접 등록. 시장·청과·공산품 구매에 적합. (본 섹션)
레시피(메뉴) 기준 : ‘제육볶음 50인분어치’처럼 메뉴 단위로 등록하면 레시피가 식재료 소요량을 역산해 식재료별 레코드를 일괄 생성 — 상세는 ③ 발주 현황 문서 4.3.
8.2 발주 → 입고 2단계 상태 모델
주문한 날과 물건이 도착하는 날은 다르다. 주문 즉시 재고를 늘리면 ‘실제로는 없는 재고’가 잡혀 발주 판단이 틀어진다. 그래서 상태를 둘로 나눈다.

입력 즉시 ‘환산 단가 ○원/g’ 프리뷰 + 기존 평균가 대비 변동률(▲/▼) 표시.
저장 → ‘발주됨(도착 대기)’ 상태로 발주 현황에 등록. 도착 시 [입고 확정].
8.5 등록 방식 B — 반수동 (캡처 업로드 → OCR 자동 채움)
타 발주앱의 주문내역 화면을 캡처해 올리면, OCR이 수동 입력과 동일한 필드를 자동으로 채운다. 사장님은 ‘확인·수정’만 하면 되므로 입력 부담이 거의 사라진다.
구매처 선택(어느 앱/거래처 주문내역인지 지정).
주문내역 스크린샷 업로드(여러 장 가능).
OCR이 품목명·용량·금액·수량을 파싱 → 동일 필드에 값 자동 채움.
품목명을 기존 식재료와 자동 매칭(부분일치·별칭). 못 찾으면 ‘새 식재료로 등록’ 유도.
사장님이 값 확인·수정 후 등록 → ‘발주됨’ 상태 생성. 한 캡처의 여러 품목은 여러 레코드로 일괄 생성.

반수동 설계 원칙 — ‘OCR은 초안, 확정은 사람’
OCR 결과는 자동 등록하지 않는다. 반드시 사람이 확인하는 단계를 거친다(오인식 방어).
신뢰도가 낮은 필드(금액·수량 등)는 노랑 하이라이트로 표시해 검수 포인트를 좁힌다.
동일 캡처/주문번호 재업로드는 중복으로 감지해 경고 — 이중 입고·이중 단가 반영 방지.
 | 
8.6 단가 갱신 & 구매 이력 정책
한 식재료를 여러 구매처·브랜드·가격으로 사면 ‘진짜 단가’가 하나로 떨어지지 않는다. 그래서 단일 숫자 하나로 가두지 않고, ‘대표값 + 이력’을 함께 보여주는 구조로 간다.
(1) 기준 단가 = 수량 가중평균 (기본)
원가 계산에 쓰는 기준 단가는 최근 입고건들의 수량 가중평균을 기본값으로 한다(일시적 1회 고가/저가에 덜 휘둘림).
카드·상세 상단에는 ‘평균 ○원/g’을 대표로 노출하고, 옆에 최저·최고·최근가를 작은 배지로 함께 보여준다.
(2) 식재료 상세 하단 = 최근 주문/입고 내역 (사장님 제안 반영)
식재료 상세로 들어가면 하단에 최근 구매 내역이 표로 쌓여, 대략적인 시세와 구매처별 차이를 한눈에 파악할 수 있다.

8.7 발주 현황 페이지에서의 표시 (연동)
탭 구성: 도착 대기(발주됨) · 입고 완료 · 전체.
도착 대기 카드: 식재료·구매처·예정일·금액 + [입고 확정] 버튼. 예정일 지난 건은 강조.
입고 확정 시: 미개봉 개수 += 수량 → 식재료(잔여) 상태 갱신, 구매이력 확정, 평균단가 재계산이 한 번에 일어남.
8.8 유저 시나리오
시나리오 F — 수동으로 발주 완료 등록
상황: ○○청과에 전화로 대파 2단(단당 4,000원)을 주문하고 앱에 기록한다.
동작: 발주 현황 → [발주 완료 등록] → ‘식재료 기준’ → 구매처 ‘○○청과’ 선택.
동작: 식재료 ‘대파’, 용량 ‘1단=1,000g’, 금액 ‘4,000원’, 수량 ‘2단’ 입력 → ‘환산 4.0원/g, 평균 대비 ▲2.6%’ 프리뷰.
결과: ‘발주됨(도착 대기)’ 상태로 등록. 재고는 아직 그대로.
시나리오 G — 반수동(캡처 업로드)으로 한 번에 등록
상황: 식자재 앱에서 채소 5종을 한 번에 주문하고 주문내역 화면을 캡처했다.
동작: [발주 완료 등록] → 구매처 ‘□□상회’ 선택 → 캡처 이미지 업로드.
처리: OCR이 5개 품목의 용량·금액·수량을 자동 채움, 기존 식재료와 매칭(미매칭 1건은 ‘신규 등록’ 안내).
동작: 노랑 표시된 ‘양파 금액’만 수정 후 등록 → 5개 발주됨 레코드 일괄 생성.
결과: 입력 5번 → 캡처 1번 + 확인으로 단축.
시나리오 H — 도착 후 입고 확정 (재고·단가 반영)
상황: 다음날 대파 2단이 도착했다.
동작: 발주 현황 → 도착 대기 → 대파 카드 [입고 확정](수량 다르면 실수량 수정).
처리: 미개봉 +2통, 구매이력 확정, 평균단가 재계산. (원가 환산 net 1,700g.)
결과: 식재료(잔여)에서 대파가 ‘충분(초록)’으로 전환.
시나리오 I — 구매처 가격 비교로 절감
상황: 대파 단가가 계속 오르는 느낌이라 상세를 확인한다.
동작: 대파 상세 하단 ‘최근 주문/입고 내역’ 확인.
결과: 대림유통(3.6원/g)이 ○○청과(4.2원/g)보다 싸다는 힌트 확인 → 다음 발주처 전환 판단.

9. 다음 단계 제안
‘식재료(잔여)’와 ‘발주 완료(입고)’ 로직이 공급하는 기준 단가·잔여·구매이력 값을 토대로, 다음 페이지를 같은 깊이로 이어서 설계할 수 있다.
레시피 페이지: N인분 입력 토글, 1인분 자동 환산, 실시간 원가·마진율, 단가 변동 연동. → 이후 ‘레시피 기준 발주 완료 등록(8.1)’ 정의로 연결.
발주 현황 페이지: 발주 완료 등록(수동·반수동), 도착 대기/입고 완료 관리, 부족 식재료 발주 후보 제시.
마이페이지(④ 문서): 고정 지출(월), 카테고리 관리(+카테고리별 로스율 기본값), 단위 시스템 설정(4.8), 구매처·브랜드 관리, 목표 순이익률 기본값, 알림, 월 손익 리포트.
