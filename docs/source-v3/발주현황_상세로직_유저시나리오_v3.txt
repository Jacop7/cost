0. 역할 — 이 앱은 발주서를 보내지 않는다
실제 주문은 외부(발주앱·사이트·전화)에서 한다. 발주 현황 페이지의 역할은 네 가지다: ① 무엇을 사야 하는지 자동으로 모아주고(발주 후보), ② 주문한 사실을 기록하고(발주 완료 등록), ③ 도착하면 확정해 재고·단가에 반영하고(입고 확정), ④ 그 이력을 남긴다.
상태 흐름 (① 8.2 재인용)
발주 후보 → (외부에서 주문) → 발주됨(도착 대기) → 입고 확정 → 입고 완료
잔여재고·평균단가는 오직 ‘입고 확정’ 시점에만 움직인다.
부분입고·취소/미입고 상태 포함(① 8.2 표 참조).
 |

3. 핵심 로직
3.1 발주 후보 산출 (3가지 트리거)
자동 ①: 남은 개수 ≤ 안전재고 개수 (① 4.7-4).
자동 ②: 개봉분 [곧 소진] 플래그 ON.
계산 ③: 레시피 기준 — 필요량 > 잔여 환산량인 식재료.
+ 수동 추가: 검색해서 직접 후보에 올리기. 같은 식재료가 중복 트리거되면 1건으로 합치고 사유를 병기.
레시피 계산 필요량의 출처 명시: 자동 예측이 아니라 사장님이 입력한 기간·인분수에서 나온 값. 카드에 근거(‘내일 · 제육볶음 50인분’)를 표시하고 탭하면 계산 내역으로 연결. 판매 데이터 기반 자동 예측은 향후 확장.
3.2 권장 발주 수량 (올림)
공식
필요량(net) = Σ(1인분 소요량 × 인분수)   또는   안전재고 회복량
부족량(net) = max(0, 필요량 − 잔여 환산량)   [잔여 환산 = 개수 × 개당 용량 × (1−로스율)]
부족량(gross) = 부족량(net) ÷ (1 − 로스율)
권장 발주 수량 = Ceil( 부족량(gross) ÷ 개당 용량 )  — 최소 발주 단위 반영, 항상 올림
 | 
예시(내일 제육 50인분): 돼지고기 필요 10,000g·잔여 7,000g → 부족 3,000g → 1개(개당 5,000g). 양파 필요 4,000g·잔여 1,080g(로스 10%) → gross 3,244g → 3망(개당 1,200g). 대파는 잔여 2,550g > 필요 1,500g → 후보 제외.

3.4 입고 확정 — 시트 동작과 전파 맵
입고 확정은 이 앱의 핵심 트랜잭션이다. 시트에서 실제 도착 수량을 수정(부분입고)하고 잔량 처리(도착 대기 유지/취소)를 고른 뒤 확정하면, 아래가 한 번에 갱신된다.
자동 입고 처리: 도착 예정일 다음날이 되면 ‘발주됨’ 건은 주문 수량 그대로 자동 입고 확정된다. 수량이 다르거나 부분입고면 자동 처리 전·후 시트에서 수정하며, 수동 [입고 확정]도 그대로 쓸 수 있다.

4.2 레시피 계산기 (바텀시트)
[레시피로 계산] → 기간 선택(내일/이번 주/직접 선택) → 판매중 메뉴 목록에 인분수 입력.
식재료별 필요량 vs 잔여 비교표 표시 → 부족 항목만 권장 수량과 함께 후보에 추가.
이미 후보에 있던 항목은 수량 합산(사유 병기).
4.3 발주 완료 등록
우하단 [+] 또는 후보 카드에서 진입. ‘식재료 기준’(수동/반수동 OCR)은 ① 8.4~8.5 그대로, ‘레시피 기준 등록’(제육 50인분어치 주문 기록)은 계산기와 같은 역산으로 식재료별 레코드를 일괄 생성한다. 도착 예정일은 칩(오늘/내일/모레/날짜 선택)으로 입력하며 기본값 ‘내일’ — 도착 대기 정렬과 지연 알림이 이 날짜를 기준으로 동작한다.
구매 링크·옵션의 추가·관리는 기본적으로 식재료 상세(① 2.3)에서 한다. 발주 완료 등록·‘주문하기’ 시트에서는 저장된 옵션을 ‘선택’하면 구매처·브랜드·용량-금액이 자동 채워지고, 필요 시 ‘신규 링크·옵션 추가’로 즉석 등록도 가능하다.
5. 유저 시나리오
시나리오 A — 아침 발주 루틴 (자동 후보)
상황: 출근 후 발주 현황을 연다.
화면: 후보 탭에 ‘다진마늘(곧 소진)’, ‘양파(안전재고 미달)’ 2건이 떠 있다.
동작: 각 카드의 최근 주문 [같은 곳 주문] → 외부 앱에서 주문 → 돌아와 [발주 완료 등록](선택으로 자동 채움).
결과: 2건이 ‘도착 대기’로 이동. 후보 탭은 비워짐.
시나리오 B — 내일 장사 준비 (레시피 계산)
상황: 내일 단체 예약으로 제육 50인분 예상.
동작: [레시피로 계산] → 내일 → 제육볶음 50 입력.
처리: 돼지고기 부족 3,000g → 1개, 양파 부족 → 3망 후보 추가. 대파는 잔여 충분이라 제외.
결과: 후보 2건을 보고 주문 → 등록. 감이 아니라 레시피 기반 수량으로 발주.
시나리오 C — 입고 확정
상황: 다음날 돼지고기 1개(5kg)·양파 3망 도착.
동작: 도착 대기 → 각 카드 [입고 확정](양파는 2망만 와서 실수량 2로 수정 → 부분입고).
처리: 미개봉 개수 증가, 구매이력·평균단가·가격 추이 갱신, 영향 레시피 순이익 재계산.
결과: 식재료(잔여) 상태가 초록으로, 미입고 양파 1망은 도착 대기에 잔류.
시나리오 D — 예정일 지연
상황: 식용유 발주 건이 예정일을 하루 넘김.
화면: 도착 대기 카드가 빨강 강조 + 지연 알림.
동작: 구매처에 확인 후 ‘예정일 수정’ 또는 ‘취소’ 처리.
