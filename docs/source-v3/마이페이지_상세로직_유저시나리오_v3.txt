0. 역할
마이페이지는 두 가지를 담는다. ① 앱 전체가 참조하는 기준값(카테고리·단위 시스템·구매처·목표 순이익률·알림)과 ② 월 단위 경영 데이터(고정 지출 입력 → 고정지출률 → 월 손익 리포트). 여기서 바꾼 값은 식재료·레시피·발주 페이지에 즉시 전파된다.
비고 — 부가세 설정은 여기 없음
부가세(포함/별도/면세)는 메뉴마다 다를 수 있어 레시피별 토글로만 관리한다(② 3.5).
마이페이지에는 부가세 관련 설정을 두지 않는다.

2. 고정 지출 (월) — 핵심 로직
상세 구조는 ② 문서 2.4와 동일하다(총 월매출 + 인건비/플랫폼 수수료/포장비/배달·배송/광고·홍보, 각 총액 or 상세 입력). 여기서는 운영 규칙만 정리한다.
월 단위 레코드: 매월 1건. 전월 복사로 시작해 바뀐 항목만 수정(입력 부담 최소화).
저장 시 고정지출률 = 합계 ÷ 월매출 재계산 → 전 레시피 순이익 자동 갱신 + 각 레시피 추이에 회색 점.
각 레시피의 1개당 고정비는 ‘월 고정 지출 합계 × 메뉴 판매 비중 ÷ 메뉴 월 판매량’으로 배분된다(② 3.3). 메뉴별 평균 판매량은 레시피 화면에서 입력한다.
표시: 합계(매출 대비 %) + ‘매출 1,000원당 ○원’(예: 31.3% → 313원). 레시피 화면의 고정 지출 카드·자세히 시트가 이 데이터를 읽는다.
미입력 월: 가장 최근 입력된 월의 률을 잠정 적용 + ‘이번 달 고정 지출을 입력하세요’ 배너.
3. 월 손익 리포트
공식
월 순이익(추정) = 총 월매출 − 고정 지출 합계 − 재료비
재료비 = 해당 월 ‘입고 확정’ 금액 합계(③에서 자동) — 입력 불필요
예) 28,500,000 − 8,930,000(31.3%) − 8,200,000(28.8%) = 11,370,000원(39.9%)
 | 
월별 추이 그래프(순이익·순이익률)와 항목별 구성(도넛 — 비용 그레이, 순이익 초록, ②와 동일 색 체계).
주의 표기: ‘추정’임을 명시 — 재료비는 입고 기준(소진 기준 아님), 부가세·세무 조정 미반영.
4. 분류·기준 관리 로직
4.1 카테고리
기본 12종(축산-계란 · 수산-해조류 · 농산(신선) · 곡물-견과-분말 · 유제품 · 냉동식품 · 소스-유지류-장류 · 향신료-허브 · 음료-주류 · 상온가공-건식 · 두부-발효식품 · 베이커리).
추가·이름변경·순서 변경 가능. 삭제 시 소속 식재료가 있으면 ‘다른 카테고리로 이동’ 선택 후 삭제.
카테고리별 로스율 기본 제안값도 여기서 수정(식재료 등록 시 제안에 반영).
4.2 단위 시스템
미터법(기본)/미국식/영국식 선택 → 개당 용량 셀렉박스의 단위 목록만 변경(① 4.8). 내부 저장은 항상 g·ml·개라 기존 데이터는 영향 없음.
조리컵 용량 사용자 설정(200/240/250ml 기본값). 스푼은 공통 15/5ml 고정.
4.3 구매처·브랜드
발주 완료 등록 때 입력된 신규 구매처·브랜드는 자동 사전 등록 — 여기서 이름변경·병합(오타 통합)·숨김.
병합 시 구매 이력·가격 추이도 합쳐진다(평균단가 재계산).
4.4 목표 순이익률 기본값
신규 레시피 생성 시 기본 목표로 자동 입력. 변경해도 기존 레시피의 개별 목표는 건드리지 않음.

6. 유저 시나리오
시나리오 A — 월초 고정 지출 입력
상황: 6월 1일, 5월 정산이 끝났다.
동작: 마이페이지 → 고정 지출 → ‘전월 복사’ → 바뀐 항목(인건비·광고)만 수정 → 저장.
처리: 고정지출률 30.1 → 31.3% 갱신, 전 레시피 재계산, 월 손익 리포트 생성.
결과: ‘5월 순이익 11,370,000원(39.9%)’ 확인.
시나리오 B — 구매처 오타 병합
상황: ‘대림유통’과 ‘대림 유통’이 따로 쌓였다.
동작: 구매처 관리 → 두 항목 선택 → 병합.
처리: 구매 이력·가격 추이 통합, 평균단가 재계산.
시나리오 C — 단위 시스템 변경
상황: 수입 레시피 때문에 oz 입력이 필요하다.
동작: 단위 시스템 → 미국식 선택.
처리: 개당 용량 셀렉박스가 oz·lb·fl oz·… 로 바뀜. 기존 데이터(g·ml 저장)는 그대로.
