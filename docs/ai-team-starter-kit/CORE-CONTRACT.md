# 공통 운영 계약

## 권위와 경계

- 채팅은 관측 표면이며 공식 기억이 아니다. 공식 상태는 저장소 Task·결정·검수 원본이 소유한다.
- 하나의 주제에는 하나의 공식 문서만 둔다. 템플릿·검수 제안·생성 산출물은 공식 정책을 대체하지 않는다.
- 모델·역할·팀은 실행 경계일 뿐 승인 권한이 아니다. 사람 승인과 운영 실행 권한은 명시적으로 분리한다.

## 안전한 실행

- Task는 대상 SHA, 허용·제외 경로, 위험, 검증 명령, 중단 조건을 가진다.
- 독립검수 실패·판정 없음은 PASS로 변환하거나 삭제하지 않는다.
- 한 목적에 두 독립검수 엔진을 병렬로 호출하지 않는다. fallback은 대상 프로젝트의 구조화된 정책으로만 허용한다.
- 모델 예산은 회차·입력 범위·실비를 기록하고, 자동 배수 증액을 하지 않는다.

## 이식 경계

공통 core는 Task, 역할, 팀 route, HANDOFF, 검수·사람 결정의 구조만 제공한다. DB, CI, 배포,
credential, 제품 규칙은 `adapters/` 또는 대상 프로젝트 profile에 두며 core를 수정해 섞지 않는다.
