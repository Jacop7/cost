# 재고 처리 확인·성공 안내

2026-09-09 사용자 요청. 입고(기존 간편 입고 경로 포함), 차감, 폐기 모두 실행 전 공용 ConfirmDialog를 연다. 확인/취소에서 취소는 mutation을 호출하지 않는다.

- 입고: `재고를 입고할까요?` → 입고 → 서버 성공 → `입고 처리했어요.`
- 차감: `재고를 차감할까요?` → 차감 → 서버 성공 → `차감 처리했어요.`
- 폐기: `재고를 폐기할까요?` → 폐기 → 서버 성공 → `폐기 처리했어요.`
- ToastHost는 앱 루트에 한 번 배치한다. 상세로 돌아간 뒤에도 표시되며 3초 후 사라진다. 새 토스트를 이전 id/타이머가 제거하지 않는다.
- 실패/건너뜀(skipped)/화면 이탈 뒤 늦은 응답에는 성공 토스트를 내지 않는다. 오류창과 입력 초안 보존은 유지한다.
- 실제 DB 쓰기는 검수 중 수행하지 않았다. 브라우저에서는 3개 확인창을 열고 취소, 단위 시험에서는 mock 성공·실패 응답과 토스트 표시/타이머를 검증했다.
- `/appmap` 샘플 모드는 기존대로 쓰기를 차단하므로 실제 처리 성공 토스트가 나오지 않는다. 확인창 자체는 샘플에서도 표시된다. 성공한 것으로 위장하지 않는다.

범위 밖: 폐기 사유·손실 preview, 입고일 달력, 전체 페이지 종결 및 네이티브 실측. 기존 미지원 상태를 이 변경으로 완료 처리하지 않는다.

검증: 타입 PASS, 모바일 전체 68파일 691/691 후 skipped 추가시험 포함 StockChange/Toast 17/17 PASS. Sol 한정 재검수 QuickInbound26+StockChange15+Toast2=43/43 직접 PASS, 추가 Finding 없음. 실제 DB 성공 저장은 실행하지 않았으며 전체 verify 6/6이나 외부 독립검수 완료를 뜻하지 않는다.
