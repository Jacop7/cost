2026-09-09 사용자 요청: 권위 루트의 `docs/prototypes/0_full-page-flow-prototype-ui-applied.html`에서 수정 메뉴 관련 6탭을 직접 클릭하며 실제 Expo에 반영한다.

[나란히 비교](./compare.html)의 왼쪽은 권위 루트 파일의 각 탭을 클릭한 390px 캡처, 오른쪽은 로컬 `/appmap`이 실제 Expo를 연결한 iframe 캡처다. prototype/Expo의 식재료·가격·단위·이력 데이터는 다르며, 픽셀 동일 판정이나 동일 fixture 검산 자료로 쓰지 않는다. 추가 `expo-inbound-confirm`, `expo-option-menu`, `expo-option-form`은 실제 열기 동작을 확인한 캡처다. 저장·삭제·외부 URL 실행은 브라우저 검증에서 하지 않았다.

## 검수 및 시험

- 타입 검사 PASS.
- 전체 모바일 67파일 **680/680 PASS**. 이후 공용 확인 시트의 선택적 compact footer 변경은 영향 범위 3파일 **46/46 PASS**로 재실행했다.
- AppMap model·샘플 시험 **22/22 PASS**. 이전 완전소진 오류를 입고 오류로 보여주던 경로는 제거하고 `unavailable`로 표시한다.
- 기존 Sol read-only 검수 4 Findings: 입고 확인 누락 / 필수 숫자 검증 / unmount 후 늦은 navigation / 구매 링크 메뉴·URL 검증. 모두 반영 후 재검수에서 닫힘. 마지막 음수 부호 보존 경계는 Sol이 stock 12/12, form 32/32 직접 재실행했다.
- 전체 `pnpm verify`도 시작했으나 초기 타입 시험에서 신규 시험의 nullable mock 접근을 발견했다. 수정 후 타입·모바일 재실행은 PASS지만 이 전체 실행을 최종 변경판의 **6/6 PASS로 주장하지 않는다**. 테스트 실행 중에도 검수 수정을 병행했으므로 같은 SHA 완결 증거가 아니다.
- Sol 로컬 검수는 공식 Fable/Opus·네이티브·전체 P3 종결을 대체하지 않는다. main 병합·운영 배포 없음.

## 남는 차이와 다음 작업

1. **폐기 사유 저장 / 예상 손실 미리보기 미완료.** 현재 `useStockChange`의 `e2_discard` 입력은 식재료 ID·남은양이며, 사유를 전달하지 않는다. 손실 확정값도 서버 권위다. UI에 미지원 표시를 남겼고, 새 원장/미리보기 계약 없이 입력을 받거나 금액을 임의로 확정하지 않았다. DB 계약 추가·검산·회귀가 별도로 필요하다.
2. 공통 토큰의 버튼/텍스트/비활성 opacity·접근성 focus, 최신 ⋮ 헤더 결정을 유지한다. 프로토타입의 과거 ✎ 수정·가짜 배경 skeleton·하단 탭 위 가짜 overlay를 복제하지 않는다. 실제 Modal은 실제 상세와 탭 위에 열린다.
3. 구매가격은 기존 계약대로 저장되지 않는 미리보기다. 수정 페이지에서 과거 입고금액을 임의로 채우지 않는다. 기존 URL 없는 구매 옵션도 삭제하지 않으며 링크 수정 시 유효한 URL·구매처 입력이 필요하다.
4. 전체 185 target/6탭의 모든 하위 팝업, 200% 글자 확대·실기기·동일 SHA 전체 게이트를 완료했다고 선언하지 않는다.

따라서 상태는 **6탭 로컬 구현 반영, 폐기 하위 기능 유보**이며 ‘프로토타입 전부 동일 구현 완료’는 아니다.
