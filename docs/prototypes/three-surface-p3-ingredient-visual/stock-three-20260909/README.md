# 입고·차감·폐기 본문 대조

2026-09-09. 권위 루트 프로토타입의 `stock_inbound`, `stock_deduct`, `stock_discard` 탭을 실제 클릭하고 최종 DOM(후처리 포함)을 검사했다. 이전에는 초기 render 함수만 보고 후처리의 결과 필드 재배치를 놓쳤다.

## 수정

- 입고: 구매처 선택 아래 용량 → 전체 너비 수량 조절 → 총 입고량 → 실제 결제금액 → 입고 후 기준단가 → 입고일 순서. 기존 별도 반영 내용 카드는 이 레이아웃에서 제거하고 서버 미리보기 단가를 원본 위치로 옮겼다.
- 저장 옵션 용량/결제금액은 읽기 전용, 직접 입력은 편집 가능. 저장 옵션 수량 변경 시 총 결제금액=옵션 금액×수량. RPC는 기존 개당 amount 계약 유지. 동일 옵션 재조회 용량/금액도 동기화. 기존 간편 입고/직접 입력의 사용자 수정 금액은 보존한다.
- 차감/폐기: 입력 숫자는 좌측, 단위는 우측. 결과값은 `StockResultField` 공용 규격으로 라벨 위·박스 안 값 우측. 차감 사유 필수 계약 유지.
- 입력 필드 중복 세로 gap 제거, 구매처 컨트롤 높이50, 공용 상단 카드/탭 간격 조정.

## 종결하지 않은 차이

- 폐기 사유: E2 `e2_discard`에는 사유 인자가 없어 비활성 필드와 미지원 설명으로 표시한다. 입력 후 저장됐다고 오인시키지 않는다.
- 예상 손실: 서버 미리보기 계약이 없으므로 `산출 미지원` 표시. 임의 원가를 확정 손실처럼 기록하지 않는다.
- 입고일은 기존 서버 날짜 기반 텍스트 편집을 유지한다. 원본 HTML의 브라우저 날짜 입력기와 같다고 판정하지 않는다.
- 샘플 데이터·금액·폰트·색상은 앱의 실제 데이터/기존 공용 토큰을 따른다. 픽셀 동일·전체 3탭 완전 종결 아님.

`compare.html`: 원본과 실제 Expo 나란히, 390×844. 입고 하단도 별도 캡처했다. 샘플 미리보기에서만 캡처했고 실제 저장은 실행하지 않았다.

검증: 타입 PASS, 모바일 67파일 685/685 PASS, 후행 테두리 변경 후 QuickInbound/InputTone 25/25, AppMap 22/22 PASS. Sol 내부 검수에서 읽기 전용 금액×수량 및 동일 ID 재조회 동기화 문제를 발견해 수정·회귀시험 추가. Sol 최종 재실행 QuickInbound24+StockChange12+InputTone1=37/37, 한정 PASS·추가 치명/중대 없음. 외부 Fable/Opus 검수나 전체 verify/네이티브 측정 완료를 의미하지 않는다.
