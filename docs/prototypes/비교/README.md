|---|---|
| **`타이포-결정-페이지.html`** | **이걸 연다.** 독립 페이지. 결정 두 건을 컴포넌트 단위로 나란히 그리고 근거·의견까지 함께 담았다 |

`타이포-결정-페이지.html`은 프로토타입을 끼우지 않는다. 프로토타입의 CSS와 토큰을 그대로
복사해 필요한 컴포넌트만 직접 그렸고, Pretendard 4 face를 실제로 로드한다.

원본은 `../0_full-page-flow-prototype-ui-applied.html`(`DS-20260904-011`)이며 **수정하지 않았다.**
사본에 전환 오버레이만 덧붙였다.

### 무엇을 비교하나

`TYPE` 스케일(22·20·18·16·14·13) 밖에 있는 제품 텍스트 중 결정이 필요한 두 가지다.
근거 수치는 활성 182건 전수 computed 측정에서 나왔다.

| 대상 | 제품 화면 | 실제 구성 (클래스별 실측) | 선택지 |
|---|---:|---|---|
| `12px` | 244회 · 15종 | **배지·칩 188회(77%)** — `badge` 89 · `expo-status` 58 · `expo-category` 38 · `detail-tag` 3. 나머지는 폼 라벨 23회와 인라인 보조 | `13`으로 흡수 / `12` 단계 신설 |
| `15px` | 210회 · 14종 | **행 라벨 158회(75%)** — `span` 88(영업일·매출) · `sales-label` 70(순이익·매장). 버튼 31회, 입력 15회 | `16`으로 올림 / `14`로 내림 / 역할별 분리 |

**초기 서술 정정.** 처음에 `15px`을 "버튼·입력"이라고 적었으나 틀렸다. 클래스별로 세어 보니
버튼은 31회뿐이고 **75%가 손익표 행 라벨**이다. 몇 개 표본만 보고 성격을 규정한 결과였다.
이 결정의 실체는 "행 라벨을 어느 역할로 볼 것인가"다.

### 바꾸지 않는 것

- **프로토타입 셸** — 상태바 시각 `9:41`(11px 368회), 화면 ID 배지 `ING-06`(10px 182회),
  뒤로가기 `‹`. 제품 UI가 아니다.
- **문자 기호로 그린 아이콘** — `＋` `›` `⋮` 등 295회. 크기가 17·19·21·25·29px로 흩어져
  있지만 이건 타이포가 아니라 아이콘이다. UI 가이드 §1.6이 **"문자 기호를 뒤로가기·검색·
  수정·닫기·더보기 아이콘으로 사용하지 않는다"**고 이미 금지하고 있으므로 별도 항목으로 다룬다.

### 구현 주의

프로토타입은 로드 시 `history.replaceState`로 주소를 `?screen=…`으로 다시 쓰며 다른 쿼리를
버린다(PRT-184 URL 계약). 그래서 오버레이는 `location.search`가 아니라
`performance.getEntriesByType('navigation')[0].name`의 최초 URL에서 파라미터를 읽는다.
