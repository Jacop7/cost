# 전체 페이지 흐름 프로토타입 · 현재 확정안

## 1. 문서 역할

이 문서는 `full-page-flow-prototype.html`에 현재 실제로 노출되는 화면만을 화면별로 정리한 살아 있는 확정안이다.

- 변경 과정과 원복 이력은 `full-page-flow-prototype-changelog.md`에 계속 누적한다.
- 이 문서에는 대체된 옛 문구와 옛 구조를 남기지 않는다.
- 같은 항목이 다시 수정되면 이 문서의 기존 항목을 교체하고, 변경 이력에는 새 PRT 항목을 추가한다.
- 기획안 작성 시에는 이 문서를 기준으로 사용하고 변경 이력은 근거 확인용으로만 사용한다.
- 실제 Expo 앱과 앱 소스에는 아직 반영하지 않는다. 현재 범위는 프로토타입과 문서다.

현재 기준 파일:

- 프로토타입: `docs/prototypes/full-page-flow-prototype.html`
- 전체 변경 이력: `docs/prototypes/full-page-flow-prototype-changelog.md`
- 현재 확정안: `docs/prototypes/full-page-flow-prototype-current-spec.md`

현재 반영 범위:

- 식재료 기본 화면 12개 전체
- 레시피 기본 화면 4개: 메인, 상세, 판매가 시뮬레이션, 레시피 추가
- 위 화면에서 직접 진입하는 선택창·확인창·상태 화면 전체

개수는 기본 화면과 팝업을 분리해 관리한다. 같은 렌더 결과를 재사용하는 상태도 URL·진입 계약이 다르면 검수 단위에는 포함한다.

| 구분 | 기본 화면 | 직접 연결된 팝업·상태 | 계약 검수 단위 | 서로 다른 렌더 결과 |
|---|---:|---:|---:|---:|
| 식재료 | 12 | 29 | 41 | 38 |
| 레시피 현재 확정 범위 | 4 | 7 | 11 | 11 |
| 합계 | 16 | 36 | 52 | 49 |

레시피 핵심 4개 화면에서 이어지는 보조 화면 6개와 보조 팝업 2개도 별도로 도달성 검수했다. 이 8개는 이번 확정안의 핵심 화면 수에는 합산하지 않고, 연결 흐름과 구현 점검 항목에 기록한다.

`폐기 내역` 독립 화면은 삭제하지 않고 숨김 보존한다. 화면 목록에서는 제외하며 `재고 내역`의 폐기 유형으로 연결한다.

## 2. 공통 확정 규칙

### 2.1 내비게이션과 헤더

- 하단 탭은 `식재료 · 레시피 · 발주 · 매출관리 · MY` 5개다.
- 메인 화면 헤더 우측에는 검색과 알림 아이콘을 둔다. 알림 아이콘은 새 알림 점을 가질 수 있다.
- 상세 화면은 좌측 뒤로가기와 화면 제목을 사용한다.
- 식재료 상세 우측에는 `✎ 수정`, 레시피 상세 우측에는 `✎ 수정`을 둔다.
- 헤더 우측에 재고량, 입고 건수 같은 요약 숫자를 중복 노출하지 않는다.

### 2.2 카드와 목록

- 카드 모서리는 둥글게 처리하고 카드 사이에는 11px 기본 간격을 유지한다.
- 섹션 헤더는 좌측 제목을 우선하며 우측의 중복 숫자·설명은 최소화한다.
- 상세 미리보기 목록은 최대 3개까지 노출하고 하단 행동은 `전체보기 ›`로 통일한다.
- 값 목록은 좌측에 이름·보조 정보, 우측에 핵심 값·단가를 둔다.
- 빈 상태는 한 문장으로 표시하고, 가능한 다음 행동이 있으면 빈 상태 바로 아래에 버튼을 둔다.

### 2.3 입력과 계산 결과

- 입력 라벨은 입력칸 위에 둔다. 입력칸 안에는 값 또는 플레이스홀더만 둔다.
- 필수값은 라벨 우측의 파란색 `*`로 표시한다.
- 입력칸 아래의 중복 설명은 노출하지 않는다.
- 합계, 변경 후 재고, 예상 손실, 구매 단가 같은 읽기 전용 결과는 라벨과 값이 분리된 결과 카드로 표시한다.
- 읽기 전용 결과 카드는 일반 입력칸보다 구분되도록 옅은 배경과 테두리를 사용한다.
- 저장·추가 버튼은 화면 하단에 고정하고, 필수값이 준비되지 않으면 비활성화한다.

### 2.4 팝업

- 선택·입력은 하단 바텀시트로 연다.
- 단일 선택창은 제목 다음에 선택지를 바로 배치하며 제목을 반복하는 작은 소제목을 넣지 않는다.
- 현재 선택값 우측에는 `✓`를 표시한다.
- 삭제, 철회, 판매 상태 변경처럼 순수 확인만 필요한 창은 화면 가운데 알럿으로 연다.
- 확인 알럿의 행동은 하단 2열 버튼을 사용한다.
- 메시지 팝업 제목은 간단한 명사형으로 작성한다. 예: `입고 실패`.

### 2.5 최근 수정과 이력

- 상세의 최근 수정 영역은 최근 7일 안에 표시할 기록이 있을 때만 노출한다.
- 기록이 없으면 영역 전체를 숨긴다.
- 수정 내역은 최근 7일만 표시하고 재고 수량 변동과 메모 변경은 포함하지 않는다.
- 재고·구매 이력 필터는 각각 독립된 필터 칩으로 표시하고, 누른 필터에 맞는 단일 선택창을 연다.

### 2.7 글꼴과 글자 위계

기본 글꼴 순서:

`Pretendard → -apple-system → BlinkMacSystemFont → Segoe UI → sans-serif`

프로토타입이 불러오는 Pretendard 파일은 `Regular 400`, `SemiBold 600`, `Bold 700`, `ExtraBold 800` 네 가지다. CSS의 `750`, `850`, `900`은 별도 폰트 파일이 아니라 브라우저가 가까운 굵기로 처리하는 값이므로 실제 Expo 구현에서는 다음처럼 정규화한다.

| 역할 | 크기·행간 | 굵기 | 자간·색상 |
|---|---|---:|---|
| 메인 화면 제목 | `22px / 30px` | `800` | `-0.6px`, `--ink` |
| 하위 화면 제목 | `18px / 26px` | `700` | `-0.3px`, `--ink` |
| 상세 대표 이름 | `20px` | `800` | `--ink` |
| 팝업 제목 | `19px`, 확인창 `1.4` 행간 | `700~800` | `--ink` |
| 카드·목록 제목 | `16px` | `700~800` | `--ink` |
| 핵심 숫자 | `18~23px` | `800` | 탭 숫자 사용 |
| 일반 값·버튼 | `15~16px` | `700` | `--ink` 또는 흰색 |
| 필드 라벨 | `14px` | `800` | `--sub` |
| 일반 본문 | `14px / 1.45~1.5` | `600~700` | `--sub` |
| 보조 정보 | `13px / 1.35` | `600~700` | `--ter` |
| 뱃지·캡션 | `12px` | `700` | 상태색 또는 `--ter` |

공통 규칙:

- 금액·수량은 `font-variant-numeric: tabular-nums`를 적용해 자릿수 폭을 맞춘다.
- 핵심 값보다 설명 문구의 굵기와 명도를 낮춘다.
- 화면에 요청된 `750`, `850`, `900`은 Expo 토큰에서 각각 `700`, `800`, `800`으로 정리한다.
- 작은 설명글은 최소 `12px`이며 동작이나 상태 이해에 필요하지 않으면 표시하지 않는다.

### 2.8 화면 골격과 여백

제품 화면 기준 골격:

| 요소 | 현재 규격 |
|---|---|
| PC 프로토타입 작업 영역 | 최대 `960px`, 좌우 `12px`, 상단 `12px` |
| 제품 화면 프레임 | 최대 `602px`, 화면 중앙 배치 |
| 일반 헤더 | 높이 `60px`, 좌측 뒤로가기 `40×40px` |
| 메인 헤더 | 최소 높이 `60px`, 좌우 `20px` |
| 본문 | 좌우 `16px`, 하단 `104px` |
| 하단 탭 | 높이 `60px`, 5등분 |
| 하단 고정 행동 | 하단 탭 위 `60px`, 좌우 `16px`, 위 `10px`, 아래 `14px` |
| 카드 간격 | `11px` |
| 기본 카드 | 반지름 `16px`, 테두리 없음, 그림자 `0 1px 3px rgba(0,0,0,.04)` |
| 카드 내부 좌우 여백 | 기본 `15~16px` |
| 일반 목록 행 | 최소 높이 `82px`, 패딩 `14px 15px` |
| 상세 계산 행 | 최소 높이 `52px`, 세로 `9px` |
| 섹션 헤더 | 최소 높이 `48px`, 좌우 `16px` |

배치 원칙:

- 한 화면의 핵심 내용은 최대 `602px` 안에서 한 열로 쌓는다.
- 카드 안에서는 왼쪽에 이름·설명, 오른쪽에 금액·수량을 우측 정렬한다.
- 같은 계층의 카드는 `11px`, 입력 필드는 `15px`, 2열 입력은 `8~9px` 간격을 사용한다.
- 스크롤 본문은 하단 탭과 고정 버튼에 가리지 않도록 `104px` 하단 여백을 확보한다.
- 제품 UI가 아닌 상단 프로토타입 화면 선택 카탈로그는 실제 앱 구현 대상에서 제외한다.

### 2.9 헤더·탭·필터·하단 내비게이션

헤더:

- 뒤로가기 터치 영역: `40×40px`, 화살표 시각 크기 `36px`.
- 검색·알림 터치 영역: 각각 `40×40px`, 아이콘 `24×24px`, 선 두께 `1.9px`.
- 알림 점: `7×7px`, 우측 `9px`, 상단 `8px`, 표면색 `1.5px` 테두리.
- 상세의 `수정` 행동: `16px / 700`, 별도 배경 없이 헤더 우측 배치.

상단 카테고리 탭:

- 높이 `42px`, 항목 간격 `20px`, 좌우 `20px`.
- 기본: `15px / 600`, `--ter`.
- 활성: `15px / 700`, `--ink`, 하단 `2.5px` 선.
- 항목이 많으면 가로 스크롤하며 줄바꿈하지 않는다.

필터:

- 일반 필터는 내용 폭의 pill이며 패딩 `9px 14px`, 완전 둥근 모서리, `14px / 700`을 사용한다.
- 레시피 메인 필터는 패딩 `5px 10px`, `13px / 700`; 활성 상태는 검정 배경과 흰 글자를 사용한다.
- 재고·구매 이력 필터는 한 문장으로 합치지 않고 독립 pill로 배치한다.

레시피 계산 기준 탭:

- 흰 배경의 밑줄 탭이며 높이 `48px`, 항목 간격 `22px`, 좌우 `15px`.
- 기본: `16px / 600`, `--ter`.
- 활성: `16px / 700`, `--ink`, 하단 `2.5px` 선.

하단 내비게이션:

- `식재료 · 레시피 · 발주 · 매출관리 · MY`를 같은 폭 5열로 배치한다.
- 아이콘 `24×24px`, 선 두께 `1.8px`, 라벨 `12.5px / 700`.
- 기본색 `#b0b8c1`, 활성색 `--blue`.

### 2.10 카드·목록·상태 요소

메인 목록 카드:

- 식재료 카드 최소 높이 `108px`, 패딩 `14px 15px`, 카드 사이 `10px`.
- 레시피 카드 최소 높이 `148px`, 패딩 `15px`.
- 카드 상단은 `상태 뱃지 → 이름 → 우측 카테고리` 순서로 한 줄 배치한다.
- 카테고리는 우측 끝에 옅은 회색 배경의 `12px / 700` 태그로 표시한다.

상태 뱃지:

- 패딩 `4px 7px`, 반지름 `6px`, `12px / 700`, 행간 `1`.
- `여유`는 초록, `소진 임박·목표 미달`은 빨강, 주의 상태는 주황을 사용한다.
- 안전재고·최소 발주·최근 입고 칩은 패딩 `5px 8px`, 반지름 `6px`, `12px / 700`.

상세 카드:

- 상단 기본 정보 패딩 `15px 16px`.
- 최근 수정 행은 상단 카드 하단 전체 폭을 사용하고 `13px 16px` 패딩과 위 구분선을 둔다.
- 상세 섹션 헤더는 보조 표면 배경을 사용하고 제목 `16px`, 설명 `12px`로 구분한다.
- 상세 목록의 하단 행동은 높이 `45px`, 보조 표면 배경, `14px / 700`의 `전체보기 ›`를 사용한다.
- 빈 상태는 패딩 `18px 16px`, `14px`, `--ter`로 표시한다.

### 2.11 입력·계산 결과·버튼

기본 입력:

- 필드 사이 간격 `15px`.
- 라벨과 입력칸 사이 `7px`.
- 입력칸 높이 `50px`, 좌우 `14px`, 테두리 `1px --line`, 반지름 `12px`.
- 입력값 `15px / 700`, 플레이스홀더 `15px / 600`, 색상 `--ter`.
- 필수 `*`는 라벨 바로 뒤 `--blue`.
- 2열 필드는 같은 비율이면 간격 `9px`; 재고 입력의 단위 열은 `112px`, 간격 `8px`.

읽기 전용 계산 결과:

- 라벨은 결과 상자 밖 위에 둔다.
- 결과 상자는 배경 `--blue2`, 테두리 `1px #b8d3ff`, 반지름 `13px`.
- 값만 들어가는 행은 패딩 `13px 14px`, 결과값 `18px / 800`, `--blue`.
- 읽기 전용 입력값은 보조 표면 배경과 `--sub` 글자를 사용한다.

버튼:

- 기본 주 버튼: 높이 `48px`, 반지름 `12px`, `--blue`, 흰 글자 `16px / 700`.
- 기본 비활성: `#d1d6db`; 레시피 추가의 비활성 예시는 `#9fc3f1`.
- 2열 팝업 행동: 높이 `48px`, 간격 `8px`; 취소는 보조 표면, 위험 행동은 `#fff0f1`과 `--red`.
- 플로팅 추가 버튼: 높이 `54px`, 우측 `16px`, 하단 `76px`, 좌우 `19px`, 반지름 `28px`, 그림자 `0 7px 20px rgba(49,130,246,.34)`.
- 화면 우측의 행 더보기 버튼은 현재 `34×34px`다. 실제 Expo 구현 전 최소 터치 영역 `44×44px` 확보 여부를 확인한다.

### 2.12 팝업·확인창·컨텍스트 메뉴

바텀시트:

- 오버레이: `rgba(0,0,0,.42)`.
- 최대 높이: 화면의 `76%`.
- 상단 모서리: `20px`.
- 내부 패딩: 위 `9px`, 좌우 `16px`, 아래 `24px`.
- 핸들: `40×5px`, 반지름 `3px`, 아래 간격 `15px`.
- 제목: `19px`, 본문 시작 전 작은 중복 설명은 표시하지 않는다.
- 하단 행동이 있으면 흰 배경에 위 구분선을 두고 화면 하단에 고정한다.

중앙 확인창:

- 오버레이 내부 여백 `24px`, 최대 너비 `340px`.
- 내부 패딩 `24px 20px 18px`, 반지름 `18px`.
- 그림자 `0 18px 50px rgba(25,31,40,.24)`.
- 제목과 본문은 가운데 정렬한다.
- 하단 행동은 2열, 높이 `48px`, 간격 `8px`.
- 핸들은 표시하지 않는다.

우측 컨텍스트 메뉴:

- 헤더 아래 상단 `52px`, 우측 `14px`, 너비 `184px`.
- 테두리 `1px --line`, 반지름 `13px`.
- 그림자 `0 10px 28px rgba(25,31,40,.18)`.
- 각 행 최소 높이 `48px`, 좌우 `15px`, `14px / 700`.

수정 행동 시트:

- 제품 화면 좌우 `10px`, 하단 탭 위 `72px`.
- 메뉴 그룹 반지름 `14px`, 각 행 높이 `51px`, `16px` 가운데 정렬.
- 닫기 버튼 높이 `52px`, 위 간격 `9px`, 파란 글자.

### 2.14 PC·모바일 표시 규칙과 현재 한계

PC:

- 회색 작업 배경 위에 최대 `680px`의 프로토타입 카탈로그와 최대 `602px`의 제품 화면을 가운데 배치한다.
- 제품 화면은 모바일 앱과 같은 한 열 구조를 유지하며 PC용 다단 레이아웃으로 늘리지 않는다.

모바일:

- 제품 화면은 가용 폭 `100%`를 사용하되 현재 프로토타입의 작업 영역 좌우 `12px`는 유지된다.
- `520px` 이하에서는 카탈로그 제목만 숨기며 화면 선택 탭은 남는다.
- 제품 카드·입력·팝업의 글자 크기와 내부 여백은 PC와 동일하다.
- 현재 CSS에는 모바일 전용 카드 재배치나 2열 입력의 1열 전환 규칙이 없다.

현재 한계:

- 주소가 PC용인지 모바일용인지에 따라 디자인이 달라지는 것이 아니라 실제 브라우저 폭에 따라 같은 구조가 줄어든다.
- `520px` 반응형 규칙보다 뒤에 공통 규칙이 다시 선언되어 일부 모바일 값이 덮어써진다. 구현 전 최종 반응형 규칙을 CSS 맨 뒤에서 다시 정리해야 한다.
- `--line3`, `--sub2`는 정의 없이 일부 선택자에서 사용된다. `--line3`는 `#d1d6db` fallback이 있지만 `--sub2`는 fallback이 없어 공용 토큰으로 정리해야 한다.
- `34×34px` 아이콘 버튼과 일부 작은 행동은 실제 앱 접근성 터치 영역 검수가 필요하다.

# 3. 식재료 현재 확정안

## ING-01 · 식재료 메인

### 헤더와 상단 탐색

- 화면 제목: `식재료`
- 우측 행동: 검색, 알림
- 카테고리 탭: `전체 · 축산·계란 · 수산·해조류 · 농산(신선) · 곡물·견과·분말 · 유제품 · 냉동식품`
- 목록 정렬 칩 기본값: `재고 적은 순⌄`

### 식재료 카드

각 카드는 다음 순서로 표시한다.

1. 재고 상태 뱃지: `여유`, `소진 임박`, `소진`
2. 식재료명
3. 카테고리
4. `총 {재고량}`
5. 안전재고가 필요한 경우 `안전재고 {수량}`
6. 기준 단가
7. `최근입고 {MM/DD}`

현재 예시:

- 설탕: `소진 임박 / 곡물·견과·분말 / 총 3kg / 안전재고 3kg / 1.80원/g / 최근입고 08/08`
- 고춧가루: `소진 임박 / 향신료·허브 / 총 812g / 안전재고 1kg / 28.00원/g / 최근입고 08/27`
- 쌀: `여유 / 곡물·견과·분말 / 총 13kg / 3.20원/g / 최근입고 08/27`
- 계란: `여유 / 축산·계란 / 총 123개 / 300.00원/개 / 최근입고 08/29`
- 대파: `여유 / 농산(신선) / 총 4.1kg / 4.00원/g / 최근입고 08/29`

상태 판정:

- 재고가 0 이하이면 `소진`이며 음수 재고를 그대로 표시한다.
- 재고가 양수이면서 안전재고 이하이거나 소진 임박 판정이면 `소진 임박`이다.
- 그 외는 `여유`다.
- 안전재고 관련 뱃지는 `안전재고` 명칭을 사용하며 노란색 계열로 표시한다.

### 정렬 선택창

- 제목: `정렬 기준`
- 선택지: `최신순 · 재고 적은 순 · 단가 높은 순 · 이름순`
- `최신순`은 최신 등록순이다.
- 추천순과 선택 설명 문구는 노출하지 않는다.

### 하단 행동

- 버튼: `＋ 식재료 추가`
- 클릭 시 ING-02로 이동한다.

최신 근거: PRT-035, PRT-036, PRT-103

## ING-02 · 식재료 추가

- `구매처 *`: `식자재쇼핑몰 · 고춧가루 1kg`

### 목록

기간 선택창:

- `최근 1개월 · 최근 3개월 · 최근 6개월 · 전체`

유형 선택창:

- 제목: `유형`
- `전체 · 입고 · 판매 소진 · 차감 · 폐기`
- 폐기 하위 구분 필터는 별도로 두지 않는다.

정렬 선택창:

- 제목: `정렬 기준`
- `최신순 · 오래된순`

### 전체 요약

- `현재 재고 812g`
- `입고 +4kg`
- `판매 소진 −3.2kg`
- `차감 −700g`
- `폐기 −200g`

특정 유형만 선택하면 전체 요약은 숨기고 해당 목록에 집중한다. 폐기 유형에서는 폐기 합계를 사용한다.

### 목록

- 월 헤더: `2026년 8월 / 총 9건`
- 입고 예시: `08/30 / 입고 / 식자재쇼핑몰 · 1kg × 1개 / +1kg / 잔량 1.8kg`
- 차감 예시: `08/30 / 차감 / 재고 정리 / −700g / 잔량 1.1kg`
- 폐기 예시: `08/29 / 폐기 · 조리 전 / 유통기한 경과 / −120g / 3,360원 · 잔량 980g`
- 판매 소진 예시: `08/29 / 판매 소진 / 순두부찌개 10개 / −80g / 잔량 812g`

### 빠른 철회

- 입고·차감·폐기만 대상이다.
- 최근 7일 안의 같은 유형 최신 1건에만 `⋮`를 표시한다.
- 판매 소진은 빠른 철회 대상이 아니다.
- 같은 유형의 이후 기록이 있으면 이전 기록에는 철회를 노출하지 않는다.

기록 상세 시트 예시:

- 제목: `입고내역`
- 회색 요약 박스 1줄: `08/30   식자재쇼핑몰`
- 회색 요약 박스 2줄: `입고 1kg (1kg × 1개)`
- 버튼: `닫기 / 입고 철회`

철회 확인:

- 제목: `입고 철회`
- 본문: `1kg 입고 기록을 철회할까요? 재고와 기준 단가가 다시 계산돼요.`
- 버튼: `취소 / 철회`

최신 근거: PRT-080~082, PRT-089, PRT-092~102

# 4. 레시피 현재 확정안

## RCP-01 · 레시피 메인

### 헤더와 카테고리

- 화면 제목: `레시피`
- 우측 행동: 검색, 알림

- 기본 정렬 칩: `순이익률 낮은순`

- 목표 전체 상태 칩: `목표 상태`

- `최신순 · 순이익률 낮은순 · 순이익률 높은순 · 판매량 많은순 · 판매가 높은순 · 판매가 낮은순`

- 제목: `목표`
- `전체 · 목표 미달 · 목표 달성`
- 전체가 선택되면 칩은 `목표 상태`로 표시한다.

### 레시피 카드

표시 순서:

1. 목표 상태 뱃지
2. 메뉴명
3. 카테고리
4. `판매가`와 금액
5. `순이익 목표 {비율}`과 실제 순이익률·금액
6. `재료비`와 비율·금액

현재 예시에는 공기밥, 김치찌개, 소불고기, 순두부찌개, 제육볶음, 된장찌개, 계란말이를 표시한다.

### 하단 행동

- 버튼: `＋ 레시피 추가`
- 클릭 시 RCP-03으로 이동한다.

최신 근거: PRT-103, PRT-104, PRT-136

## RCP-02 · 레시피 상세

### 헤더와 상태

- 화면 헤더 제목: `레시피`
- 우측 행동: `✎ 수정`
- 목표 상태 `목표 미달`을 메뉴명 위에 표시한다.
- 메뉴명: `제육볶음`
- 메뉴명 우측 판매 상태 버튼: `판매중⌄`
- 판매중 버튼은 파란색 채움, 흰색 글자, 테두리 없음이다.
- 판매중지 상태는 회색 테두리와 `판매중지⌃`를 사용한다.

### 판매 상태 변경

- 상태 버튼을 누르면 선택 목록이 아니라 중앙 확인창을 연다.
- 판매중에서 누르면 제목: `판매를 중지하시겠습니까?`
- 판매중지에서 누르면 제목: `판매중으로 상태를 변경하시겠습니까?`
- 버튼: `아니오 / 예`

### 메모와 최근 수정

- 메모 행: `▣ 메모  메모 없음`
- 메모 행 클릭 시 `메모 수정` 바텀시트를 연다.
- 메모 수정 시트: 다중 행 입력, `0 / 100`, `취소 / 완료`
- 최근 7일 수정 기록이 있을 때만 최근 수정 영역을 표시한다.
- 현재 예시: `◴ 최근 수정 15:21 / 매출 계산과 무관 / ›`

### 기본 요약

- `판매가 12,000원`
- `기준 인분 10인분`
- `최근 30일 판매 438개 · 폐기 6`
- `목표 순이익률 40%`
- 사용자가 직접 입력하는 월 평균 판매량은 사용하지 않는다.

### 판매가 구성

- 중앙 지표: `순이익률 33.7%`
- `재료 2,806원 / 23.3%`
- `부자재 300원 / 2.5%`
- `고정 지출 3,756원 / 31.3%`
- `세금 1,091원 / 9.0%`
- `순이익 4,047원 / 33.7%`
- 소계: `12,000원 / 100%`

### 재료

- 탭: `10인분 · 1인분`, 기본 선택 `1인분`
- 각 행: 재료명, 기준 단가·재고, 원가, 사용량·판매가 대비 비율

# 5. 4회 교차 검수 결과

이번 판본은 같은 화면을 네 가지 관점으로 다시 확인했다.

1. 화면 원문 검수 — 기본 화면과 URL 상태의 실제 렌더 텍스트·순서·버튼을 대조했다.
2. 식재료 독립 검수 — 식재료 12개 화면과 29개 팝업·상태를 별도로 확인했다.
3. 레시피 독립 검수 — 핵심 4개 화면, 핵심 팝업 7개, 직접 연결 보조 화면 6개와 보조 팝업 2개를 확인했다.
4. 변경 충돌 검수 — PRT-001~136 중 서로 대체된 결정과 휴면 화면·후처리 치환을 확인했다.

검수 결과는 아래처럼 구분한다.

- 본문: 현재 확정된 화면 구조와 문구
- 추가 확인 필요: 기획값끼리 충돌해 사용자의 선택이 필요한 항목
- 구현 점검: 확정안은 정해졌지만 현재 프로토타입 상호작용이 아직 따라오지 못한 항목
- 실제 Expo 앱: 이번 작업에서는 읽기 전용이며 수정하지 않음

## 5.1 추가 확인이 필요한 기획 항목

1. 식재료 상세의 최근 입고 예시 3건은 모두 `최고`로 표시되지만, 구매 이력은 동일 최저·최고일 때 최신 대표 행 한 건에만 두 뱃지를 표시한다. 상세 미리보기에도 같은 대표 규칙을 적용할지 확인이 필요하다.
2. 레시피 상세 세금 비율은 `9.0%`, 판매가 시뮬레이션의 12,000원 초기값은 동적 계산 후 `9.1%`로 표시된다. 반올림 자릿수 계약을 하나로 통일해야 한다.
3. 권장 판매가 `15,800원`은 화면에서 `40%`로 보이지만 내부 계산값은 약 `39.96%`라 목표에 미달한다. 목표 이상이 되는 최소 단위 올림 규칙이 필요하다.
4. 레시피 상세의 `최근 30일 판매`는 `438개 · 폐기 6`, 판매 손익의 판매량은 `1인분`을 사용한다. 요약 단위를 `개`로 유지할지 `인분`으로 통일할지 확인이 필요하다.
5. 상세 상단은 `기준 인분 10인분`인데 상세 원가 카드의 기본 선택은 모두 `1인분`이다. 기본 선택 기준을 하나로 통일해야 한다.
6. 프로젝트 표시 규칙은 구매 옵션을 `식재료명 · 용량 · 금액 / 구매처 · 단가` 순서로 정의하지만 현재 구매 링크 목록은 `구매처 / 금액 / 용량 / 단가` 순서다. 이번 프로토타입 결정을 공식 규칙에 반영할지 확인이 필요하다.
7. 요청에서 언급한 `24페이지`와 프로토타입의 집계 방식이 다르다. 이 문서는 누락 방지를 위해 기본 화면과 URL 팝업·상태를 분리해 52개 계약 단위로 관리한다.
8. 레시피 상세의 표시 행을 정수로 더하면 `12 + 100 + 2,600 + 95 = 2,807원`이지만 재료비 소계는 `2,806원`이다. 내부 소수 사용량·원가를 합산한 뒤 반올림한 값인지, 표시 행 반올림값의 합을 사용할지 반올림 계약을 명시해야 한다.

## 5.2 현재 프로토타입 구현 점검 항목

아래는 확정안 자체가 아니라 현재 HTML에서 확인된 미구현·불일치다. 실제 Expo 앱 수정 전에 프로토타입에서 먼저 보완한다.

### 식재료

1. 메인에 `향신료·허브` 카테고리 탭이 없어 해당 카테고리의 고춧가루를 탭으로 찾을 수 없다.
2. 메인 카테고리와 정렬은 선택 표시만 바뀌며 카드 필터·정렬은 실제 적용되지 않는다.
3. 추가 화면은 필수값이 비어 있어도 `추가` 버튼이 활성화된다.
4. 추가 화면의 단위를 `g`로 바꾸면 안전재고 단위는 바뀌지만 구매 단가는 `0원/kg`로 남는다.
5. 식재료 카드 다섯 개가 모두 고춧가루 상세 예시로 연결된다.
6. 수정 메뉴 화면 헤더의 `✎ 수정`이 자기 화면을 다시 연다.
7. 재고 내역의 요약 `현재 재고 812g`과 최신 입고 행의 잔량 `1.8kg`이 일치하지 않는다.
8. 재고 요약의 입고 `+4kg`과 현재 표시된 입고 행 두 건의 합계 `+2kg`이 일치하지 않는다.
9. 재고를 `오래된순`으로 바꾸면 렌더 순서를 기준으로 철회 메뉴를 붙여 유형별 최신 기록이 아닌 오래된 기록에 철회가 노출될 수 있다.
10. 폐기 입력에는 `조리 전 / 조리 후` 구분 선택이 없지만 내역과 합계는 두 유형을 구분한다.
11. 직접 입고의 구매처는 동작상 필수지만 라벨에 `*`가 없다.
12. 구매 링크 추가·수정의 링크 이름·용량·금액이 정적 표시라 실제로 편집할 수 없고, 저장 가능 여부도 모든 필수값을 검사하지 않는다.
13. 구매 링크 수정의 단위 선택창은 현재 단위 `kg`에 체크를 표시하지 않는다.
14. 기간 필터는 표시값만 바뀌고 재고·구매 이력 행 범위는 바뀌지 않는다.
15. 수정 내역의 서로 다른 두 사건이 같은 전후 비교 내용을 재사용한다.
16. 메모 글자 수가 입력에 따라 갱신되지 않고 완료 동작도 연결되지 않는다.
17. 식재료 삭제, 구매 링크 저장, 재고 차감, 폐기 기록 등 일부 최종 행동은 다음 상태가 연결되지 않았다.

### 레시피

1. 상세 헤더 `✎ 수정`은 보이지만 `recipe_edit`로 이동하지 않는다.
2. 메인의 검색·알림은 동작하지 않는다.
3. 메인 카테고리·정렬·판매 상태·목표 필터는 표시만 바뀌고 카드 목록에 적용되지 않는다.
4. 상세와 시뮬레이션의 `10인분 / 1인분` 탭은 선택 표시와 일부 문구만 바꾸며 사용량·금액을 환산하지 않는다.
5. 판매가 시뮬레이션은 순이익률이 목표를 넘어도 `목표 미달` 뱃지가 바뀌지 않는다.
6. 레시피 추가의 메뉴명·판매가·기준 인분·목표 순이익률은 입력 요소가 아닌 고정 표시이고, 최종 버튼은 항상 비활성이다.
7. 레시피 카테고리를 골라도 원 화면 값이 바뀌거나 선택창이 닫히지 않는다.
8. 목표 순이익률 안내 시트 안에 닫기 행동이 없다.
9. 메모 `완료`와 권장 판매가 `적용하기`는 아직 저장 결과 상태까지 연결되지 않는다.
12. 상세 재료 행에는 화살표가 있지만 이동 동작이 없다.
13. 휴면 상태의 옛 판매가 시뮬레이션 팝업 정의가 남아 있으나 사용자 경로에서는 별도 페이지로만 이동한다.
14. 레시피 상세의 돼지고기 앞다리는 기본 `1인분` 탭에서 `200g · 2,600원`인데, 재료 추가 사용량 시트는 `10인분 전체 200g → 1인분 20g · 260원`으로 표시한다. 화면별 기준 인분 계약을 공식 계산 문서에서 하나로 정리해야 한다.
15. `목표 순이익률 안내` 팝업 상태는 존재하지만 레시피 추가 화면의 목표 순이익률 라벨이나 입력 영역에서 여는 진입점이 없다.
16. 사용자에게는 최신 레시피 메인 렌더가 노출되지만, 코드 안에는 카드 수와 필터 문구가 다른 옛 레시피 메인 렌더 분기가 휴면 상태로 남아 있다.

## 5.3 Opus 독립 검수 기록

- 검수 모델: `claude-opus-5`
- 실행 방식: 새 세션·읽기 전용·제품 파일 쓰기 금지
- 성공 검수 1: 식재료 화면·팝업과 현재 확정안 대조
- 성공 검수 2: 레시피 핵심 4개 화면·직접 연결 팝업·최신 변경 기록 대조
- 1차 지적은 실제 최종 렌더와 다시 대조했다. 휴면 렌더나 후처리 이전 코드만 근거로 한 항목은 확정안에 반영하지 않았다.
- 2차에서 확인된 유효 항목은 `소계` 문구 정정, 재료 사용량 10배 불일치, 표시 행 합계 반올림 계약, 목표 순이익률 안내 진입 누락, 휴면 레시피 메인 분기다.
- 레시피 추가 판매 손익에 세금·부자재 행을 넣자는 제안은 현재 사용자 확정안과 다르므로 반영하지 않았다.
- 실제 Expo 앱과 앱 소스는 두 회차 모두 수정하지 않았다.
