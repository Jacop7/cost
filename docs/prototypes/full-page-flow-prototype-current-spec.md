- 최근 갱신일: 2026-09-04
- 현재 디자인 동기화 ID: `DS-20260904-006`

- 변경 과정과 원복 이력은 `full-page-flow-prototype-changelog.md`에 계속 누적한다.

UI 가이드는 전체 화면을 공통화하기 위한 적용 목표안이다. 일괄 적용과 전수 재검수가 끝나기 전까지
현재 실제 렌더 판정은 이 문서를 우선한다.

UI 가이드의 현재 판본은 세분화된 항목을 `문서 계약 · 기초 토큰 · 앱 셸 · 조작 컴포넌트 ·
콘텐츠 표시 · 팝업 · 상태/업무 흐름 · 문구/국제화 · 접근성 · 검수/적용` 10개 장과 3개 부록으로
병합한 개정안이다. Expo의 `tokens.ts`와 공용 kit을 코드 권위로 두며 등록 화면 62개, 팝업·조건 상태
호스트 123개와 고유 ID 98개의 매핑을 보존한다(활성은 화면 61 / 호스트 121 / 고유 ID 96). 이 판본 역시 실제 Expo와 프로토타입 HTML에
아직 일괄 적용한 상태는 아니다.

현재 UI 가이드는 `shell-excluded / layout / section / card / card-part / row-group / field / result /
notice / kpi / empty / badge / control / chart / layer / sticky-action`을 정규 감사 역할로 사용한다.
시연용 카탈로그·stage·backdrop·underlay만 제품 검수에서 제외하며, 그 안에 표시된 실제 제품
Sheet·Dialog·Card·Control은 계속 검수한다. 팝업은 ID마다 `host / layerType / dismissPolicy /
footerPolicy / renderer`를 명시하고, 페이지 고정 행동·Layer 고정 행동·일반 Card Footer의 소유권과
Safe Area 계산을 분리한다. 부록 C.3의 고위험 selector·renderer 매핑은 전수 매핑의 출발점이며,
전체 매핑과 화면별 적용 검수 전에는 적용 완료로 판정하지 않는다.

서비스 기준은 `캐시노트·오늘얼마 = 정보 구조·디자인 로직·업무 프로세스`, `토스 = 시각 디자인
톤`으로 분리한다. 디자인 로직은 무엇을 먼저 보여주고 상세·기록·수정·철회로 어떻게 이어지는지를
뜻한다. 따라서 각 탭 메인은 사장님의 첫 질문과 확인할 이상 항목, 다음 행동을 우선하지만
토스 금융앱의 정보 구조나 기준 서비스의 POS 자동 연동·실시간 문법은 복제하지 않는다. 현재 제품은
수기 기록형이므로 집계·요약·손익에서 `마지막 기록 시각 · 미입력 · 작성 중/마감 완료`를 신뢰
정보로 사용한다. 이 규칙은 UI 가이드 목표안이며 현재 HTML 화면 반영 완료를 뜻하지 않는다.

현재 반영 범위:

- 식재료 기본 화면 12개 전체
- 레시피 기본 화면 4개: 메인, 상세, 판매가 시뮬레이션, 레시피 추가
- 위 화면에서 직접 진입하는 선택창·확인창·상태 화면 전체

개수는 기본 화면과 팝업을 분리해 관리한다. 같은 렌더 결과를 재사용하는 상태도 URL·진입 계약이 다르면 검수 단위에는 포함한다.

| 구분 | 기본 화면 | 직접 연결된 팝업·상태 | 계약 검수 단위 | 서로 다른 렌더 결과 |
|---|---:|---:|---:|---:|
| 식재료 | 12 | 29 | 41 | 38 |
| 레시피 현재 확정 범위 | 4 | 7 | 11 | 11 |
| 합계 | 16 | 36 | 52 | 49 |

레시피 핵심 4개 화면에서 이어지는 보조 화면 6개와 보조 팝업 2개도 별도로 도달성 검수했다. 이 8개는 이번 확정안의 핵심 화면 수에는 합산하지 않고, 연결 흐름과 구현 점검 항목에 기록한다.

`폐기 내역` 독립 화면은 삭제하지 않고 숨김 보존한다. 화면 목록에서는 제외하며 `재고 내역`의 폐기 유형으로 연결한다.

## 2. 공통 확정 규칙

### 2.1 내비게이션과 헤더

- 하단 탭은 `식재료 · 레시피 · 발주 · 매출관리 · MY` 5개다.
- 메인 화면 헤더 우측에는 검색과 알림 아이콘을 둔다. 알림 아이콘은 새 알림 점을 가질 수 있다.
- 상세 화면은 좌측 뒤로가기와 화면 제목을 사용한다.
- 식재료 상세 우측에는 `✎ 수정`, 레시피 상세 우측에는 `✎ 수정`을 둔다.
- 헤더 우측에 재고량, 입고 건수 같은 요약 숫자를 중복 노출하지 않는다.

### 2.2 카드와 목록

- 카드 모서리는 공통 `radius.lg`를 사용하고 카드 사이는 `space.md`를 기본으로 한다.
- 섹션 헤더는 좌측 제목을 우선하며 우측의 중복 숫자·설명은 최소화한다.
- 상세 미리보기 목록은 최대 3개까지 노출하고 하단 행동은 `전체보기 ›`로 통일한다.
- 값 목록은 좌측에 이름·보조 정보, 우측에 핵심 값·단가를 둔다.
- 빈 상태는 한 문장으로 표시하고, 가능한 다음 행동이 있으면 빈 상태 바로 아래에 버튼을 둔다.
- 목록 행은 3줄 기록형 `92px / 상하 16px`, 2줄 관리형 `76px / 14px`, 1줄 단순형
  `60px / 12px` 세 종류로만 사용한다.
- 연속 목록의 내부 구분선은 `1px / --line2` 한 줄만 사용하고 마지막 행은 제거한다.
- 유형명·행 제목은 검정, 날짜·설명은 회색, 변화량·상태만 의미색을 사용한다.

### 2.3 입력과 계산 결과

- 입력 라벨은 입력칸 위에 둔다. 입력칸 안에는 값 또는 플레이스홀더만 둔다.
- 필수값은 라벨 우측의 파란색 `*`로 표시한다.
- 입력칸 아래의 중복 설명은 노출하지 않는다.
- 합계, 변경 후 재고, 예상 손실, 구매 단가 같은 읽기 전용 결과는 라벨과 값이 분리된 결과 카드로 표시한다.
- 숫자·수량·금액·비율은 우측 정렬하고 단위는 값 바로 뒤에 한 묶음으로 배치한다.
- 읽기 전용 결과 카드는 전체 너비·높이 `50px`, 좌우 `14px`, 우측 정렬된 `16px / 800` 값을
  사용한다. 라벨은 결과 카드 밖에 둔다.
- 결과 카드는 중립 표면을 기본으로 하고 사용자가 방금 바꾼 대표 계산 결과 그룹 한 곳만 옅은 파란
  배경과 테두리를 사용할 수 있다.
- 읽어야 하는 안내는 좌측 `20px` 정보 아이콘, 최소 높이 `48px`, 아이콘과 본문 사이 `10px`를
  사용하는 Notice로 표시한다. 중복 설명은 Notice로 만들지 않고 삭제한다.
- 저장·추가 버튼은 화면 하단에 고정하고, 필수값이 준비되지 않으면 비활성화한다.

### 2.4 팝업

- 선택·입력은 하단 바텀시트로 연다.
- 단일 선택창은 제목 다음에 선택지를 바로 배치하며 제목을 반복하는 작은 소제목을 넣지 않는다.
- 현재 선택값 우측에는 `✓`를 표시한다.
- 삭제, 철회, 판매 상태 변경처럼 순수 확인만 필요한 창은 화면 가운데 알럿으로 연다.
- 확인 알럿의 행동은 `1:1` 하단 2열 버튼을 사용한다. 취소·닫기는 연한 회색, 완료·확인은 파란색,
  삭제·철회는 연한 빨강을 사용한다.
- 두 행동은 320px에서도 `1:1` 2열을 유지한다. 긴 번역은 글자를 줄이지 않고 버튼 내부 줄바꿈과
  높이 확장으로 처리한다.
- 확인 대상의 이름·수량·금액은 말줄임하지 않고 중립 요약 영역의 `라벨 + 값`으로 분리한다.
- 메시지 팝업 제목은 간단한 명사형으로 작성한다. 예: `입고 실패`.

### 2.5 최근 수정과 이력

- 상세의 최근 수정 영역은 최근 7일 안에 표시할 기록이 있을 때만 노출한다.
- 기록이 없으면 영역 전체를 숨긴다.
- 수정 내역은 최근 7일만 표시하고 재고 수량 변동과 메모 변경은 포함하지 않는다.
- 재고·구매 이력 필터는 각각 독립된 필터 칩으로 표시하고, 누른 필터에 맞는 단일 선택창을 연다.
- 날짜·시간은 실제 제품에서 locale formatter와 매장 시간대를 사용한다. 프로토타입 fallback은
  `YYYY-MM-DD · HH:mm`이며 `MM/DD · HH:mm`은 사용하지 않는다.
- 수정 상세의 변경 전 값이 없으면 `—` 대신 `없음`을 사용하고 비교 항목을 각각 중립 경계의 독립
  비교 블록으로 표시한다.

### 2.7 글꼴과 글자 위계

기본 글꼴 순서:

`Pretendard → -apple-system → BlinkMacSystemFont → Segoe UI → sans-serif`

프로토타입이 불러오는 Pretendard 파일은 `Regular 400`, `SemiBold 600`, `Bold 700`, `ExtraBold 800` 네 가지다. CSS의 `750`, `850`, `900`은 별도 폰트 파일이 아니라 브라우저가 가까운 굵기로 처리하는 값이므로 실제 Expo 구현에서는 다음처럼 정규화한다.

| 역할 | 크기·행간 | 굵기 | 자간·색상 |
|---|---|---:|---|
| 메인 화면 제목 | `22px / 30px` | `800` | `-0.6px`, `--ink` |
| 하위 화면 제목 | `18px / 26px` | `700` | `-0.3px`, `--ink` |
| 상세 대표 이름 | `20px` | `800` | `--ink` |
| 팝업 제목 | `19px`, 확인창 `1.4` 행간 | `700~800` | `--ink` |
| 카드·목록 제목 | `16px` | `700~800` | `--ink` |
| 핵심 숫자 | `18~23px` | `800` | 탭 숫자 사용 |
| 일반 값·버튼 | `15~16px` | `700` | `--ink` 또는 흰색 |
| 필드 라벨 | `14px` | `800` | `--sub` |
| 일반 본문 | `14px / 1.45~1.5` | `600~700` | `--sub` |
| 보조 정보 | `13px / 1.35` | `600~700` | `--ter` |
| 뱃지·캡션 | `12px` | `700` | 상태색 또는 `--ter` |

공통 규칙:

- 금액·수량은 `font-variant-numeric: tabular-nums`를 적용해 자릿수 폭을 맞춘다.
- 핵심 값보다 설명 문구의 굵기와 명도를 낮춘다.
- 화면에 요청된 `750`, `850`, `900`은 Expo 토큰에서 각각 `700`, `800`, `800`으로 정리한다.
- 작은 설명글은 최소 `12px`이며 동작이나 상태 이해에 필요하지 않으면 표시하지 않는다.

### 2.8 화면 골격과 여백

제품 화면 기준 골격:

### 2.15 숫자·단위 표기 규격

숫자와 단위의 크기·굵기는 화면별로 정하지 않고 아래 역할 토큰만 사용한다. 최신 근거: PRT-179

| 역할 | 크기·굵기 | 색 | 정렬 | 숫자 폭 |
|---|---|---|---|---|
| 큰 핵심값(히어로·재고 총량) | `TYPE.display` 22 / 800 | `--ink` | 화면 규칙 | tabular |
| 화면·시트 제목의 수치 | `TYPE.header` 18 / 700 | `--ink` | 화면 규칙 | tabular |
| 행 주값(금액·수량·단가) | `TYPE.body` 16 / 700 | `--ink` | 우측 끝선 | tabular |
| 계산 결과 값 | 16 / 800 | 결과 카드 규칙 | 우측 끝선 | tabular |
| 입력 필드 값 | 16 / 700 | `--ink` | 우측 끝선 | **적용 안 함** |
| 입력 필드 suffix | `TYPE.caption` 14 / 600 | `--sub` | 값 뒤 8px | – |
| 행 보조 수치 | `TYPE.captionSm` 13 / 600 | `--ter` | 값과 같은 열 | tabular |

- 굵기는 `400 / 600 / 700 / 800`만 쓴다. `650 · 750 · 850 · 900`은 사용하지 않는다.
- 기존 굵기를 정규화할 때는 숫자상 가까운 값이 아니라 **선언된 `@font-face`가 실제로 선택하던
  face**로 매핑한다. 이 프로토타입 기준: `300·400·500 → 400`, `600 → 600`, `650·700 → 700`,
  `750·800·850·900 → 800`. 근사값으로 내리면 실제 굵기가 바뀐다.
- `b·strong`의 브라우저 기본 굵기(`bolder`)를 전역 규칙으로 덮지 않는다. 중첩된 강조가 무너진다.
  그 결과 굵은 부모 아래의 `b·strong`은 computed `900`이 되지만 렌더 face는 `800`과 같다.
  굵기 검사는 **선언값**과 **computed 값**을 구분해 표기한다.
- 굵기·크기 일괄 변환은 `@font-face` 같은 **at-rule을 반드시 제외**한다. at-rule은 선택자가 아니며,
  디스크립터를 정규화하면 face 선택 자체가 깨진다.
- 검사 범위는 `<style>` 블록이 아니라 **렌더된 요소의 computed 값과 스크립트 템플릿의 인라인 style**
  전체다.
- 프로토타입이 참조하는 자산(폰트 등)은 **상대경로**로 적는다. 루트 절대경로는 `file://`에서
  드라이브 루트로 해석되어 로드되지 않는다. 검수 증거는 실제 사용 프로토콜에서 취득한다.
- 표시용 숫자는 단위를 붙여 쓴다(`12원`, `200g`, `33.7%`, `10인분`). 띄어 쓰는 것은
  입력 필드의 suffix 하나뿐이며 간격은 `8px`로 고정한다.
- 값 역할에는 `font-variant-numeric: tabular-nums`를 적용해 목록에서 자릿수가 흔들리지 않게 한다.
- 크기를 지정하지 않은 `<small>`이 브라우저 기본 `0.83em`으로 줄어들지 않도록, `b,strong`과
  `small,em`에 낮은 특이도 기본 규칙을 둔다. 다만 **크기 규칙이 없는 요소는 이 기본값을 그대로
  받는다.** 부모 크기를 따라야 하는 요소(필수 표시 `*`, 곱셈 기호 `×26`)에는 역할 선택자에
  `font-size: inherit; font-weight: inherit`을 명시한다.
- 단일 편집 입력에는 `tabular-nums`를 적용하지 않는다. UI 가이드 `1.3`이 폰트 렌더 검증 전까지
  제외하도록 규정하고, 실제 Expo `components/kit`도 같은 이유로 적용하지 않는다.
- 숫자는 `b·strong·small·em`에만 담기지 않는다. 탭·칩·버튼·선택 표시처럼 클래스로만 스타일된
  요소도 숫자를 담으므로, 검사는 태그가 아니라 **렌더된 text node와 입력값 전체**를 대상으로 한다.
- 프로토타입 셸(폰 목업 상태바 시각, 카탈로그 화면 ID 배지)은 제품 UI가 아니므로 이 규격의
  적용 대상이 아니다.
- 이 규격은 크기·굵기·정렬만 정한다. 색과 결과 카드의 파란 배경은 기존 규칙을 그대로 따른다.

### 2.14 PC·모바일 표시 규칙과 현재 한계

PC:

- 회색 작업 배경 위에 최대 `680px`의 프로토타입 카탈로그와 최대 `602px`의 제품 화면을 가운데 배치한다.
- 제품 화면은 모바일 앱과 같은 한 열 구조를 유지하며 PC용 다단 레이아웃으로 늘리지 않는다.

모바일:

- 제품 화면은 가용 폭 `100%`를 사용하되 현재 프로토타입의 작업 영역 좌우 `12px`는 유지된다.
- `520px` 이하에서는 카탈로그 제목만 숨기며 화면 선택 탭은 남는다.
- 제품 카드·입력·팝업의 글자 크기와 내부 여백은 PC와 동일하다.
- 현재 CSS에는 모바일 전용 카드 재배치나 2열 입력의 1열 전환 규칙이 없다.

현재 한계:

- 주소가 PC용인지 모바일용인지에 따라 디자인이 달라지는 것이 아니라 실제 브라우저 폭에 따라 같은 구조가 줄어든다.
- `520px` 반응형 규칙보다 뒤에 공통 규칙이 다시 선언되어 일부 모바일 값이 덮어써진다. 구현 전 최종 반응형 규칙을 CSS 맨 뒤에서 다시 정리해야 한다.
- `--line3`, `--sub2`는 정의 없이 일부 선택자에서 사용된다. `--line3`는 `#d1d6db` fallback이 있지만 `--sub2`는 fallback이 없어 공용 토큰으로 정리해야 한다.
- `34×34px` 아이콘 버튼과 일부 작은 행동은 실제 앱 접근성 터치 영역 검수가 필요하다.

### 2.16 프로토타입 URL 계약

프로토타입의 진입 상태는 **쿼리스트링만으로** 표현한다. 최신 근거: PRT-184

| 파라미터 | 값 | 의미 |
|---|---|---|
| `screen` | `screens` 레지스트리의 키 | 열 화면 |
| `popup` | `popupTabs[screen]`의 팝업·조건 상태 ID | 그 화면 위에 열 Layer 또는 PageState |
| `terms` | `1` | 용어 사전 화면 |

- **해시(`#…`)는 라우팅 계약이 아니다.** 프로토타입은 로드 시 `history.replaceState`로 주소를
  `?screen=…` 형태로 다시 쓰며 이 과정에서 해시를 버린다. 따라서 해시로 상태를 전달하는 링크는
  동작하지 않는다. 해시 기반 진입이 필요해지면 앱의 `replaceState` 정책을 먼저 바꾼 뒤에
  계약으로 승격한다. 그 전까지 문서·스텁·외부 링크는 해시를 쓰지 않는다.
- 구 파일명 `full-page-flow-prototype-ui-applied.html`은 정본 `0_…`로 보내는 리다이렉트 스텁이며,
  `location.search`만 그대로 전달한다. 쿼리를 버리는 `<meta refresh>`는 쓰지 않는다.
- 위 세 가지 외의 파라미터는 정의되어 있지 않다. 앱은 알 수 없는 파라미터를 무시한다.

# 3. 식재료 현재 확정안

## ING-01 · 식재료 메인

### 헤더와 상단 탐색

- 화면 제목: `식재료`
- 우측 행동: 검색, 알림
- 카테고리 탭: `전체 · 축산·계란 · 수산·해조류 · 농산(신선) · 곡물·견과·분말 · 유제품 · 냉동식품`
- 목록 정렬 칩 기본값: `재고 적은 순⌄`

### 식재료 카드

각 카드는 다음 순서로 표시한다.

1. 재고 상태 뱃지: `여유`, `소진 임박`, `소진`
2. 식재료명
3. 카테고리
4. `총 {재고량}`
5. 안전재고가 필요한 경우 `안전재고 {수량}`
6. 기준 단가
7. `최근입고 {MM/DD}`

현재 예시:

- 설탕: `소진 임박 / 곡물·견과·분말 / 총 3kg / 안전재고 3kg / 1.80원/g / 최근입고 2026-08-08`
- 고춧가루: `소진 임박 / 향신료·허브 / 총 812g / 안전재고 1kg / 28.00원/g / 최근입고 2026-08-27`
- 쌀: `여유 / 곡물·견과·분말 / 총 13kg / 3.20원/g / 최근입고 2026-08-27`
- 계란: `여유 / 축산·계란 / 총 123개 / 300.00원/개 / 최근입고 2026-08-29`
- 대파: `여유 / 농산(신선) / 총 4.1kg / 4.00원/g / 최근입고 2026-08-29`

상태 판정:

- 재고가 0 이하이면 `소진`이며 음수 재고를 그대로 표시한다.
- 재고가 양수이면서 안전재고 이하이거나 소진 임박 판정이면 `소진 임박`이다.
- 그 외는 `여유`다.
- 안전재고 관련 뱃지는 `안전재고` 명칭을 사용하며 노란색 계열로 표시한다.

### 정렬 선택창

- 제목: `정렬 기준`
- 선택지: `최신순 · 재고 적은 순 · 단가 높은 순 · 이름순`
- `최신순`은 최신 등록순이다.
- 추천순과 선택 설명 문구는 노출하지 않는다.

### 하단 행동

- 버튼: `＋ 식재료 추가`
- 클릭 시 ING-02로 이동한다.

최신 근거: PRT-035, PRT-036, PRT-103

## ING-02 · 식재료 추가

### 기본 정보 입력 순서

### 하단 행동

- 저장된 구매처를 선택하면 기존 링크의 경로를 제거한 도메인 원본만 구매 링크 입력칸에 채운다.
- 자동으로 채워진 도메인은 사용자가 수정할 수 있다.
- 구매처가 없으면 라벨 우측 `＋ 새 구매처`를 누르고 같은 자리에서 이름을 입력한다.

### 구매처 선택창

- 제목: `구매처 선택`

- `마장축산 / 발주 17건`

- `식자재쇼핑몰 / 발주 40건`
- 현재 선택값에 `✓`

### 단위 선택창

- ING-02 단위 선택창과 같은 6개 단위를 사용한다.

### 더보기와 삭제

- 수정 화면 헤더 우측 `•••`를 누르면 우측 하단 컨텍스트 메뉴를 연다.
- 메뉴: `구매 링크 삭제 / 닫기`
- 삭제 확인은 중앙 알럿이다.
- 제목: `구매 링크 삭제`
- 본문: `이 구매 링크를 삭제할까요? 삭제한 링크는 복구할 수 없어요.`

## RCP-02 · 레시피 상세

### 헤더와 상태

- 화면 헤더 제목: `레시피`
- 우측 행동: `✎ 수정`
- 목표 상태 `목표 미달`을 메뉴명 위에 표시한다.

- 판매중지에서 누르면 제목: `판매중으로 상태를 변경하시겠습니까?`
- 버튼: `아니오 / 예`

### 메모와 최근 수정

- 메모 행: `▣ 메모  메모 없음`
- 메모 행 클릭 시 `메모 수정` 바텀시트를 연다.
- 메모 수정 시트: 다중 행 입력, `0 / 100`, `취소 / 완료`
- 최근 7일 수정 기록이 있을 때만 최근 수정 영역을 표시한다.
- 현재 예시: `◴ 최근 수정 15:21 / 매출 계산과 무관 / ›`

### 기본 요약

## RCP-02c · 판매가 시뮬레이션

- 별도 페이지로 연다.
- 화면 제목: `판매가 시뮬레이션`
- 카드 제목: `판매 손익`
- 탭: `10인분 · 1인분`, 기본 선택 `1인분`
- 판매가만 입력할 수 있고 나머지는 즉시 계산되는 읽기 전용 값이다.
- 판매가 입력칸은 공통 폼 입력 스타일을 사용한다.
- 판매가 행은 최소 `76px`, 상하 `14px`를 사용한다. 입력칸은 높이 `50px`, 모바일 최소 `180px`,
  넓은 시연 화면 최대 `240px`를 확보한다.
- 판매가 행 우측 `100%`는 표시하지 않는다.

현재 행 순서:

1. `판매가 / 12,000원 입력`
2. `판매량 / 1인분`
3. `(−) 세금 / 1,091원 / 9.1%`
4. `(−) 재료 원가 / 2,806원 / 23.4%`
5. `(−) 고정 지출 / 3,756원 / 31.3%`
6. `(−) 부자재 / 300원 / 2.5%`
7. `순이익 / 목표 미달 / 4,047원 / 33.7%`
8. `권장 판매가 / 목표 40% 기준 / 15,800원 / 40%`

# 5. 발주 현재 확정안

## ORD-01 · 발주 메인

### 헤더와 상태 탭

- 헤더는 `발주`, 검색, 알림으로 구성한다.
- 상태 탭은 `발주 후보 · 입고 예정 · 입고 완료` 순서이며 건수를 함께 표시한다.
- 기본 화면은 안전재고 미달 후보를 우선 노출하고 `권장 발주 · 현재 재고 · 안전재고`를 한 카드에서
  비교한 뒤 `주문하기`로 연결한다.

### 발주 후보·입고 예정·입고 완료 목록

- 세 상태의 전체 목록은 제목과 건수, 반복 Row만 있는 공통 InfoSheet를 사용한다.
- 후보는 식재료명, 미달 사유·현재 재고, 권장 수량 순서다.
- 입고 예정은 식재료명, 도착 예정·구매처·총량, 발주 수량 순서다.
- 입고 완료는 식재료명, 날짜·구매처·결제 금액×수량, 기준 단가 순서다.
- 절대 날짜의 프로토타입 fallback은 `YYYY-MM-DD`이며 `8/17`처럼 순서가 모호한 축약 표기는 쓰지 않는다.

### 주문하기

- `발주는 기록만 돼요. 재고와 단가는 ‘입고 완료’를 눌렀을 때 바뀌어요.` 안내를 아이콘 Callout으로
  노출한다.
- 등록된 구매 링크가 없는 상태를 본문으로 표시하고, `발주 수량 · 도착까지`를 숫자 Field로 입력한다.
- 수량과 `개`, 기간과 `일 후`는 end에 한 묶음으로 정렬한다.
- 구매 링크가 없으면 `발주 등록`을 비활성화한다.

### 입고 완료

- 식재료명과 발주 수량을 제목 아래 맥락으로 표시한다.
- 실제 입고 수량은 부분 입고가 가능하며 숫자와 `개`를 end에 한 묶음으로 둔다.
- `입고 후 재고 · 입고 후 기준단가`는 읽기 전용 결과 영역으로 구분한다.
- 저장 영향 안내는 정보 아이콘 Callout을 사용하고 하단은 `취소 · 입고 확정` 1:1 행동이다.

### 발주 취소·입고 취소·단가 급등

- 상태를 되돌리는 `발주 취소 · 입고 취소`는 중앙 ConfirmDialog를 사용한다.
- 취소 대상과 결과를 본문에서 확인하고 하단은 중립 취소와 위험 행동을 1:1로 배치한다.
- 단가 급등은 단가가 직전 평균보다 20% 이상 높은 경우 원가 영향 문구와 단일 확인 행동을 제공한다.

최신 근거: PRT-164

## ORD-02 · 발주 상세

### 정보 순서

- 페이지 헤더 `주문하기`를 본문 카드에서 반복하지 않는다.
- 첫 카드에는 `고춧가루 / 권장 1개`를 좌우로 비교하고 발주가 재고·단가를 바꾸지 않는다는 안내를
  정보 아이콘 Callout으로 표시한다.
- 구매 링크는 별도 카드로 구분하며 빈 상태에서는 `등록된 구매 링크가 없어요`와 등록 경로를 표시한다.

### 입력과 저장

- `발주 수량`은 필수이며 숫자와 `개`, `도착 예정`은 숫자와 `일 후`를 공용 FieldControl의 end에
  한 묶음으로 정렬한다.
- 페이지와 `주문하기` FormSheet는 같은 `prototypeField()` 규격을 사용한다.
- 구매 링크가 없는 빈 상태에서는 페이지와 팝업 모두 `발주 등록`을 비활성화한다.
- 하단 행동은 앱 탭 위에 고정하고 본문 마지막 입력과 겹치지 않도록 스크롤 여백을 확보한다.

최신 근거: PRT-165

## ORD-03 · 입고 상세

### 대상과 입력

- 페이지 헤더 `입고 확정`을 본문에서 반복하지 않는다.
- 첫 카드에는 `돼지고기 앞다리 / 발주 2개`를 공용 Row로 표시한다.
- `실제 입고 수량 (부분 입고 가능)`은 필수 숫자 Field이며 값과 `개`를 end에 한 묶음으로 정렬한다.

### 계산 결과와 영향 안내

- `입고 후 재고 · 입고 후 기준단가`는 입력과 같은 너비의 읽기 전용 ResultField로 표시한다.
- 두 결과는 중립 배경·중립선·검정 값을 기본으로 하며 동시에 파란색으로 강조하지 않는다.
- 저장 영향은 정보 아이콘 Callout으로 표시한다.
- 페이지 하단은 단일 `입고 확정`, FormSheet 하단은 `취소 · 입고 확정` 1:1 행동이다.
- 모바일 320px에서도 두 행동을 세로로 쌓지 않고 2열로 유지한다.

최신 근거: PRT-166

## ORD-02 실제 경로 · 직접 발주

### 최초 미선택 상태

- 식재료 선택은 본문 전체 폭의 공용 Select를 사용하고 필수 표시를 둔다.

# 6. 매출관리 현재 확정안

## SALES-01 · 매출관리 메인

### 정보 순서와 이동

- 헤더는 `매출관리`, 영업일, 날짜 행동으로 구성한다.
- 본문은 영업 상태, 오늘 순이익, 기타 매출·지출 추가, 정렬·메뉴 관리, 메뉴별 판매 목록 순서다.
- 영업 상태는 상태 자체가 선택 행동이며, 오늘 순이익 카드는 일 손익으로 이동한다.
- `기타 매출 · 지출 추가 · 정렬 기준 · 메뉴별 판매`의 페이지 버튼은 각각 해당 Sheet로 직접 연결한다.
- 메뉴 관리는 레시피 탭의 메뉴 목록으로 이동하며 문자 기호가 아니라 공용 편집 아이콘을 사용한다.

### 메뉴별 판매 목록

- 한 행은 메뉴명·오늘 기준 판매가/재료비, 판매 수량·금액, 파란 `판매` 행동 순서다.
- 수량·금액 영역과 판매 행동 모두 같은 `오늘의 판매 수량` Sheet로 연결한다.
- 오늘 장부와 현재 원가가 다르면 `다음 영업일부터 적용` 문구를 해당 행 안에 표시한다.
- 판매 버튼의 더하기와 메뉴 관리의 편집은 SVG 아이콘을 사용하고 장식 문자로 대체하지 않는다.

### 영업 상태·정렬·판매 수량

- 영업 상태 Sheet는 `브레이크 타임 · 영업 종료` 두 행동만 보여 주며 현재 선택 체크를 표시하지 않는다.
- 영업 종료 확인은 `오늘 장사를 마칠까요?` 중앙 Dialog와 `취소 · 영업 종료` 1:1 행동을 사용한다.
- 정렬은 `판매량순 · 순이익순 · 이름순`과 설명을 공용 PickerSheet로 제공한다.
- 판매 수량은 `매장 · 배달 · 포장`, 별도 `조리 폐기` Stepper로 입력하고 합계를 즉시 갱신한다.
- 판매 저장 영향은 정보 아이콘 Callout으로 표시한다.

### 재고 부족·기타 매출·지출

- 판매 재고 부족은 막는 오류가 아니라 FormSheet 안내다. 메뉴별 부족 재료 건수를 보여 주고 하단은
  `재고 확인 · 그대로 판매` 1:1 행동으로 구성한다.
- 기타 매출은 기존 내역, 항목명, 판매가·수량, 필수 판매 채널, 추가 매출 결과, Callout 순서다.
  판매 채널 기본값은 `매장`이며 `매장 · 배달 · 포장` 3분할 선택을 사용한다.
- 지출 추가는 필수 항목명·금액, 메모, 추가 지출 결과, Callout 순서다.
- 기타 매출과 지출 입력은 숫자·suffix end 정렬, 중립 ResultField, `취소 · 추가` 1:1 행동을 사용한다.

최신 근거: PRT-168

## SALES-02 · 매출 분석

- 기간 FilterButton은 `오늘, 8월 29일 (토)`처럼 프리셋과 실제 범위를 함께 표시한다.
- 본문은 `매출 분석 · 채널별 매출 · 손익 계산 · 메뉴별 판매량` 순서이며, 매출·지출·순이익의
  금액과 비율을 같은 행 끝선에 맞춘다.
- 기간 Sheet는 `기간 / 언제를 볼까요?` 제목·맥락 아래 오늘·어제·최근 7일·이번달·지난달의 실제
  범위를 표시한다. 프리셋은 선택 즉시 반영하고 별도 적용 버튼을 반복하지 않는다.
- `직접 설정하기`는 `기간 직접 설정` Sheet로 이동하며 시작일·종료일을 별도 Field로 보여 주고
  유효한 구간만 적용한다.

최신 근거: PRT-169

## SALES-03 · 일 손익

- 헤더는 선택한 영업일을 포함한 `8월 29일 (토) 손익`으로 표시하며 별도 기간 필터를 반복하지 않는다.
- 본문은 `채널별 매출 · 일 손익 계산 · 메뉴별 판매량` 순서다. 금액과 비율은 같은 우측 끝선에
  맞추고, 하루 화면에서는 매출과 최종 순이익이 비용보다 먼저 읽히도록 위계를 둔다.
- 채널 카드의 `자세히 보기`는 채널별 손익으로, 손익 계산의 각 비용 행은 해당 상세 화면으로 이동한다.
- 메뉴별 판매 행은 메뉴명·판매 수량, 채널 구성, 매출·재료 원가를 보여 주며 행 전체가 메뉴 손익
  Sheet를 연다.
- 메뉴 손익 Sheet는 판매 수량·채널 구성·매출·비용·순이익을 한 카드에서 비교한다. 재료 원가는
  판매 시점 실제값이고 폐기·고정 지출·추가 지출·세금은 `배분`으로 명시하며 정보 아이콘 Callout으로
  산정 기준을 설명한다.
- 편집 가능한 종료 영업일에는 하단 고정 `판매 내역 수정`을 노출하고 과거 판매 수정 화면으로 이동한다.

최신 근거: PRT-170

## SALES-10 · 손익 전체 자세히

- 한 영업일의 판매 수량, 매출 구성, 비용별 세부 근거, 순이익을 하나의 긴 카드에서 위에서 아래로
  읽는다. 동일 정보를 여러 카드로 잘게 쪼개지 않는다.
- 매출은 금액 상위 메뉴 5개와 `그 외 메뉴 · 기타 매출`, 매출 합계 순서다. 메뉴명·수량은 좌측,
  금액은 우측 끝선에 맞춘다.
- 재료 원가와 부자재는 사용 금액 상위 항목, 고정 지출은 항목별 배분 금액을 부모 비용 행 아래 한
  단계 들여쓴 세부 행으로 표시한다. 근거가 없는 폐기·추가 지출·세금에는 임의 세부 행을 만들지 않는다.
- 부모 비용 행은 `라벨 / 금액 / 매출 대비 비율`, 세부 행은 `· 항목명 / 금액` 구조를 사용한다.
- 마지막 순이익 행은 목표 달성 상태, 금액, 비율을 함께 보여 주고 결과색은 상태에만 사용한다.

최신 근거: PRT-171

## SALES-12 · 매출 상세

- 헤더는 실제 Expo 화면 ID `SALES-12`의 `매출 자세히`를 사용한다.
- 한 카드 안에서 먼저 `영업일 · 판매 수량 · 매출 합계`를 요약하고, 그 아래에 `메뉴 매출 · 소계 ·
  기타 매출 · 소계`를 순서대로 표시한다.
- 메뉴 매출은 금액 내림차순이며 기본 5개만 노출한다. `더보기 (N개)`를 누르면 같은 페이지 안에서
  나머지 메뉴를 모두 펼치고 버튼은 사라진다.
- 메뉴 행은 좌측 `메뉴명 ×수량`, 우측 금액을 사용한다. 기타 매출은 좌측 두 번째 줄에 판매 채널을
  표시하고 채널 미지정은 회색 `미지정`으로 표시한다.
- 목록 이름·수량·금액과 소계는 `16px` 숫자 끝선 규격을 사용한다. 더보기 화살표는 문자 기호가 아닌
  SVG 아이콘을 사용한다.
- 프로토타입 상단의 `메뉴 전체 보기` 상태 탭은 실제 인라인 펼침을 검수하기 위한 전체 목록 시연이며,
  작은 중복 설명 문구를 표시하지 않는다.

최신 근거: PRT-173

## SALES-09 · 메뉴 손익 상세

- 이 화면은 현재 레시피를 다시 계산하는 화면이 아니라 선택한 영업일의 판매·원가 스냅샷을 보여
  주는 장부다. 화면 제목과 ID는 실제 Expo의 `메뉴 손익 / SALES-09`를 사용한다.
- 첫 카드에는 `메뉴명 → 영업일 → 판매 수량 → 매출 → 순이익률`을 표시하고, 순이익률에만 목표값을
  보조 정보로 둔다. 메뉴명은 `20px/800`, 요약 라벨·값은 `15px` 규격을 사용한다.
- 본문은 `판매량 기준 손익 → 채널 구성 → 재료 → 부자재 → 고정 지출·세금` 순으로 읽는다.
  같은 금액·비율을 반복하는 도넛 차트는 표시하지 않는다.
- 재료·부자재·고정 지출·세금 상세 행은 좌측에 `항목명 / 단가·산정 기준`, 우측에 `금액 /
  사용량·매출 대비 비율`을 둔다. 이름과 금액은 `16px`, 보조값은 `14px`이며 모든 숫자는 우측
  끝선에 맞춘다.
- 재료 카드에는 금액과 매출 대비 비율 소계를 제공한다. 카드 내부 구분선은 `line2 1px` 하나만
  사용하고 임의의 세로선·그래프·장식은 추가하지 않는다.

최신 근거: PRT-174

## SALES-04 · 채널별 손익

- 채널 카드는 금액순으로 재정렬하지 않고 `매장 → 배달앱 → 포장`의 고정 업무 순서를 유지한다.
- 첫 카드에는 영업일만 표시한다. 각 채널 카드의 헤더는 `10px` 색상 표식과 채널명을 사용하며,
  표식은 매장 파랑·배달 중간 회색·포장 연한 회색로 구분한다.
- 채널 카드 내부는 `판매 수량 → 매출 → 순이익 → 비용 항목` 순이다. 실제 채널 값과 매출 비중으로
  나눈 값은 항목명 끝의 `배분`으로 구분하며 별도 장문의 설명 문단은 표시하지 않는다.
- 금액과 비율은 같은 우측 끝선을 사용한다. 순이익만 흑자 초록·적자 빨강 상태색을 쓰고 나머지
  원가 금액은 중립색을 유지한다.
- 귀속 채널을 알 수 없는 기타 매출은 어느 채널에도 억지로 배분하지 않고 마지막 독립 요약 카드에
  `채널 미지정 기타 매출`로 표시한다.

최신 근거: PRT-175

## SALES-13 · 재료 원가 자세히 / SALES-14 · 재료별 사용 메뉴

- 재료 원가 페이지는 `영업일 · 재료 원가 합계 · 매출 원가율` 요약 뒤에 판매 소진 원장으로 집계한
  사용 식재료를 표시한다. 현재 레시피로 과거 원가를 다시 계산하지 않는다.
- 사용 식재료 행은 좌측 `식재료명+사용량 / 사용 메뉴`, 우측 `원가 / SVG 이동 아이콘` 구조다.

## 8.1 추가 확인이 필요한 기획 항목

1. 식재료 상세의 최근 입고 예시 3건은 모두 `최고`로 표시되지만, 구매 이력은 동일 최저·최고일 때 최신 대표 행 한 건에만 두 뱃지를 표시한다. 상세 미리보기에도 같은 대표 규칙을 적용할지 확인이 필요하다.
2. 레시피 상세 세금 비율은 `9.0%`, 판매가 시뮬레이션의 12,000원 초기값은 동적 계산 후 `9.1%`로 표시된다. 반올림 자릿수 계약을 하나로 통일해야 한다.
3. 권장 판매가 `15,800원`은 화면에서 `40%`로 보이지만 내부 계산값은 약 `39.96%`라 목표에 미달한다. 목표 이상이 되는 최소 단위 올림 규칙이 필요하다.
4. 레시피 상세의 `최근 30일 판매`는 `438개 · 폐기 6`, 판매 손익의 판매량은 `1인분`을 사용한다. 요약 단위를 `개`로 유지할지 `인분`으로 통일할지 확인이 필요하다.
5. 상세 상단은 `기준 인분 10인분`인데 상세 원가 카드의 기본 선택은 모두 `1인분`이다. 기본 선택 기준을 하나로 통일해야 한다.
6. 프로젝트 표시 규칙은 구매 옵션을 `식재료명 · 용량 · 금액 / 구매처 · 단가` 순서로 정의하지만 현재 구매 링크 목록은 `구매처 / 금액 / 용량 / 단가` 순서다. 이번 프로토타입 결정을 공식 규칙에 반영할지 확인이 필요하다.
7. 요청에서 언급한 `24페이지`와 프로토타입의 집계 방식이 다르다. 이 문서는 누락 방지를 위해 기본 화면과 URL 팝업·상태를 분리해 52개 계약 단위로 관리한다.
8. 레시피 상세의 표시 행을 정수로 더하면 `12 + 100 + 2,600 + 95 = 2,807원`이지만 재료비 소계는 `2,806원`이다. 내부 소수 사용량·원가를 합산한 뒤 반올림한 값인지, 표시 행 반올림값의 합을 사용할지 반올림 계약을 명시해야 한다.

## 8.2 현재 프로토타입 구현 점검 항목

아래는 확정안 자체가 아니라 현재 HTML에서 확인된 미구현·불일치다. 실제 Expo 앱 수정 전에 프로토타입에서 먼저 보완한다.

### 식재료

1. 메인에 `향신료·허브` 카테고리 탭이 없어 해당 카테고리의 고춧가루를 탭으로 찾을 수 없다.
2. 메인 카테고리와 정렬은 선택 표시만 바뀌며 카드 필터·정렬은 실제 적용되지 않는다.
3. 추가 화면은 필수값이 비어 있어도 `추가` 버튼이 활성화된다.
4. 추가 화면의 단위를 `g`로 바꾸면 안전재고 단위는 바뀌지만 구매 단가는 `0원/kg`로 남는다.
5. 식재료 카드 다섯 개가 모두 고춧가루 상세 예시로 연결된다.
6. 수정 메뉴 화면 헤더의 `✎ 수정`이 자기 화면을 다시 연다.
7. 재고 내역의 요약 `현재 재고 812g`과 최신 입고 행의 잔량 `1.8kg`이 일치하지 않는다.
8. 재고 요약의 입고 `+4kg`과 현재 표시된 입고 행 두 건의 합계 `+2kg`이 일치하지 않는다.
9. 재고를 `오래된순`으로 바꾸면 렌더 순서를 기준으로 철회 메뉴를 붙여 유형별 최신 기록이 아닌 오래된 기록에 철회가 노출될 수 있다.
10. 폐기 입력에는 `조리 전 / 조리 후` 구분 선택이 없지만 내역과 합계는 두 유형을 구분한다.
11. 직접 입고의 구매처는 동작상 필수지만 라벨에 `*`가 없다.
12. 구매 링크 추가·수정의 링크 이름·용량·금액이 정적 표시라 실제로 편집할 수 없고, 저장 가능 여부도 모든 필수값을 검사하지 않는다.
13. 구매 링크 수정의 단위 선택창은 현재 단위 `kg`에 체크를 표시하지 않는다.
14. 기간 필터는 표시값만 바뀌고 재고·구매 이력 행 범위는 바뀌지 않는다.
15. 수정 내역의 서로 다른 두 사건이 같은 전후 비교 내용을 재사용한다.
16. 메모 글자 수가 입력에 따라 갱신되지 않고 완료 동작도 연결되지 않는다.
17. 식재료 삭제, 구매 링크 저장, 재고 차감, 폐기 기록 등 일부 최종 행동은 다음 상태가 연결되지 않았다.

### 레시피

1. 상세 헤더 `✎ 수정`은 보이지만 `recipe_edit`로 이동하지 않는다.
2. 메인의 검색·알림은 동작하지 않는다.
3. 메인 카테고리·정렬·판매 상태·목표 필터는 표시만 바뀌고 카드 목록에 적용되지 않는다.
4. 상세와 시뮬레이션의 `10인분 / 1인분` 탭은 선택 표시와 일부 문구만 바꾸며 사용량·금액을 환산하지 않는다.
5. 판매가 시뮬레이션은 순이익률이 목표를 넘어도 `목표 미달` 뱃지가 바뀌지 않는다.
6. 레시피 추가의 메뉴명·판매가·기준 인분·목표 순이익률은 입력 요소가 아닌 고정 표시이고, 최종 버튼은 항상 비활성이다.
7. 레시피 카테고리를 골라도 원 화면 값이 바뀌거나 선택창이 닫히지 않는다.
9. 메모 `완료`와 권장 판매가 `적용하기`는 아직 저장 결과 상태까지 연결되지 않는다.
12. 상세 재료 행에는 화살표가 있지만 이동 동작이 없다.
13. 휴면 상태의 옛 판매가 시뮬레이션 팝업 정의가 남아 있으나 사용자 경로에서는 별도 페이지로만 이동한다.
14. 레시피 상세의 돼지고기 앞다리는 기본 `1인분` 탭에서 `200g · 2,600원`인데, 재료 추가 사용량 시트는 `10인분 전체 200g → 1인분 20g · 260원`으로 표시한다. 화면별 기준 인분 계약을 공식 계산 문서에서 하나로 정리해야 한다.
16. 사용자에게는 최신 레시피 메인 렌더가 노출되지만, 코드 안에는 카드 수와 필터 문구가 다른 옛 레시피 메인 렌더 분기가 휴면 상태로 남아 있다.

- Opus 검수는 공식 Fable 게이트를 대신하지 않는 보조 교차검수다.
- 실제 Expo 앱, 앱 소스와 기존 프로토타입 HTML은 세 회차 모두 수정하지 않았다.
