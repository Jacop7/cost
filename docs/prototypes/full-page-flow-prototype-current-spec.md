# 전체 페이지 흐름 프로토타입 · 현재 확정안

## 1. 문서 역할

이 문서는 `full-page-flow-prototype.html`에 현재 실제로 노출되는 화면만을 화면별로 정리한 살아 있는 확정안이다.

- 변경 과정과 원복 이력은 `full-page-flow-prototype-changelog.md`에 계속 누적한다.
- 이 문서에는 대체된 옛 문구와 옛 구조를 남기지 않는다.
- 같은 항목이 다시 수정되면 이 문서의 기존 항목을 교체하고, 변경 이력에는 새 PRT 항목을 추가한다.
- 기획안 작성 시에는 이 문서를 기준으로 사용하고 변경 이력은 근거 확인용으로만 사용한다.
- 실제 Expo 앱과 앱 소스에는 아직 반영하지 않는다. 현재 범위는 프로토타입과 문서다.

현재 기준 파일:

- 프로토타입: `docs/prototypes/full-page-flow-prototype.html`
- 전체 변경 이력: `docs/prototypes/full-page-flow-prototype-changelog.md`
- 현재 확정안: `docs/prototypes/full-page-flow-prototype-current-spec.md`

현재 반영 범위:

- 식재료 기본 화면 12개 전체
- 레시피 기본 화면 4개: 메인, 상세, 판매가 시뮬레이션, 레시피 추가
- 위 화면에서 직접 진입하는 선택창·확인창·상태 화면 전체

개수는 기본 화면과 팝업을 분리해 관리한다. 같은 렌더 결과를 재사용하는 상태도 URL·진입 계약이 다르면 검수 단위에는 포함한다.

| 구분 | 기본 화면 | 직접 연결된 팝업·상태 | 계약 검수 단위 | 서로 다른 렌더 결과 |
|---|---:|---:|---:|---:|
| 식재료 | 12 | 29 | 41 | 38 |
| 레시피 현재 확정 범위 | 4 | 7 | 11 | 11 |
| 합계 | 16 | 36 | 52 | 49 |

레시피 핵심 4개 화면에서 이어지는 보조 화면 6개와 보조 팝업 2개도 별도로 도달성 검수했다. 이 8개는 이번 확정안의 핵심 화면 수에는 합산하지 않고, 연결 흐름과 구현 점검 항목에 기록한다.

`폐기 내역` 독립 화면은 삭제하지 않고 숨김 보존한다. 화면 목록에서는 제외하며 `재고 내역`의 폐기 유형으로 연결한다.

## 2. 공통 확정 규칙

### 2.1 내비게이션과 헤더

- 하단 탭은 `식재료 · 레시피 · 발주 · 매출관리 · MY` 5개다.
- 메인 화면 헤더 우측에는 검색과 알림 아이콘을 둔다. 알림 아이콘은 새 알림 점을 가질 수 있다.
- 상세 화면은 좌측 뒤로가기와 화면 제목을 사용한다.
- 식재료 상세 우측에는 `✎ 수정`, 레시피 상세 우측에는 `✎ 수정`을 둔다.
- 헤더 우측에 재고량, 입고 건수 같은 요약 숫자를 중복 노출하지 않는다.

### 2.2 카드와 목록

- 카드 모서리는 둥글게 처리하고 카드 사이에는 11px 기본 간격을 유지한다.
- 섹션 헤더는 좌측 제목을 우선하며 우측의 중복 숫자·설명은 최소화한다.
- 상세 미리보기 목록은 최대 3개까지 노출하고 하단 행동은 `전체보기 ›`로 통일한다.
- 값 목록은 좌측에 이름·보조 정보, 우측에 핵심 값·단가를 둔다.
- 빈 상태는 한 문장으로 표시하고, 가능한 다음 행동이 있으면 빈 상태 바로 아래에 버튼을 둔다.

### 2.3 입력과 계산 결과

- 입력 라벨은 입력칸 위에 둔다. 입력칸 안에는 값 또는 플레이스홀더만 둔다.
- 필수값은 라벨 우측의 파란색 `*`로 표시한다.
- 입력칸 아래의 중복 설명은 노출하지 않는다.
- 합계, 변경 후 재고, 예상 손실, 구매 단가 같은 읽기 전용 결과는 라벨과 값이 분리된 결과 카드로 표시한다.
- 읽기 전용 결과 카드는 일반 입력칸보다 구분되도록 옅은 배경과 테두리를 사용한다.
- 저장·추가 버튼은 화면 하단에 고정하고, 필수값이 준비되지 않으면 비활성화한다.

### 2.4 팝업

- 선택·입력은 하단 바텀시트로 연다.
- 단일 선택창은 제목 다음에 선택지를 바로 배치하며 제목을 반복하는 작은 소제목을 넣지 않는다.
- 현재 선택값 우측에는 `✓`를 표시한다.
- 삭제, 철회, 판매 상태 변경처럼 순수 확인만 필요한 창은 화면 가운데 알럿으로 연다.
- 확인 알럿의 행동은 하단 2열 버튼을 사용한다.
- 메시지 팝업 제목은 간단한 명사형으로 작성한다. 예: `입고 실패`.

### 2.5 최근 수정과 이력

- 상세의 최근 수정 영역은 최근 7일 안에 표시할 기록이 있을 때만 노출한다.
- 기록이 없으면 영역 전체를 숨긴다.
- 수정 내역은 최근 7일만 표시하고 재고 수량 변동과 메모 변경은 포함하지 않는다.
- 재고·구매 이력 필터는 각각 독립된 필터 칩으로 표시하고, 누른 필터에 맞는 단일 선택창을 연다.

# 3. 식재료 현재 확정안

## ING-01 · 식재료 메인

### 헤더와 상단 탐색

- 화면 제목: `식재료`
- 우측 행동: 검색, 알림
- 카테고리 탭: `전체 · 축산·계란 · 수산·해조류 · 농산(신선) · 곡물·견과·분말 · 유제품 · 냉동식품`
- 목록 정렬 칩 기본값: `재고 적은 순⌄`

### 식재료 카드

각 카드는 다음 순서로 표시한다.

1. 재고 상태 뱃지: `여유`, `소진 임박`, `소진`
2. 식재료명
3. 카테고리
4. `총 {재고량}`
5. 안전재고가 필요한 경우 `안전재고 {수량}`
6. 기준 단가
7. `최근입고 {MM/DD}`

현재 예시:

- 설탕: `소진 임박 / 곡물·견과·분말 / 총 3kg / 안전재고 3kg / 1.80원/g / 최근입고 08/08`
- 고춧가루: `소진 임박 / 향신료·허브 / 총 812g / 안전재고 1kg / 28.00원/g / 최근입고 08/27`
- 쌀: `여유 / 곡물·견과·분말 / 총 13kg / 3.20원/g / 최근입고 08/27`
- 계란: `여유 / 축산·계란 / 총 123개 / 300.00원/개 / 최근입고 08/29`
- 대파: `여유 / 농산(신선) / 총 4.1kg / 4.00원/g / 최근입고 08/29`

상태 판정:

- 재고가 0 이하이면 `소진`이며 음수 재고를 그대로 표시한다.
- 재고가 양수이면서 안전재고 이하이거나 소진 임박 판정이면 `소진 임박`이다.
- 그 외는 `여유`다.
- 안전재고 관련 뱃지는 `안전재고` 명칭을 사용하며 노란색 계열로 표시한다.

### 정렬 선택창

- 제목: `정렬 기준`
- 선택지: `최신순 · 재고 적은 순 · 단가 높은 순 · 이름순`
- `최신순`은 최신 등록순이다.
- 추천순과 선택 설명 문구는 노출하지 않는다.

### 하단 행동

- 버튼: `＋ 식재료 추가`
- 클릭 시 ING-02로 이동한다.

최신 근거: PRT-035, PRT-036, PRT-103

## ING-02 · 식재료 추가

### 기본 정보 입력 순서

1. `식재료명 *` — 플레이스홀더 `식재료명을 입력하세요`
2. `카테고리 *` — 기본값 `카테고리 선택`
3. `개당 용량 *` — 수량 입력과 단위 선택을 2열로 배치, 기본 단위 `kg`
4. `구매 단가` — 읽기 전용 결과, 초기값 `0원/kg`
5. `구매 가격` — 초기값 `0원`
6. `안전재고 *` — 초기값 `0kg`
7. `최소 발주 수량 *` — 초기값 `1개`
8. `메모 (선택)` — 최초 등록에서만 허용, 플레이스홀더 `메모를 입력하세요`

### 구매 링크 안내

- 폼 하단에 입력칸과 같은 너비의 안내 영역을 둔다.
- 문구: `구매 링크는 저장한 뒤 상세 화면에서 추가할 수 있어요.`
- 우측 화살표는 표시하지 않는다.
- 식재료 추가 단계에서는 구매 링크를 직접 관리하지 않는다.

### 카테고리 선택창

- 제목: `카테고리 선택`
- 선택지: `축산·계란 · 수산·해조류 · 농산(신선) · 곡물·견과·분말 · 향신료·허브 · 유제품 · 냉동식품`
- `식재료 카테고리` 같은 중복 소제목은 표시하지 않는다.

### 단위 선택창

- 제목: `단위 선택`
- `kg — 무게`
- `g — 무게`
- `L — 부피`
- `ml — 부피`
- `개 — 수량`
- `모 — 수량`
- 현재 선택값에 `✓`를 표시한다.

### 하단 행동

- 버튼: `추가`
- 필수값이 준비되기 전에는 비활성화한다.

최신 근거: PRT-033, PRT-037~042, PRT-050~051

## ING-03 · 식재료 상세

### 헤더

- 화면 제목: `식재료`
- 우측 행동: `✎ 수정`
- `✎ 수정` 클릭 시 ING-03a 수정 메뉴를 연다.

### 상단 기본 카드

- 카테고리 태그: `향신료·허브`
- 식재료명: `고춧가루`
- 메모 영역: `▣ 메모`와 본문 `메모를 입력하세요`
- 최근 7일 수정 기록이 있을 때만 최근 수정 링크를 표시한다.
- 현재 예시: `◴ 최근 수정 08:52 / 현재 매출 반영 / ›`

### 재고 요약 카드

- 왼쪽: `재고 812g`
- 왼쪽 두 번째 줄: `기준 단가 28.00원/g`
- 오른쪽 상태 뱃지: `소진 임박`
- 하단 칩: `안전재고 1kg · 최소 발주 1개 · 최근 입고 08/27`
- `현재 재고`, `총`, `개당 1kg` 같은 중복 대표 문구는 표시하지 않는다.

### 구매 링크 카드

보유 상태:

- 섹션 제목: `구매 링크`
- 최대 3개를 미리보기로 노출한다.
- 행의 왼쪽: 구매처와 금액
- 행의 오른쪽: 용량과 단가
- 현재 예시:
  - `식자재쇼핑몰 / 28,000원 / 1kg / 28.00원/g`
  - `성동청과 / 57,000원 / 2kg / 28.50원/g`
  - `온라인도매 / 88,500원 / 3kg / 29.50원/g`
- 하단 버튼: `전체보기 ›`
- 행 우측 화살표는 표시하지 않는다.

빈 상태:

- 문구: `등록된 구매 링크가 없어요`
- 하단 버튼: `＋ 구매 링크 추가`

### 기준 단가·최근 입고 카드

- 섹션 제목: `기준 단가`
- `기준 단가를 계산한 입고 기록` 같은 설명은 표시하지 않는다.
- 값: `실입고 기준 28.00원/g`, `가중평균 28.00원/g`
- 범위: `최저 28.00원/g`, `최고 28.00원/g`
- 같은 카드 안에서 `최근 입고` 목록을 이어 표시한다.
- 최근 입고는 최대 3개 노출한다.
- 예시 행은 날짜, 구매처, 단가, 총량·총액 순으로 구성한다.
- 하단 버튼: `전체보기 ›`, 클릭 시 ING-09로 이동한다.

### 폐기 내역 카드

- 섹션 제목: `폐기 내역`
- 최대 3개 노출한다.
- 예시:
  - `08/29 · 조리 전 폐기 / 유통기한 경과 / −120g / 3,360원`
  - `08/26 · 조리 후 폐기 / 영업 종료 후 남은 재료 / −80g / 2,240원`
- 하단 버튼: `전체보기 ›`
- 클릭 시 숨김 폐기 화면을 직접 열지 않고 ING-07을 폐기 유형으로 연다.

### 현재 재고 카드

- 섹션 제목: `현재 재고`
- 최대 3개 노출한다.
- 예시 행: 날짜·유형, 출처, 증감량, 처리 후 잔량
- 하단 버튼: `전체보기 ›`, 클릭 시 ING-07로 이동한다.

최신 근거: PRT-007~016, PRT-043~047, PRT-068~072, PRT-092~093

행 순서:

1. `식재료 수정`
2. `재고 수정`
3. `메모 수정`
4. `구매 링크 수정`
5. `식재료 삭제` — 위험 색상

시트 아래 별도 버튼: `닫기`

최신 근거: PRT-012, PRT-013, PRT-046

## ING-04 · 식재료 수정

입력 순서:

1. `식재료명 *` — `고춧가루`
2. `카테고리 *` — `향신료·허브`
3. `개당 용량 *` — `1 / kg`
4. `구매 단가` — 읽기 전용 `28.00원/g`
5. `구매 가격` — `28,000원`
6. `안전재고 *` — `1kg`
7. `최소 발주 수량 *` — `1개`

수정 폼에는 메모와 구매 링크 관리 항목을 표시하지 않는다. 각각 `메모 수정`, `구매 링크 수정`에서 별도로 관리한다.

카테고리·단위 선택창은 ING-02와 같은 공통 규격을 사용한다.

하단 버튼: `저장`

최신 근거: PRT-048~051

## ING-05 · 재고 수정

### 공통 상단

- 식재료명: `고춧가루`
- 현재 재고: `812g`
- 기준단가: `28.00원/g`
- 탭: `입고 · 차감 · 폐기`
- `실사` 탭은 사용하지 않는다.

### 입고 탭

구매처 미선택 상태:

- 필드: `구매처 *`
- 값: `미선택⌄`
- 구매처 선택 전에는 용량, 수량, 총 입고량, 결제금액, 기준단가, 입고일을 노출하지 않는다.
- 하단 버튼: `재고 0g 입고`, 비활성화한다.

구매처 선택창:

- 제목: `구매처 선택`
- 첫 행: `미 선택`, 회색
- 저장 링크 행 1줄: `식자재쇼핑몰 · 고춧가루 1kg`
- 저장 링크 행 2줄: `28,000원 · 28.00원/g`
- 다른 예시: `동네마트 · 고춧가루 500g / 15,000원 · 30.00원/g`
- 하단 고정 2열 버튼: `＋ 직접 입력`, `＋ 구매 링크 추가`

저장 구매 링크 선택 후:

- `구매처 *`: `식자재쇼핑몰 · 고춧가루 1kg`
- `용량 *`: 구매 링크 값으로 고정하며 수정할 수 없다.
- `입고 수량 *`: `− / 1개 / ＋` 스테퍼
- 결과: `총 입고량 1kg`
- `실제 결제금액 *`
- 결과: `입고 후 기준단가 28.00원/g`
- `입고일`
- 하단 버튼: `재고 1kg 입고`

입고 확인:

- 중앙 확인창 제목: `재고를 입고할까요?`
- 핵심 정보: `고춧가루 · 1kg`
- 버튼: `취소 / 입고`

입고 실패:

- 제목: `입고 실패`
- 본문: `재고를 입고하지 못했어요. 잠시 후 다시 시도해 주세요.`
- 버튼: `확인`

### 차감 탭

- `차감할 수량 *` — 예시 `120g`
- 결과: `차감 후 재고 692g`
- `사유 *` — 필수, 플레이스홀더 `예) 조리 중 사용`
- 전량 차감 버튼은 표시하지 않는다.
- 하단 버튼: `재고 차감`

### 폐기 탭

- `폐기할 수량 *` — 예시 `120g`
- 결과: `폐기 후 재고 692g`
- 결과: `예상 손실 3,360원`
- `폐기 사유 *` — 예시 `유통기한 경과`
- 하단 버튼: `폐기 기록`

## ING-06 · 구매 링크

### 목록

- 화면 제목: `구매 링크`

- 왼쪽 2줄: 금액
- 오른쪽 1줄: 용량
- 오른쪽 2줄: 단가
- 별도 외부 이동 화살표와 연필 아이콘은 표시하지 않는다.

현재 예시:

- 구매처: `식자재쇼핑몰`

### 추가·수정 폼

필드 순서:

1. `링크 이름 *`
2. `구매처 *`
3. `용량 *` — 수량과 단위 2열
4. `금액 *`
5. `구매 링크 *`

추가 초기값:

- 링크 이름 플레이스홀더: `예) 고춧가루 1kg`

- 용량: `0 / g`
- 금액: `0원`
- 구매 링크 플레이스홀더: `https://`
- 하단 결과: `구매 단가 0원/g`
- 하단 버튼: `추가`

수정 예시:

- 링크 이름: `고춧가루 1kg`
- 구매처: `식자재쇼핑몰`
- 용량: `1 / kg`
- 금액: `28,000원`
- 하단 결과: `구매 단가 28.00원/g`
- 하단 버튼: `저장`

입력 규칙:

- 구매처와 구매 링크는 필수다.
- URL은 `http` 또는 `https` 형식이어야 한다.
- 저장된 구매처를 선택하면 기존 링크의 경로를 제거한 도메인 원본만 구매 링크 입력칸에 채운다.

### 구매처 선택창

### 단위 선택창

### 더보기와 삭제

- 수정 화면 헤더 우측 `•••`를 누르면 우측 하단 컨텍스트 메뉴를 연다.

## ING-07 · 재고 내역

### 필터

- `최근 3개월⌄`
- `전체⌄`
- `최신순⌄`
- 세 필터는 각각 독립적으로 누를 수 있다.

기간 선택창:

- 제목: `조회 기간`
- `최근 1개월 · 최근 3개월 · 최근 6개월 · 전체`

유형 선택창:

- 제목: `유형`
- `전체 · 입고 · 판매 소진 · 차감 · 폐기`
- 폐기 하위 구분 필터는 별도로 두지 않는다.

정렬 선택창:

- 제목: `정렬 기준`
- `최신순 · 오래된순`

### 전체 요약

- `현재 재고 812g`
- `입고 +4kg`
- `판매 소진 −3.2kg`
- `차감 −700g`
- `폐기 −200g`

특정 유형만 선택하면 전체 요약은 숨기고 해당 목록에 집중한다. 폐기 유형에서는 폐기 합계를 사용한다.

### 목록

- 월 헤더: `2026년 8월 / 총 9건`
- 입고 예시: `08/30 / 입고 / 식자재쇼핑몰 · 1kg × 1개 / +1kg / 잔량 1.8kg`
- 차감 예시: `08/30 / 차감 / 재고 정리 / −700g / 잔량 1.1kg`
- 폐기 예시: `08/29 / 폐기 · 조리 전 / 유통기한 경과 / −120g / 3,360원 · 잔량 980g`
- 판매 소진 예시: `08/29 / 판매 소진 / 순두부찌개 10개 / −80g / 잔량 812g`

### 빠른 철회

- 입고·차감·폐기만 대상이다.
- 최근 7일 안의 같은 유형 최신 1건에만 `⋮`를 표시한다.
- 판매 소진은 빠른 철회 대상이 아니다.
- 같은 유형의 이후 기록이 있으면 이전 기록에는 철회를 노출하지 않는다.

기록 상세 시트 예시:

- 제목: `입고내역`
- 회색 요약 박스 1줄: `08/30   식자재쇼핑몰`
- 회색 요약 박스 2줄: `입고 1kg (1kg × 1개)`
- 버튼: `닫기 / 입고 철회`

철회 확인:

- 제목: `입고 철회`
- 본문: `1kg 입고 기록을 철회할까요? 재고와 기준 단가가 다시 계산돼요.`
- 버튼: `취소 / 철회`

최신 근거: PRT-080~082, PRT-089, PRT-092~102

- 단가 설명 푸터는 표시하지 않는다.

최신 근거: PRT-090, PRT-091, PRT-101

## ING-03b · 수정 내역

# 4. 레시피 현재 확정안

## RCP-01 · 레시피 메인

### 헤더와 카테고리

- 화면 제목: `레시피`
- 우측 행동: 검색, 알림
- 카테고리 탭: `전체 · 찌개·전골 · 볶음·구이 · 밥·면 · 사이드`

### 필터

- 기본 정렬 칩: `순이익률 낮은순`
- 기본 판매 상태 칩: `판매중`
- 목표 전체 상태 칩: `목표 상태`

정렬 선택창:

- 제목: `정렬 기준`
- `최신순 · 순이익률 낮은순 · 순이익률 높은순 · 판매량 많은순 · 판매가 높은순 · 판매가 낮은순`

판매 상태 선택창:

- 제목: `판매 상태`
- `전체 · 판매중 · 판매중지`
- 전체가 선택되면 칩은 `판매 상태`로 표시한다.

목표 선택창:

- 제목: `목표`
- `전체 · 목표 미달 · 목표 달성`
- 전체가 선택되면 칩은 `목표 상태`로 표시한다.

### 레시피 카드

표시 순서:

1. 목표 상태 뱃지
2. 메뉴명
3. 카테고리
4. `판매가`와 금액
5. `순이익 목표 {비율}`과 실제 순이익률·금액
6. `재료비`와 비율·금액

현재 예시에는 공기밥, 김치찌개, 소불고기, 순두부찌개, 제육볶음, 된장찌개, 계란말이를 표시한다.

### 하단 행동

- 버튼: `＋ 레시피 추가`
- 클릭 시 RCP-03으로 이동한다.

최신 근거: PRT-103, PRT-104, PRT-136

## RCP-02 · 레시피 상세

### 헤더와 상태

- 화면 헤더 제목: `레시피`
- 우측 행동: `✎ 수정`
- 목표 상태 `목표 미달`을 메뉴명 위에 표시한다.
- 메뉴명: `제육볶음`
- 메뉴명 우측 판매 상태 버튼: `판매중⌄`
- 판매중 버튼은 파란색 채움, 흰색 글자, 테두리 없음이다.
- 판매중지 상태는 회색 테두리와 `판매중지⌃`를 사용한다.

### 판매 상태 변경

- 상태 버튼을 누르면 선택 목록이 아니라 중앙 확인창을 연다.
- 판매중에서 누르면 제목: `판매를 중지하시겠습니까?`
- 판매중지에서 누르면 제목: `판매중으로 상태를 변경하시겠습니까?`
- 버튼: `아니오 / 예`

### 메모와 최근 수정

- 메모 행: `▣ 메모  메모 없음`
- 메모 행 클릭 시 `메모 수정` 바텀시트를 연다.
- 메모 수정 시트: 다중 행 입력, `0 / 100`, `취소 / 완료`
- 최근 7일 수정 기록이 있을 때만 최근 수정 영역을 표시한다.
- 현재 예시: `◴ 최근 수정 15:21 / 매출 계산과 무관 / ›`

### 기본 요약

- `판매가 12,000원`
- `기준 인분 10인분`
- `최근 30일 판매 438개 · 폐기 6`
- `목표 순이익률 40%`
- 사용자가 직접 입력하는 월 평균 판매량은 사용하지 않는다.

### 판매가 구성

- 중앙 지표: `순이익률 33.7%`
- `재료 2,806원 / 23.3%`
- `부자재 300원 / 2.5%`

# 5. 4회 교차 검수 결과

이번 판본은 같은 화면을 네 가지 관점으로 다시 확인했다.

1. 화면 원문 검수 — 기본 화면과 URL 상태의 실제 렌더 텍스트·순서·버튼을 대조했다.
2. 식재료 독립 검수 — 식재료 12개 화면과 29개 팝업·상태를 별도로 확인했다.
3. 레시피 독립 검수 — 핵심 4개 화면, 핵심 팝업 7개, 직접 연결 보조 화면 6개와 보조 팝업 2개를 확인했다.
4. 변경 충돌 검수 — PRT-001~136 중 서로 대체된 결정과 휴면 화면·후처리 치환을 확인했다.

검수 결과는 아래처럼 구분한다.

- 본문: 현재 확정된 화면 구조와 문구
- 추가 확인 필요: 기획값끼리 충돌해 사용자의 선택이 필요한 항목
- 구현 점검: 확정안은 정해졌지만 현재 프로토타입 상호작용이 아직 따라오지 못한 항목
- 실제 Expo 앱: 이번 작업에서는 읽기 전용이며 수정하지 않음

## 5.1 추가 확인이 필요한 기획 항목

1. 식재료 상세의 최근 입고 예시 3건은 모두 `최고`로 표시되지만, 구매 이력은 동일 최저·최고일 때 최신 대표 행 한 건에만 두 뱃지를 표시한다. 상세 미리보기에도 같은 대표 규칙을 적용할지 확인이 필요하다.
2. 레시피 상세 세금 비율은 `9.0%`, 판매가 시뮬레이션의 12,000원 초기값은 동적 계산 후 `9.1%`로 표시된다. 반올림 자릿수 계약을 하나로 통일해야 한다.
3. 권장 판매가 `15,800원`은 화면에서 `40%`로 보이지만 내부 계산값은 약 `39.96%`라 목표에 미달한다. 목표 이상이 되는 최소 단위 올림 규칙이 필요하다.
4. 레시피 상세의 `최근 30일 판매`는 `438개 · 폐기 6`, 판매 손익의 판매량은 `1인분`을 사용한다. 요약 단위를 `개`로 유지할지 `인분`으로 통일할지 확인이 필요하다.
5. 상세 상단은 `기준 인분 10인분`인데 상세 원가 카드의 기본 선택은 모두 `1인분`이다. 기본 선택 기준을 하나로 통일해야 한다.
6. 프로젝트 표시 규칙은 구매 옵션을 `식재료명 · 용량 · 금액 / 구매처 · 단가` 순서로 정의하지만 현재 구매 링크 목록은 `구매처 / 금액 / 용량 / 단가` 순서다. 이번 프로토타입 결정을 공식 규칙에 반영할지 확인이 필요하다.
7. 요청에서 언급한 `24페이지`와 프로토타입의 집계 방식이 다르다. 이 문서는 누락 방지를 위해 기본 화면과 URL 팝업·상태를 분리해 52개 계약 단위로 관리한다.

## 5.2 현재 프로토타입 구현 점검 항목

아래는 확정안 자체가 아니라 현재 HTML에서 확인된 미구현·불일치다. 실제 Expo 앱 수정 전에 프로토타입에서 먼저 보완한다.

### 식재료

1. 메인에 `향신료·허브` 카테고리 탭이 없어 해당 카테고리의 고춧가루를 탭으로 찾을 수 없다.
2. 메인 카테고리와 정렬은 선택 표시만 바뀌며 카드 필터·정렬은 실제 적용되지 않는다.
3. 추가 화면은 필수값이 비어 있어도 `추가` 버튼이 활성화된다.
4. 추가 화면의 단위를 `g`로 바꾸면 안전재고 단위는 바뀌지만 구매 단가는 `0원/kg`로 남는다.
5. 식재료 카드 다섯 개가 모두 고춧가루 상세 예시로 연결된다.
6. 수정 메뉴 화면 헤더의 `✎ 수정`이 자기 화면을 다시 연다.
7. 재고 내역의 요약 `현재 재고 812g`과 최신 입고 행의 잔량 `1.8kg`이 일치하지 않는다.
8. 재고 요약의 입고 `+4kg`과 현재 표시된 입고 행 두 건의 합계 `+2kg`이 일치하지 않는다.
9. 재고를 `오래된순`으로 바꾸면 렌더 순서를 기준으로 철회 메뉴를 붙여 유형별 최신 기록이 아닌 오래된 기록에 철회가 노출될 수 있다.
10. 폐기 입력에는 `조리 전 / 조리 후` 구분 선택이 없지만 내역과 합계는 두 유형을 구분한다.
11. 직접 입고의 구매처는 동작상 필수지만 라벨에 `*`가 없다.
12. 구매 링크 추가·수정의 링크 이름·용량·금액이 정적 표시라 실제로 편집할 수 없고, 저장 가능 여부도 모든 필수값을 검사하지 않는다.
13. 구매 링크 수정의 단위 선택창은 현재 단위 `kg`에 체크를 표시하지 않는다.
14. 기간 필터는 표시값만 바뀌고 재고·구매 이력 행 범위는 바뀌지 않는다.
15. 수정 내역의 서로 다른 두 사건이 같은 전후 비교 내용을 재사용한다.
16. 메모 글자 수가 입력에 따라 갱신되지 않고 완료 동작도 연결되지 않는다.
17. 식재료 삭제, 구매 링크 저장, 재고 차감, 폐기 기록 등 일부 최종 행동은 다음 상태가 연결되지 않았다.

### 레시피

1. 상세 헤더 `✎ 수정`은 보이지만 `recipe_edit`로 이동하지 않는다.
2. 메인의 검색·알림은 동작하지 않는다.
3. 메인 카테고리·정렬·판매 상태·목표 필터는 표시만 바뀌고 카드 목록에 적용되지 않는다.
4. 상세와 시뮬레이션의 `10인분 / 1인분` 탭은 선택 표시와 일부 문구만 바꾸며 사용량·금액을 환산하지 않는다.
5. 판매가 시뮬레이션은 순이익률이 목표를 넘어도 `목표 미달` 뱃지가 바뀌지 않는다.
6. 레시피 추가의 메뉴명·판매가·기준 인분·목표 순이익률은 입력 요소가 아닌 고정 표시이고, 최종 버튼은 항상 비활성이다.
7. 레시피 카테고리를 골라도 원 화면 값이 바뀌거나 선택창이 닫히지 않는다.
8. 목표 순이익률 안내 시트 안에 닫기 행동이 없다.
9. 재료·부자재 검색창은 입력 요소가 아닌 장식이며 실제 검색되지 않는다.
10. 재료·부자재를 골라도 사용량 시트가 선택 대상에 연동되지 않고 고정 예시값을 보여준다.
11. 재료·부자재 `담기`, 메모 `완료`, 권장 판매가 `적용하기`가 동작하지 않는다.
12. 상세 재료 행에는 화살표가 있지만 이동 동작이 없다.
13. 휴면 상태의 옛 판매가 시뮬레이션 팝업 정의가 남아 있으나 사용자 경로에서는 별도 페이지로만 이동한다.
