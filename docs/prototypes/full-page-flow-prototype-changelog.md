# 전체 페이지 흐름 프로토타입 변경 기록

대상 프로토타입: `docs/prototypes/full-page-flow-prototype.html`

이 문서는 프로토타입 검토 중 확정하거나 실험한 화면 변경을 기록한다. 실제 Expo 앱과 공식 기획안에는 자동으로 적용하지 않는다. 프로토타입 검토가 끝나면 `기획안 반영 포인트`를 기준으로 공식 기획안에 옮기고, 반영 여부를 다시 확인한다.

## 기록 규칙

- 프로토타입을 수정할 때마다 새 항목을 추가한다.
- `변경 이유`에는 사용자가 느낀 문제와 해결하려는 UX를 적는다.
- `기획안 반영 포인트`에는 화면 구성, 노출 조건, 이동 경로처럼 문서에 확정해야 할 규칙을 적는다.
- 실제 앱에 반영하기 전까지 상태는 `프로토타입 반영`으로 유지한다.
- 기획안 반영 후에는 대상 문서와 항목을 연결하고 상태를 `기획안 반영`으로 바꾼다.

## 변경 내역

### PRT-001 · 전체 페이지를 현재 Expo 디자인 기준으로 재구성

- 날짜: 2026-08-29
- 적용 화면: 식재료 · 레시피 · 발주 · 매출관리 · MY 전체 흐름
- 상태: 프로토타입 반영 · 기획안 미반영
- 변경 내용:
  - 기존 상세·내역 프로토타입을 보존하고 별도 전체 페이지 프로토타입을 생성했다.
  - 하단 메뉴 5개와 `메인 → 상세 → 상세의 상세` 흐름을 한 파일에서 전환할 수 있게 구성했다.
  - 실제 Expo의 색상, 카드, 간격, 헤더, 하단 탭을 기준으로 화면을 다시 맞췄다.
  - MY의 묶음 설정을 카테고리, 세금, 언어·통화, 단위, 구매처, 판매 채널, 영업시간, 알림, 계정 화면으로 분리했다.
  - 총 39개 화면을 전환·검수했다.
- 변경 이유: 화면을 하나로 축약하면 실제 앱의 화면별 구조와 이동 경로를 검토하기 어렵다.
- 기획안 반영 포인트:
  - 하단 메뉴별 전체 화면 목록과 화면 ID
  - 화면별 헤더·카드·하단 탭 공통 규칙
  - 메인, 상세, 하위 상세 사이의 이동 경로

### PRT-002 · 식재료 상세의 내역 링크 묶음 제거

- 날짜: 2026-08-29
- 적용 화면: `ingredient_detail`
- 상태: 프로토타입 반영 · 기획안 미반영
- 변경 내용:
  - `상세 내역` 카드에 모아 둔 재고 변동·구매 이력·폐기 내역 링크를 제거했다.
  - 실제 화면 순서에 맞춰 기준 단가, 최근 입고, 폐기 상태, 최근 재고 변동, 구매 옵션을 각각 독립 영역으로 노출했다.
- 변경 이유: 실제 식재료 상세는 필요한 핵심 내역을 한 화면에서 바로 확인하며, 별도 링크 묶음 구조가 아니다.
- 기획안 반영 포인트:
  - 식재료 상세의 섹션 순서와 각 섹션의 전체보기 이동 경로
  - 최근 내역 노출 개수와 빈 상태 문구

### PRT-003 · 레시피 상세의 계산 영역을 실제 구조로 분리

- 날짜: 2026-08-29
- 적용 화면: `recipe_detail`
- 상태: 프로토타입 반영 · 기획안 미반영
- 변경 내용:
  - 링크로 축약했던 상세 내역을 판매가 구성, 재료, 부자재, 고정 지출, 세금, 손익 미리보기, 손익 변동 카드로 분리했다.
  - 기준 인분과 1인분 전환 구조, 소계, 권장 판매가를 실제 화면 순서대로 배치했다.
- 변경 이유: 계산 근거가 링크 뒤에 숨으면 메뉴 손익을 한 화면에서 검산하기 어렵다.
- 기획안 반영 포인트:
  - 레시피 상세의 계산 항목, 표시 순서, 기준 인분 전환 규칙
  - 각 소계와 손익 변동 상세의 연결 관계

### PRT-004 · 발주 주문과 입고 확정 흐름 분리

- 날짜: 2026-08-29
- 적용 화면: `order_detail`, `order_receive`
- 상태: 프로토타입 반영 · 기획안 미반영
- 변경 내용:
  - 발주 후보의 주문 입력과 입고 예정 건의 입고 확정을 별도 화면 흐름으로 구성했다.
  - 발주는 기록만 하며, 재고와 단가는 입고 확정에서 반영된다는 안내를 포함했다.
- 변경 이유: 발주 기록과 재고 반영 이벤트의 역할이 다르다.
- 기획안 반영 포인트:
  - 발주 등록 시 저장하는 값과 재고 비반영 원칙
  - 부분 입고와 입고 확정 시 재고·단가 전파 규칙

### PRT-005 · 수정 내역의 중복 이동 링크 제거

- 날짜: 2026-08-29
- 적용 화면: `ingredient_changes`
- 상태: 프로토타입 반영 · 기획안 미반영
- 변경 내용:
  - 화면 하단의 `재고 변동`과 `구매 이력` 링크를 제거했다.
- 변경 이유: 두 내역은 식재료 상세에서 이미 접근할 수 있고, 수정 내역 화면에서는 변경 기록에만 집중하는 편이 명확하다.
- 기획안 반영 포인트:
  - 수정 내역 화면은 직접 수정과 자동 갱신 기록만 제공한다.
  - 재고 원장과 구매 이력은 식재료 상세를 단일 진입점으로 사용한다.

### PRT-006 · 수정 내역 범위 안내 문구 제거

- 날짜: 2026-08-29
- 적용 화면: `ingredient_changes`, `recipe_changes`
- 상태: 프로토타입 반영 · 기획안 미반영
- 변경 내용:
  - `최근 7일 수정 내역만 표시합니다. 메모 변경과 재고 수량 변동은 포함하지 않습니다.` 안내를 제거했다.
- 변경 이유: 기간은 상단에서 이미 표시되고, 제외 항목 안내가 화면의 핵심 기록보다 더 눈에 띄어 불필요한 정보가 된다.
- 기획안 반영 포인트:
  - 최근 7일 필터와 제외 항목은 데이터 조회 규칙으로만 정의한다.
  - 화면 본문에는 별도 설명 문구를 노출하지 않는다.

### PRT-007 · 기준 단가 카드의 최근 입고 제목 위계 개선

- 날짜: 2026-08-29
- 적용 화면: `ingredient_detail`
- 상태: 프로토타입 반영 · 기획안 미반영
- 변경 내용:
  - 회색 메뉴형 `최근 입고` 헤더를 카드 내부의 하위 제목으로 변경했다.
  - 보조 문구를 `기준 단가를 계산한 입고 기록`으로 바꿨다.
  - 오른쪽에 포함 기록 수 `3건`을 표시했다. 이후 PRT-009에서 제거했다.
- 변경 이유: 기존 헤더가 별도 메뉴처럼 보여 기준 단가와 최근 입고 기록의 관계가 모호했다.
- 기획안 반영 포인트:
  - 기준 단가와 그 값을 만든 입고 기록은 한 카드로 구성한다.
  - 최근 입고 제목은 비동작 섹션 제목으로 사용한다.

### PRT-008 · 식재료 상세의 빈 상태 문구 단순화

- 날짜: 2026-08-29
- 적용 화면: `ingredient_detail`만 해당
- 상태: 프로토타입 반영 · 기획안 미반영
- 변경 내용:
  - 식재료 상세의 폐기 빈 상태 문구를 `폐기내역이 없습니다.`로 변경했다.
  - 폐기 빈 상태 카드에 `폐기 내역` 헤더를 추가했다.
  - 식재료 상세의 `구매 링크 · 옵션` 빈 상태 문구를 `등록된 구매링크가 없습니다.`로 변경했다.
  - 최초에는 `discard`, `options` 전용 화면을 변경하지 않았다. 이후 PRT-011에서 같은 문구로 통일했다.
- 변경 이유: 식재료 상세에서는 긴 안내보다 짧은 빈 상태 문구만 노출한다.
- 기획안 반영 포인트:
  - 이번 문구 변경 범위는 식재료 상세 화면 내부로 한정한다.
  - 폐기 빈 상태도 다른 상세 카드와 같은 헤더 구조를 사용한다.
  - 전용 내역·관리 화면의 빈 상태 문구는 별도 검토한다.

### PRT-009 · 식재료 상세 헤더의 우측 숫자 정보 제거

- 날짜: 2026-08-29
- 적용 화면: `ingredient_detail`
- 상태: 프로토타입 반영 · 기획안 미반영
- 변경 내용:
  - `기준 단가` 헤더 우측의 `입고 3건 기준`을 제거했다.
  - `최근 입고` 헤더 우측의 `3건`을 제거했다.
  - `현재 재고` 헤더 우측의 `812g`을 제거했다.
  - `구매 링크 · 옵션`의 `관리`는 숫자 정보가 아닌 동작 버튼이므로 유지했다.
- 변경 이유: 작은 보조 숫자가 잘 보이지 않으며, 본문에 같은 정보가 있어 헤더를 복잡하게 만든다.
- 기획안 반영 포인트:
  - 식재료 상세의 섹션 헤더는 제목 중심으로 구성한다.
  - 수량·건수·기준 설명은 헤더 우측에 중복 노출하지 않는다.
  - 헤더 우측에는 실제 동작이 필요한 버튼만 허용한다.

### PRT-010 · 식재료 상세 상단의 대표 구매처 뱃지 제거

- 날짜: 2026-08-29
- 적용 화면: `ingredient_detail`
- 상태: 프로토타입 반영 · 기획안 미반영
- 변경 내용:
  - 식재료명 위의 `식자재쇼핑몰` 구매처 뱃지를 제거했다.
  - `향신료·허브` 카테고리 뱃지만 유지했다.
- 변경 이유: 구매처는 입고마다 달라질 수 있어 상세 상단에서 하나를 대표값처럼 표시하면 오해할 수 있다.
- 기획안 반영 포인트:
  - 식재료 상세 상단에는 카테고리만 표시한다.
  - 구매처는 최근 입고 기록과 구매 링크·옵션에서 해당 기록별로 표시한다.

### PRT-011 · 폐기·구매 옵션 전용 화면의 빈 상태 문구 통일

- 날짜: 2026-08-29
- 적용 화면: `discard`, `options`
- 상태: 프로토타입 반영 · 기획안 미반영
- 변경 내용:
  - 폐기 내역 전용 화면의 빈 상태를 `폐기내역이 없습니다.`로 변경했다.
  - 구매 링크 · 옵션 전용 화면의 빈 상태를 `등록된 구매링크가 없습니다.`로 변경했다.
- 변경 이유: 식재료 상세과 전용 화면에서 같은 빈 상태가 서로 다른 문구로 노출되지 않도록 통일한다.
- 기획안 반영 포인트:
  - 동일한 데이터 빈 상태는 진입 화면과 전용 화면에서 같은 문구를 사용한다.
  - 추가 설명이 필요하지 않으면 한 문장만 노출한다.

### PRT-012 · 식재료 상세 수정 메뉴와 연결 화면 추가

- 날짜: 2026-08-29
- 적용 화면: `ingredient_detail`, `ingredient_edit_menu`, `ingredient_edit`, `stock_add`, `stock_edit`, `memo_edit`, `options`, `ingredient_delete`
- 상태: 프로토타입 반영 · 기획안 미반영
- 변경 내용:
  - 식재료 상세 헤더의 `수정`을 누르면 Expo와 같은 수정 메뉴 팝업이 열리도록 연결했다.
  - 팝업 항목을 `식재료 수정`, `재고 추가 (입고)`, `재고 수정 (실사)`, `메모 수정`, `구매 링크 · 옵션`, `식재료 삭제` 순서로 구성했다.
  - 화면 선택 탭에도 `수정`과 각 연결 화면을 추가해 팝업 이후 화면을 개별 확인할 수 있게 했다.
  - `재고 추가`의 상위 흐름을 식재료 상세 직결에서 수정 메뉴 경유로 변경했다.
  - 재고 수정·메모 수정은 실제 Expo의 시트 형태로, 삭제는 확인 팝업 형태로 노출했다.
- 변경 이유: 재고 추가를 독립 상세 화면처럼 보이게 하면 실제 앱의 `상세 → 수정 메뉴 → 재고 추가` 진입 구조와 다르게 이해할 수 있다.
- 기획안 반영 포인트:
  - 식재료 상세의 수정 메뉴 항목, 순서, 위험 동작 색상을 고정한다.
  - 입고는 `재고 추가`, 실사·완전 소진·폐기는 `재고 수정`으로 역할을 분리한다.
  - 수정 메뉴에서 전체 화면으로 이동하는 항목과 현재 상세 위에 시트·확인창으로 뜨는 항목을 구분한다.

### PRT-013 · 수정 메뉴 연결 화면을 3번째 탭 줄로 분리

- 날짜: 2026-08-29
- 적용 화면: 식재료 도메인의 프로토타입 화면 선택 영역
- 상태: 프로토타입 반영 · 기획안 미반영
- 변경 내용:
  - 1번째 줄은 도메인, 2번째 줄은 식재료의 주요 화면, 3번째 줄은 수정 메뉴 연결 화면으로 분리했다.
  - 3번째 줄에 `식재료 수정`, `재고 추가 (입고)`, `재고 수정 (실사)`, `메모 수정`, `구매 링크 · 옵션`, `식재료 삭제`를 순서대로 배치했다.

### PRT-045 · 구매 링크 중심 명칭·입력·목록 동작 개편

- 날짜: 2026-08-30
- 적용 화면: 식재료 상세·수정 메뉴·수정 폼, 구매 링크 목록·추가·수정, 재고 입고의 링크 선택, 발주 화면
- 상태: 프로토타입 반영 · PC/모바일 재검수 완료 · 기획안 미반영
- 문제점:
  - 핵심 행동은 외부 구매 페이지 이동인데 사용자 문구가 `구매 링크 · 옵션`, `구매 옵션`으로 나뉘어 있었다.
  - 구매 링크가 선택 입력이라 URL이 없는 항목도 같은 목록에 들어갈 수 있었고, 목록 행의 구매 이동과 수정 진입도 구분되지 않았다.
  - 구매처가 없을 때 새 구매처를 추가하려면 별도 선택창 안으로 다시 들어가야 했다.
- 수정안:
  - 사용자 노출 명칭을 `구매 링크`로 통일하고, 추가·수정·삭제·빈 상태·입고·발주 안내 문구를 함께 변경했다.
  - 구매 링크를 필수 항목으로 표시하고 `http://` 또는 `https://` 주소가 아니면 저장 버튼이 활성화되지 않도록 했다.
  - 구매처는 `(선택)`으로 두고 기본값을 `미선택`으로 변경했다.

  - 구매 링크 목록 행은 외부 구매 페이지 이동으로 사용하고, 수정은 우측 연필 버튼으로 분리했다.
  - 식재료 상세의 구매 링크 빈 상태 `＋ 구매 링크 추가`는 목록을 거치지 않고 추가 폼으로 바로 이동하게 했다.
- 기획안 반영 포인트:
  - 구매 링크는 URL이 필수인 외부 이동 항목이며, 구매처는 선택 속성으로 관리한다.
  - 목록의 기본 행 동작은 구매 페이지 열기, 수정은 별도 버튼으로 구분한다.
