# 식재료 상세 내역 화면 공통 UI 가이드

> 상태: 기획 기준 확정안 · 앱 미반영  
> 대상: ING-07 재고 내역 · ING-09 구매 이력 · ING-10 폐기 내역  
> 공통 비교 시안: [ingredient-history-common-ui.html](./prototypes/ingredient-history-common-ui.html)  
> 폐기 내역 단독 시안: [ingredient-discard-history.html](./prototypes/ingredient-discard-history.html)

## 1. 목적

식재료 상세에서 내역 화면으로 이동했을 때 화면마다 헤더, 필터 위치, 합계 카드, 목록 행이 달라 보이는 문제를 없앤다.

사용자는 화면을 바꿔도 아래 순서를 그대로 학습해야 한다.

1. 무엇의 내역인지 확인한다.
2. 유형과 기간을 고른다.
3. 전체 요약을 본다.
4. 월별 기록을 최신순으로 읽는다.

설계 근거는 다음과 같다.

- 구매 옵션은 앞으로 살 후보이고 구매 이력은 실제로 산 결과다: `식재료(잔여)_상세로직_유저시나리오_v3` §2.3.
- 식재료 상세는 최근 구매·입고 및 입출고·폐기·실사 기록으로 연결되어야 한다: 같은 문서 §3.4.
- 기준단가는 대표값과 실제 구매 이력을 함께 보여야 한다: 같은 문서 §8.6.
- 재고 수량 변화는 수정 내역에 복제하지 않고 재고 원장을 단일 출처로 둔다: `구현-변경점` §14.
- 기준단가는 실제 입고량으로 가중하며 구매 이력이 계산 근거다: `구현-변경점` §15·§18.

## 2. 적용 범위

| 화면 | 공통 가이드 적용 | 화면 역할 |
|---|---:|---|
| ING-07 재고 내역 | 전체 적용 | 입고·소진·폐기·조정이 쌓이는 수량 원장 |
| ING-09 구매 이력 | 전체 적용 | 실제 입고된 구매 결과와 단가 근거 |
| ING-10 폐기 내역 | 전체 적용 | 조리 전·후 폐기 기록과 폐기 손실 |
| 식재료 수정 내역 | 목록 규격만 적용 | 레시피와 공유하는 최근 7일 변경 원장 |
| 구매 링크·옵션 | 제외 | 내역이 아니라 구매 후보를 관리하는 편집 화면 |

수정 내역은 최근 7일 고정, 레시피와 공용, 상세 시트 제공이라는 별도 정책이 있으므로 기간 필터와 합계 규칙을 강제로 합치지 않는다. 다만 월 머리말과 목록 행의 크기·간격은 본 가이드에 맞춘다.

## 3. 공통 화면 구조

모든 내역 화면은 아래 순서만 사용한다.

```text
앱 헤더
유형 탭                 선택지가 있을 때만
기간·정렬 조건 / 건수
전체 요약               전체 탭에서만
월 머리말
월별 그룹 목록
빈 화면                 결과가 없을 때 목록 대신
기간·정렬 시트          조건 행을 눌렀을 때
```

화면별로 카드 순서를 바꾸거나 필터를 헤더·본문·시트에 나눠 배치하지 않는다.

## 4. 앱 헤더

### 4.1 제목

세 화면 모두 같은 제목 형식을 사용한다.

- `{식재료명} 재고 내역`
- `{식재료명} 구매 이력`
- `{식재료명} 폐기 내역`

식재료명이 길면 한 줄 말줄임하고 접근성 라벨에는 전체 제목을 제공한다. 글로벌 앱에서는 문자열을 이어 붙이지 않고 로케일별 제목 템플릿을 사용한다.

### 4.2 헤더 액션

- 왼쪽: 뒤로가기만 둔다.
- 오른쪽 `조회`, `필터` 텍스트 버튼은 두지 않는다.
- 기간과 정렬은 본문의 공통 조건 행에서 변경한다.

이렇게 해야 구매 이력처럼 헤더 액션이 없는 화면과 재고 내역처럼 `조회`가 있는 화면이 갈라지지 않는다.

## 5. 유형 탭

유형이 실제 목록 분류일 때만 헤더 바로 아래에 밑줄형 탭을 둔다.

| 화면 | 탭 |
|---|---|
| 재고 내역 | 전체 · 입고 · 판매 소진 · 폐기 · 조정 |
| 구매 이력 | 없음 |
| 폐기 내역 | 전체 · 조리 전 폐기 · 조리 후 폐기 |

규칙:

- 탭은 가로 스크롤을 허용해 번역 문구가 길어져도 잘리지 않게 한다.
- 건수가 1건 이상이면 라벨 뒤에 숫자를 붙인다: `전체 1`, `조리 전 폐기 1`.
- 0건은 숫자를 생략한다: `조리 후 폐기`.
- 숫자는 현재 선택 기간에 포함된 기록 수다.
- 유형은 탭에서만 바꾼다. 기간 시트에 같은 유형 선택을 다시 넣지 않는다.

## 6. 기간·정렬 조건 행

유형 탭 아래에 모든 화면이 같은 조건 행을 사용한다.

```text
최근 3개월 · 최신순 ⌄                              12건
```

규칙:

- 기본 기간: 최근 3개월.
- 기본 정렬: 최신순.
- 왼쪽 조건을 누르면 공통 필터 시트가 열린다.
- 오른쪽은 현재 유형과 기간에 맞는 기록 건수다.
- `조회`라는 별도 동작은 없다. 조건을 적용하면 바로 다시 조회한다.
- 조건 행과 실제 서버 조회 범위는 반드시 같아야 한다.

### 6.1 기간 선택지

`오늘 · 최근 1개월 · 최근 3개월 · 최근 6개월 · 최근 1년 · 전체`

### 6.2 정렬 선택지

`최신순 · 오래된순`

필터 시트에는 기간과 정렬만 둔다. 선택한 기간의 실제 시작일과 종료일을 시트 안에 표시한다.

## 7. 전체 요약 카드

### 7.1 공통 원칙

- 요약 카드는 화면당 최대 1개다.
- 유형 탭이 있는 화면에서는 `전체` 탭에서만 표시한다.
- 조리 전·후, 입고·소진 등 하위 탭마다 이름만 바꾼 합계 카드를 반복하지 않는다.
- 선택 기간의 목록과 같은 데이터로 계산한다.
- 설명, 조언, 원인 분석 문장은 넣지 않는다.

따라서 폐기 내역의 `조리 전 폐기 합계`와 `조리 후 폐기 합계` 카드는 만들지 않는다. 사용자가 하위 유형을 선택하면 목록만 필터링한다.

### 7.2 카드 골격

```text
요약 제목                                      대표값
보조 지표                                      보조값
```

필요한 화면만 두 개의 보조 지표를 좌우로 나눌 수 있다. 한 카드 안의 지표는 최대 3개다.

### 7.3 화면별 내용

#### 재고 내역

```text
현재 재고                                      13.5kg
입고 +125kg                         판매 소진 −111.5kg
```

- `현재 재고`는 현재값이다.
- 입고와 판매 소진은 선택 기간 합계다.
- 폐기와 조정은 합계 카드에 섞지 않고 해당 유형 목록에서 본다.

#### 구매 이력

```text
기준단가                                    5.00원/g
기간 최저 4.70원/g                 기간 최고 5.30원/g
```

- 기준단가는 전체 실입고량 가중평균이다.
- 최저·최고는 선택 기간의 실제 입고 기록에서 구한다.
- `지금까지 산 금액`처럼 기간 필터와 충돌하는 누적 문구는 사용하지 않는다.
- 입고 대기와 취소는 구매 이력에서 제외한다. 이 상태들은 발주 현황이 담당한다.

#### 폐기 내역

```text
전체 합계                                           6개
폐기 금액                                        1,800원
```

- 전체 탭에서만 표시한다.
- 조리 전·후 탭에서는 합계 카드를 숨긴다.
- `조리 전은 발주·보관을...`, `쓰기도 전에 상한 몫...` 같은 문장은 제거한다.

## 8. 월별 목록

### 8.1 그룹

- 모든 기록을 `YYYY년 M월` 머리말로 묶는다.
- 한 달의 기록은 카드 하나 안에 행으로 쌓는다.
- 기록마다 카드 하나를 만들지 않는다.
- 행 사이에는 `T.line2` 구분선만 둔다.
- 월이 바뀔 때만 카드 사이 간격을 둔다.

### 8.2 공통 행 골격

```text
08/20 · 상태 배지                         우측 대표값
사건 제목                                 우측 보조값
설명 또는 메모
```

공통 규격:

| 요소 | 규격 |
|---|---|
| 날짜 | 13~14 · 600 · `T.ter` |
| 상태 배지 | 11~12 · 700 · 짧은 상태만 |
| 제목 | 16 · 700 · `T.ink` · 한 줄 |
| 설명 | 14 · 400~600 · `T.sub2` · 필요할 때만 |
| 우측 대표값 | 16 · 800 · 숫자 탭 정렬 |
| 우측 보조값 | 13~14 · `T.ter` 또는 `T.sub2` |
| 행 패딩 | 세로 13~14 · 가로 15 |

메모가 없으면 빈 줄을 만들지 않는다.

### 8.3 화면별 행

#### 재고 내역

```text
08/20                                      −1kg
판매 소진                             잔량 13.5kg
김치찌개 13개
```

- 증가값은 파랑, 감소값은 빨강.
- 잔량은 서버 원장의 `balance`를 그대로 표시한다.
- 상세 동작이 없으므로 화살표를 넣지 않는다.

#### 구매 이력

```text
08/18 · 최고                           5.30원/g
식자재쇼핑몰
총 3kg · 15,900원
```

- 날짜 옆에는 `최저`, `최고`, `부분 입고`처럼 의미 있는 배지만 표시한다.
- 대표값은 해당 입고의 단가다.
- 총량을 먼저 쓰고 금액을 뒤에 둔다.
- 팩 구성은 반복되지 않을 때만 괄호로 보조한다.
- 별도 상세 화면이 없으면 화살표를 넣지 않는다.

#### 폐기 내역

```text
08/20 · 조리 전                             −6개
보관 중 변질                              1,800원
```

- 날짜 옆 배지는 `조리 전` 또는 `조리 후`다.
- 대표값은 폐기 수량, 보조값은 폐기 금액이다.
- 조리 전이며 삭제 가능한 기간에만 더보기 메뉴를 표시한다.
- 조리 후 폐기는 매출이 주인이므로 이 화면에서 삭제하지 않는다.

## 9. 누름·화살표·더보기 규칙

- 행을 눌렀을 때 상세 화면이나 시트가 열릴 때만 우측 화살표를 표시한다.
- 읽기 전용 행에는 화살표를 표시하지 않는다.
- 삭제 같은 부가 동작은 `⋮` 메뉴로 분리한다.
- 메뉴가 없는 행에 자리 맞춤용 빈 아이콘을 두지 않는다.
- 카드 전체와 내부 버튼에 서로 다른 동작을 중첩하지 않는다.

## 10. 문장과 빈 화면

### 10.1 제거할 문장

내역 화면에는 다음 성격의 문장을 두지 않는다.

- 행동 조언: “한 번에 사는 양을 줄여 보세요.”
- 원인 추정: “발주·보관을 손봐야 해요.”
- 매 탭마다 반복되는 설명.
- 화면의 숫자를 다시 풀어 쓴 안내.

이런 문구는 데이터가 적을 때는 맞아 보여도 기록이 쌓이면 실제 원인과 어긋날 수 있다.

### 10.2 빈 화면

빈 화면은 제목과 한 줄 설명까지만 사용한다.

```text
조리 후 폐기 기록이 없어요
선택한 기간에 해당하는 기록이 없습니다.
```

- 현재 선택 유형을 제목에 반영한다.
- 기간을 넓힐 수 있는 경우에만 기간 변경을 안내한다.
- 합계 카드는 빈 화면에서 숨긴다.

## 11. 공통 여백과 카드

| 항목 | 기준 |
|---|---|
| 화면 좌우 여백 | 16 |
| 블록 간격 | 11~14 |
| 카드 모서리 | 14 |
| 카드 테두리 | 1 · `T.line` |
| 카드 배경 | `T.surface` |
| 카드 머리 배경 | `T.surface2` |
| 월 머리말 좌우 여백 | 6 |
| 월 머리말과 카드 간격 | 7~8 |

내역 화면에만 별도 그림자, 색 배경, 큰 아이콘을 추가하지 않는다. 숫자 상태는 기존 토큰인 파랑·빨강·중립색으로만 구분한다.

## 12. 글로벌 표기 규칙

- 제목, 탭, 상태, 빈 화면 문구는 번역 키를 사용한다.
- 날짜는 문자열 `slice()` 조립이 아니라 로케일 날짜 포매터를 사용한다.
- 금액과 단가는 `@sikjae/core`의 로케일 포매터를 사용한다.
- 수량은 `formatQuantity()`, 단가는 `formatUnitPrice()`를 사용한다.
- 통화기호 위치와 소수 자릿수는 MY-08 설정을 따른다.
- 탭과 조건 행은 번역 길이에 따라 늘어나야 하며 고정 너비를 두지 않는다.
- 숫자 뒤에 한국어 조사나 단위를 문자열로 직접 붙이지 않는다.

## 13. 데이터 규칙

- 기간, 유형, 정렬, 건수, 합계, 목록은 한 쿼리 조건을 공유한다.
- 재고 내역 잔량은 서버가 계산한 `balance`만 사용한다.
- 구매 이력은 `received`와 `partial` 중 실제 받은 수량이 있는 행만 사용한다.
- 구매 이력 단가는 그 입고건의 `실제 결제금액 ÷ 실제 입고량`이다.
- 구매 이력 기준단가는 전체 실입고 기록의 양 가중평균이다.
- 폐기 내역은 `discard && !reverted`만 표시한다.
- 폐기 금액은 해당 시점 단가 스냅샷이 있으면 그 값을 우선 사용한다. 현재 기준단가로 과거 금액을 다시 쓰지 않는다.
- 스냅샷이 없는 과거 폐기 행은 금액을 숨기고 수량만 표시한다.

마지막 두 규칙은 현재 화면처럼 현재 기준단가를 모든 과거 폐기에 곱해 과거 손실이 바뀌는 문제를 막기 위한 필수 조건이다.

## 14. 공통 컴포넌트 제안

`apps/mobile/src/features/ingredients/components/history/` 아래에 다음 구성요소를 둔다.

| 컴포넌트 | 책임 |
|---|---|
| `HistoryScreenShell` | 헤더, 스크롤, 공통 여백 |
| `HistoryTypeTabs` | 유형 탭과 기간 내 건수 |
| `HistoryConditionBar` | 기간·정렬 조건과 결과 건수 |
| `HistorySummaryCard` | 전체 탭 요약 카드 골격 |
| `HistoryMonthGroup` | 월 머리말과 단일 그룹 카드 |
| `HistoryRow` | 날짜·배지·제목·설명·우측값 |
| `HistoryFilterSheet` | 기간·정렬 선택과 실제 날짜 범위 |

화면 파일은 데이터 매핑과 화면별 라벨만 담당한다. 패딩, 폰트, 구분선, 카드 모서리를 화면마다 직접 선언하지 않는다.

## 15. 현재 화면에서 바꿀 내용

### ING-07 재고 내역

- 헤더의 `조회` 제거.
- 유형을 조건 시트에서 꺼내 밑줄형 탭으로 이동.
- 조건 행을 `최근 3개월 · 최신순 / N건` 공통 형식으로 변경.
- 기존 월 그룹과 `LedgerRow` 데이터 규칙은 유지.

### ING-09 구매 이력

- 기간 필터와 월별 그룹 추가.
- 기록별 개별 카드를 월별 그룹 카드 하나로 통합.
- 입고 대기·취소 제거.
- 누적 구매금액 중심 요약을 `기준단가 + 기간 최저·최고`로 변경.
- 하단 단가 설명 문장 제거.

### ING-10 폐기 내역

- 기간·정렬 조건 행 추가.
- 전체 합계는 전체 탭에만 표시.
- 탭별 합계 카드와 조언 문장 제거.
- 기록별 개별 카드를 월별 그룹 카드 하나로 통합.
- 현재 기준단가로 과거 폐기 금액을 재계산하지 않도록 데이터 계약 보완.

## 16. 완료 조건

- 세 내역 화면의 헤더, 조건 행, 카드 폭, 월 머리말, 목록 행 높이가 같다.
- 유형 선택은 탭, 기간·정렬은 조건 시트 한 곳에서만 변경된다.
- 전체 외 탭에는 합계 카드가 없다.
- 구매 이력에는 실제 입고되지 않은 행이 없다.
- 기간을 바꾸면 탭 건수, 전체 요약, 목록이 함께 바뀐다.
- 0건 탭은 숫자를 표시하지 않는다.
- 설명이나 조언 문장이 합계 카드 아래 반복되지 않는다.
- 상세 동작이 없는 행에 화살표가 없다.
- 320px 폭과 긴 번역에서도 탭·값·단위가 겹치지 않는다.
- 날짜·금액·단위가 선택 로케일에 맞게 표시된다.
- 과거 폐기 금액은 당시 단가 스냅샷이 없으면 임의로 계산하지 않는다.
