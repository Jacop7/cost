# 사고 대응 진입점

사고 발생 시 새 정책을 즉석에서 만들지 않고, 영향 범위와 증거를 보존한 뒤 담당 권위로 연결한다.

1. 사용자·데이터·보안·운영 영향과 최초 관측 시각을 기록한다.
2. 추가 손상을 막는 비파괴 중단 조치를 우선하고 운영 변경은 사람에게 호출한다.
3. 현재 Task는 [작업큐](../작업큐.md), 환경·릴리스는 [릴리스 게이트](../team/RELEASE_GATE.md)에 연결한다.
4. 데이터 정정이 필요하면 [데이터 정정 진입점](./DATA_CORRECTION_POLICY.md), 복구가 필요하면
   [복구 진입점](./RUNBOOK_RECOVERY.md)으로 분리한다.
5. 실제 사후분석이 확정될 때만 `docs/operations/POSTMORTEMS/`에 새 원본을 만든다.

사고 종결·위험 수용·사용자 고지는 사람이 결정한다.
