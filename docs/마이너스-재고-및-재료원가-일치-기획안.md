# 마이너스 재고 및 재료 원가 일치 기획안

> 상태: 최종 기획 확정안
> 범위: 영업 시작·판매 전 재고 확인, 판매 소진, 재고 원장, 식재료 화면, 레시피 화면, 발주, 매출 손익, 재료 원가 상세
> 실제 앱·DB 코드는 이 문서 작성만으로 변경하지 않는다.

## 최종 확정 요약

- 판매에 필요한 전체 사용량을 차감하고 부족분은 음수 재고로 기록한다.
- 영업 시작과 판매 전에 부족 메뉴를 안내하지만 영업 시작·판매 자체는 막지 않는다.
- `재고 확인`에서는 부족한 레시피별로 식재료를 최대 3개까지 보여주고, 영업 시작 전에는 `안전재고 · 현재 재고`, 판매 전에는 `필요 수량 · 현재 재고`를 표시한다.
- 부족 식재료 행 전체를 `재고 추가` 단일 동작으로 사용하며, 누르면 해당 식재료의 재고 추가 화면을 바로 연다.
- `입고 등록 / 재고 수정` 선택 메뉴는 만들지 않는다.
- 재고 추가는 입고 이벤트로 기록해 재고·구매 이력·기준단가를 함께 갱신한다.
- 실제 수량 정정은 식재료 상세의 기존 `재고 수정`에서만 처리한다.
- 구매처는 저장된 구매 옵션을 선택하거나 직접 입력해야 하며 `미선택` 상태에서는 등록할 수 없다.
- 미해결 음수 재고는 자동으로 `0` 처리하지 않고 매출 화면 상단에 `식재료 부족 N개`로 계속 안내한다.

## 1. 배경

현재 판매량이 장부 재고보다 많으면 판매는 정상적으로 기록되지만 재고는 `0`까지만 차감된다.

예시:

| 구분 | 수량 |
|---|---:|
| 판매 전 소고기 재고 | 750g |
| 소불고기 10개에 필요한 양 | 1,500g |
| 현재 재고 차감 | 750g |
| 기록에서 사라지는 사용량 | 750g |

이 때문에 같은 날 같은 이름의 값이 서로 달라진다.

- 손익 계산의 재료 원가: 판매 당시 레시피 사용량 `1,500g` 기준
- 재료 원가 자세히: 재고 원장에서 실제 차감된 `750g` 기준
- 현재 재고: `0g`으로 고정

기존 설계는 “재고가 부족해도 판매는 막지 않는다”는 판단은 맞지만, 부족분을 장부에서 버려 원장과 손익이 갈라진다.

## 2. 설계 결정

### 2.1 핵심 원칙

1. 판매는 재고 부족 여부와 관계없이 기록한다.
2. 판매에 필요한 전체 사용량을 재고 원장에 기록한다.
3. 장부 재고가 부족하면 음수 잔액을 허용한다.
4. 화면에서도 음수 재고를 숨기지 않고 `−750g`으로 표시한다.
5. 재료 원가 자세히는 재고 차감액이 아니라 손익의 재료 원가를 식재료별로 분해한다.
6. 입고·재고 실사·판매 수정으로 음수 재고를 해소한다.
7. 음수 재고를 자동으로 `0`으로 보정하거나 과거 입고를 추정하지 않는다.

### 2.2 용어

| 용어 | 정의 |
|---|---|
| 장부 재고 | 입고·판매 소진·폐기·조정 이벤트를 모두 합산한 재고. 음수 가능 |
| 재고 부족 | 장부 재고가 0보다 작은 상태 |
| 부족량 | `abs(min(장부 재고, 0))` |
| 판매 사용량 | 판매 당시 레시피 1인분 사용량 × 판매 수량 |
| 재료 원가 | 판매 당시 단가 × 판매 사용량. 재고 보유량과 무관 |

`사용 가능 재고 = max(장부 재고, 0)`은 별도 화면 값으로 사용하지 않는다. 사용자에게는 실제 장부 상태인 음수 재고를 그대로 보여준다.

### 2.3 재고 상태 공통 기준

식재료·레시피·발주에서 서로 다른 상태명을 만들지 않고 `여유 / 소진 임박 / 소진` 3단계를 공통으로 사용한다.

| 장부 상태 | 화면 상태 | 색상 | 의미 |
|---|---|---|---|
| 재고 `<= 0` | 소진 | 빨강 | 현재 재고가 없거나 음수 장부가 발생함 |
| 재고 `> 0`이고 `soon_out = true` 또는 안전재고 이하 | 소진 임박 | 빨강 | 재고가 남아 있지만 발주가 필요한 상태 |
| 위 조건에 해당하지 않음 | 여유 | 초록 | 현재 재고 충분 |

`soon_out`은 사장님이 지정한 긴급 소진 신호이고, 안전재고 미달은 수량으로 계산하는 발주 신호다. 내부 발주 사유는 둘을 구분해 보관하지만 화면 상태는 둘 다 `소진 임박`으로 합친다.

`재고 부족 750g`은 상태명이 아니라 음수 재고의 부족량을 설명하는 안내 문구다. 상태 뱃지는 `소진`으로 표시하고 실제 수량은 `−750g`으로 표시한다.

## 3. 기준 사례

판매 전 재고가 `750g`이고 판매 사용량이 `1,500g`인 경우:

```text
판매 전 장부 재고      750g
판매 소진 이벤트    −1,500g
판매 후 장부 재고     −750g
재고 부족량             750g
```

식재료 화면:

```text
현재 재고
−750g                              소진
```

재고 내역:

```text
08/24  판매 소진
소불고기 10개
−1,500g                       잔량 −750g
```

매출 화면:

```text
재료 원가                     159,472원
매출 원가율                        23.8%
```

재료 원가 자세히도 동일한 `159,472원 · 23.8%`를 사용한다.

## 4. 화면 기획

### 4.1 식재료 목록

- 재고가 0 이상이면 기존 표시를 유지한다.
- 재고가 0 미만이면 수량을 빨간색으로 표시한다.
- 재고가 0 이하이면 상태 뱃지는 `소진`을 사용한다.
- 재고가 양수이면서 `soon_out`이거나 안전재고 이하이면 `소진 임박`을 사용한다.
- `−750g`을 `0g`으로 바꿔 표시하지 않는다.

예시:

```text
소고기 불고기감                              소진
−750g
```

### 4.2 식재료 상세

상단 재고 카드:

```text
소진
현재 재고                              −750g
안전재고                                  2kg
```

우선 행동:

- `재고 추가`
- 부족을 만든 판매 내역 확인

`재고 추가`는 실제로 구매한 재고를 등록하는 입고 흐름이다. 수량과 구매 금액을 기록해 재고·구매 이력·기준단가를 함께 갱신한다.

장부와 실제 수량을 맞추는 `재고 수정`은 기존처럼 식재료 상세의 수정 메뉴에서만 제공한다. 재고 부족 안내에서는 `재고 추가`와 `재고 수정`을 동시에 노출하지 않는다.

별도의 `사용 가능 재고 0g`은 노출하지 않는다.

### 4.3 재고 내역

- 판매 소진 행에는 전체 필요량을 표시한다.
- 행 우측 잔량도 음수로 표시한다.
- 음수 잔량과 차감 수량은 빨간색을 사용한다.
- 음수 발생 시점 이후의 입고·조정 흐름을 그대로 이어서 보여준다.

### 4.4 영업 시작·판매 전 재고 확인

재고 부족 때문에 영업 시작이나 판매를 막지는 않지만, 사용자가 부족 상태를 확인할 기회는 반드시 제공한다.

#### 영업 시작

- 영업 시작을 누르면 현재 재고로 1개 이상 만들 수 없는 레시피를 확인한다.
- 재고가 0 이하인 식재료가 연결된 레시피는 반드시 포함한다.
- 안전재고 이하이지만 현재 1개 이상 만들 수 있는 레시피는 영업 시작 경고에 포함하지 않고 `전체 부족 재고`에서 확인한다.
- 부족한 레시피가 있으면 다음 안내를 표시한다.

```text
현재 재고가 부족한 메뉴가 있어요

재고를 확인하거나 그대로 영업을 시작할 수 있어요.

[재고 확인] [그대로 영업 시작]
```

#### 판매

- 판매를 누르면 선택한 메뉴와 판매 수량에 필요한 식재료 전체량을 현재 장부 재고와 비교한다.
- 하나라도 부족하면 저장 전에 다음 안내를 표시한다.

```text
판매 수량보다 재고가 부족해요

재고를 확인하거나 그대로 판매할 수 있어요.

[재고 확인] [그대로 판매]
```

- `그대로 판매`를 누르면 판매를 한 번만 저장하고 전체 필요량을 차감한다.
- 경고 확인 후 판매 저장 요청을 다시 호출해 중복 판매가 생기지 않도록 한다.

#### 재고 확인

`재고 확인`을 누르면 부족한 레시피 목록을 보여준다.

- 레시피명 우측에 `부족 재료 N개`를 표시한다.
- 레시피 아래에는 부족한 식재료만 표시한다.
- 영업 시작 전에는 각 식재료에 `안전재고 · 현재 재고`를 표시한다.
- 판매 전에는 각 식재료에 `필요 수량 · 현재 재고`를 표시한다.
- `영업 시작 기준`, `1개 판매 기준` 같은 설명 문구는 표시하지 않는다.
- 식재료는 레시피당 최대 3개까지 먼저 표시하고, 3개를 초과하면 `N개 더보기`를 제공한다.
- 식재료 행 전체가 `재고 추가` 동작이며 우측 화살표로 이동 가능함을 표시한다. `입고 등록 / 재고 수정` 선택 메뉴는 제공하지 않는다.
- 같은 식재료가 여러 레시피에서 부족하더라도 재고 추가 결과는 모든 레시피에 즉시 다시 계산한다.

예시:

```text
소불고기                              부족 재료 4개

소고기 불고기감
필요 수량 1.5kg · 현재 재고 −750g                ›
```

특정 식재료의 `재고 추가`를 누르면 안전재고 이하 전체 목록을 다시 거치지 않고 해당 식재료의 재고 추가 화면을 바로 연다. 안전재고 이하 식재료 전체는 별도의 `전체 부족 재고 보기`로 분리한다.

#### 재고 추가

- 상단에는 식재료명, `현재 재고`, `기준단가`를 각각 한 행으로 표시한다.
- 음수 현재 재고는 빨간색으로 표시한다.
- 사용자 화면에는 `재고 추가` 흐름 하나만 표시한다.
- `재고 채우기 → 입고 등록/재고 수정` 선택 메뉴는 제공하지 않는다.
- 구매처는 저장된 `구매한 곳 · 옵션`을 선택하거나 `직접 입력`해야 한다.
- 최초값은 회색 `미선택`이며 이 상태에서는 등록 버튼을 비활성화한다.
- 직접 입력을 선택하면 구매처 입력란을 표시하고, 구매처명이 입력되어야 등록할 수 있다.
- `개당 용량 + 단위`, `입고 수량`, `실제 결제금액`, `입고일`을 입력한다.
- 용량과 결제금액은 0보다 커야 한다.
- 하단에는 등록 전후의 `재고`와 `기준단가`를 두 행으로 미리 보여준다.
- 등록하면 입고 이벤트로 기록하고 재고·구매 이력·기준단가를 함께 갱신한다.
- 실제 수량 정정은 이 흐름에서 제공하지 않고 식재료 상세의 `재고 수정`에서 처리한다.
- 등록 후에도 재고가 부족하면 남은 부족량을 다시 표시하고, 해소되면 해당 식재료를 부족 목록에서 제거한다.

#### 미해결 상태

- 부족 재고를 정리하지 않아도 사용자가 경고를 확인하면 영업 시작과 판매가 가능하다.
- 미해결 항목은 중복을 제거한 식재료 개수로 계산한다.
- 매출 화면 상단에는 빨간색 테두리·연한 빨간색 배경·삼각형 경고 아이콘과 함께 다음 문구를 표시한다.

```text
식재료 부족 N개
부족한 식재료의 재고를 추가해 주세요
```

- 안내 전체를 누르면 `재고 확인`으로 이동한다.
- 음수 재고를 자동으로 `0`으로 초기화하지 않는다.
- 영업 중에는 재고 부족으로 판매를 막지 않고 판매에 필요한 전체 사용량을 계속 차감한다.

### 4.5 판매 저장 직후 안내

판매 전 경고에서 `그대로 판매`를 선택했거나 판매 처리 중 새 부족이 발생해도 판매는 한 번만 저장한다. 저장 직후에는 긴 결과 팝업 대신 짧은 완료 안내를 표시하고, 미해결 상태는 매출 화면 상단 안내에 계속 남긴다.

```text
판매를 기록했어요 · 부족분은 음수 재고로 반영돼요
```

- 오류 팝업으로 표현하지 않는다.
- 동일 저장 요청에서 경고 때문에 판매를 다시 등록하지 않도록 한다.
- 상세 부족 식재료는 지속 노출되는 `식재료 부족 N개` 안내에서 확인한다.

### 4.6 재료 원가 자세히

화면 목적을 다음과 같이 고정한다.

> 손익 계산의 재료 원가를 식재료별·메뉴별로 분해해서 확인하는 화면

계산 기준:

```text
식재료별 사용량 = 판매 당시 1인분 사용량 × 판매 수량
식재료별 금액   = 식재료별 사용량 × 판매 당시 단가
```

- 재고 이벤트를 합산해 금액을 만들지 않는다.
- 조리 폐기 사용량은 재료 원가에서 제외하고 `폐기 손실`에만 포함한다.
- 식재료별 합계는 손익 계산의 재료 원가와 항상 같아야 한다.
- 재고가 부족해도 재료 원가 금액은 달라지지 않는다.

재고가 왜 줄었는지는 식재료의 `재고 내역`에서 확인한다. 재료 원가 자세히가 재고 원장과 손익 상세의 두 역할을 동시에 맡지 않는다.

### 4.7 레시피 안의 식재료

레시피 흐름에서 현재 식재료 재고를 보여주는 모든 위치도 동일한 장부 재고를 사용한다.

- 레시피 재료 검색: `재고 −750g`을 빨간색으로 표시하고 `소진` 상태를 함께 보여준다.
- 레시피 목록: 연결된 재료 중 하나라도 재고가 0 이하이면 `재료 소진` 뱃지를 표시한다.
- 레시피 상세: 각 식재료 행의 단가 옆에 현재 재고를 추가하고 `0g`으로 보정하지 않는다.
- 식재료 행을 누르면 동일한 음수 재고가 표시된 식재료 상세로 이동한다.
- 만들 수 있는 수량을 계산하는 화면이 생기면 결과는 최소 `0개`로 제한할 수 있지만, 그 근거가 되는 현재 재고 값은 `−750g`으로 보여준다.
- 재고가 부족해도 이미 발생한 판매 등록은 막지 않는다.

레시피 상세 식재료 행 예시:

```text
소고기 불고기감                         22,425원
30.00원/g · 재고 −750g              750g / 3.4%
```

- `재고 −750g`만 빨간색으로 표시한다.
- 재료명·단가·사용량·원가 금액은 기존 검정·회색 체계를 유지한다.
- 음수 재고 때문에 원가 금액이나 사용량을 `0`으로 바꾸지 않는다.

주의할 점:

- 레시피의 `사용량`과 `재료 원가`는 음수 재고와 무관하게 판매 당시 레시피·단가 기준으로 계산한다.
- 음수로 표시되는 것은 현재 장부 재고뿐이다.
- 레시피 사용량이나 단가를 음수로 바꾸지 않는다.

### 4.8 발주 현황

발주 후보 카드도 `order_board.stock_total`의 음수 값을 그대로 사용한다.

```text
소고기 불고기감                              소진

권장 발주                              현재 재고
3개                                      −750g
                                          안전 2kg
```

- 현재 재고 `−750g`은 빨간색으로 표시한다.
- 재고가 0 이하이면 상태는 `소진`으로 표시한다.
- 권장 발주량에는 음수 부족분이 포함된다.
- 발주 후보를 만든 내부 사유인 `safety_stock`과 `soon_out`은 계속 분리해 저장한다.
- 발주 등록은 기록일 뿐이므로 재고는 그대로 `−750g`이다. 실제 입고가 확정될 때만 재고가 증가한다.

## 5. 서버·데이터 기획

### 5.1 재고 잔액 제약

현재 `inventory_states.stock_total`에는 `stock_total >= 0` 제약이 있다. 신규 마이그레이션에서 해당 제약을 제거해 음수 장부 잔액을 허용한다.

단, 다음 값은 계속 음수를 허용하지 않는다.

- 입고 수량
- 폐기 입력 수량
- 판매 수량
- 레시피 사용량
- 단가와 금액
- 안전재고와 최소 발주량

음수를 허용하는 값은 계산 결과인 `현재 장부 재고`뿐이다.

읽기 API는 저장된 음수 값을 그대로 반환한다. 미등록 상태를 위한 `coalesce(..., 0)`은 유지할 수 있지만 `greatest(stock_total, 0)`처럼 저장된 음수를 0으로 바꾸는 보정은 사용하지 않는다.

### 5.2 레시피 조회 계약

현재 레시피 상세의 식재료 행에는 단가·사용량만 있고 현재 재고가 없다. `recipe_detail`의 각 식재료 줄에 다음 값을 추가한다.

| 필드 | 의미 |
|---|---|
| `stock_total` | 식재료 현재 장부 재고. 음수 가능 |
| `stock_state` | 기존 타입을 유지한 `out`·`low`·`ok` 공통 상태. 화면 문구는 소진·소진 임박·여유 |

- `stock_total`은 현재 재고이므로 레시피 원가 스냅샷과 섞지 않는다.
- 레시피 원가와 단가는 기존 계산 결과를 유지한다.
- 레시피 목록의 `blocked_by` 판정은 재고 `<= 0` 기준을 유지하되, 음수 값 자체는 상세와 재료 검색에서 확인할 수 있게 한다.

### 5.3 판매 소진

판매 소진은 재고에서 실제 보유량만 빼는 방식이 아니라 판매 당시 필요량 전체를 차감한다.

```text
after = before − required_quantity
```

원장 이벤트:

```text
count_delta = −required_quantity
```

응답에는 다음 값을 포함한다.

| 필드 | 의미 |
|---|---|
| `stock_before` | 판매 전 장부 재고 |
| `required` | 이번 판매의 전체 필요량 |
| `stock_after` | 판매 후 장부 재고 |
| `shortage_total` | 판매 후 누적 부족량 |
| `shortage_added` | 이번 판매로 새로 늘어난 부족량 |

이미 `−750g`인 상태에서 `200g`을 추가 소진하면 `stock_after = −950g`, `shortage_added = 200g`이다.

### 5.4 판매 수정·취소

- 판매 취소는 원래 소진 이벤트 전체에 대한 반대 부호 이벤트를 추가한다.
- 판매 수량 감소는 차이만큼 복구한다.
- 판매 수량 증가는 차이만큼 추가 차감하며 음수 잔액을 허용한다.
- 기존 이벤트를 삭제하거나 원래 수량을 덮어쓰지 않는다.

예시:

```text
판매 소진       −1,500g
판매 취소 보정  +1,500g
```

### 5.5 입고와 재고 실사

- 입고는 음수 재고에 그대로 더한다.
- `−750g` 상태에서 `1,000g` 입고 시 `250g`이 된다.
- 재고 부족 흐름의 `재고 추가`는 입고 이벤트로 저장한다.
- 재고 추가 시 수량과 구매 금액을 함께 받아 구매 이력과 기준단가에 반영한다.
- 구매처는 저장된 구매 옵션 선택 또는 직접 입력 중 하나가 필수다. `미선택`은 입력 전 상태일 뿐 저장 가능한 값이 아니다.
- 구매처와 구매 옵션은 입고 출처를 식별하기 위한 값이며 기준단가 계산식에는 사용하지 않는다.
- 재고 실사는 사용자가 확인한 실제 수량으로 장부를 맞춘다.
- 실사 입력값은 0 이상이어야 하며, 차이는 조정 이벤트로 기록한다.
- 재고 수정은 기존 수량에 입력값을 더하는 기능이 아니라 입력한 실제 수량으로 현재 재고를 맞추는 기능이다.

예시:

```text
실사 전 장부 재고  −750g
실제 확인 재고       500g
재고 조정          +1,250g
실사 후 장부 재고    500g
```

### 5.6 폐기와 입고 취소

판매 소진과 폐기는 같은 정책을 사용하지 않는다.

- 판매 소진은 이미 발생한 판매의 레시피 필요량 전체를 기록하므로 음수 재고를 허용한다.
- 폐기는 사용자가 확인한 현재 잔량을 저장하는 흐름이므로 기존처럼 기록된 재고 범위 안에서 폐기량을 계산한다.
- 장부보다 실제 재고가 더 많아 추가 폐기가 필요하면 먼저 재고 실사로 실제 수량을 맞춘 뒤 폐기를 기록한다.
- 폐기를 음수까지 허용하면 장부에 없던 재료도 폐기 손실 금액으로 잡혀 월 손익이 커질 수 있으므로 이번 범위에서는 허용하지 않는다.
- 향후 폐기 입력을 ‘남은 양’이 아니라 ‘버린 양’으로 바꾸더라도, 초과 폐기의 손익 반영 정책을 별도로 결정해야 한다.

입고 취소는 잘못 기록된 입고 전체를 되돌리는 사건이므로 결과가 음수가 되더라도 허용한다.

- 마이그레이션 0038의 `e11_inbound_reverted`는 과거에 구매단위 개수에서 기준단위 g을 빼고 `greatest(..., 0)`으로 잘라 재고를 통째로 날린 사고가 있었던 경로다.
- 새 로직도 입고 이벤트의 기준단위 총량을 그대로 반대 부호로 기록해야 한다.
- 현재처럼 ‘있는 만큼만 취소하고 나머지는 미반영’으로 남기지 않는다.
- 단위는 항상 기준단위(g/ml/개)로 맞추고 원래 입고 이벤트를 직접 수정하거나 삭제하지 않는다.

### 5.7 발주 후보

`refresh_order_candidate()`의 기존 공식을 새로 바꾸지 않는다. `stock_total`에 음수가 들어갈 수 있도록 제약과 읽기 경로만 수정한다.

```text
후보 사유가 존재할 때
권장 발주 개수 = greatest(
  ceil((안전재고 − 장부 재고) / 구매 옵션 용량),
  최소 발주 개수
)
```

- 안전재고 미달과 `soon_out`은 기존과 같이 서로 다른 후보 사유로 유지한다.
- 후보 사유가 없으면 기존처럼 발주 후보를 삭제한다.
- 안전재고보다 1g 부족하더라도 구매 옵션과 최소 발주 단위 때문에 최소 발주 개수가 추천되는 현재 동작을 유지한다.
- 음수 재고는 `안전재고 − 장부 재고`에 자연스럽게 포함되므로 별도의 부족량 덧셈을 추가하지 않는다.

예시:

```text
안전재고      2,000g
장부 재고      −750g
구매 옵션 용량 1,000g
최소 발주          1개
권장 발주          3개
```

### 5.8 기준단가

음수 재고는 기준단가를 변경하지 않는다.

- 기준단가는 0072의 `쓴 돈 ÷ 실제 들어온 양` 가중평균만 사용한다.
- 판매 소진·폐기·입고 취소로 재고 잔액이 음수가 되어도 기준단가 공식에 재고 잔액을 넣지 않는다.
- 대파 검산값 `4,000원 ÷ 1,000g = 4.00원/g`은 그대로 유지한다.
- 음수 재고를 해소하기 위해 새 입고를 등록하면 그 입고의 금액과 들어온 양만 기존 가중평균 규칙에 반영한다.

## 6. 손익과 재고의 역할 분리

| 질문 | 권위 데이터 |
|---|---|
| 판 메뉴의 재료 원가는 얼마인가 | 판매 당시 레시피·단가 스냅샷 |
| 어떤 식재료가 원가를 만들었나 | 동일 스냅샷을 식재료별로 분해 |
| 재고가 얼마나 줄었나 | 재고 원장 이벤트 |
| 현재 재고가 부족한가 | 재고 원장 합계 |
| 조리 후 버린 원가는 얼마인가 | 조리 폐기 수량 × 판매 당시 재료 원가 |
| 보관 중 버린 식재료 손실은 얼마인가 | 식재료 폐기량 × 폐기 당시 단가 |

재료 원가 상세를 판매 스냅샷 기준으로 바꾸더라도 재고 원장은 계속 전체 소진량을 기록해야 한다. 두 변경은 서로 대체 관계가 아니다.

## 7. 기존 원칙 재정의

기존 `가이드 §2 불변식 6`은 “금액과 수량은 음수가 될 수 없다”고 정의돼 있고, 현재 DB 테스트도 음수 재고가 없음을 단언한다.

다음과 같이 범위를 명확히 바꾼다.

> 사용자 입력 수량·단가·금액은 음수가 될 수 없다. 단, 입고·판매 소진·폐기·조정 이벤트의 합으로 계산되는 장부 재고 잔액은 현실과 기록의 불일치를 보존하기 위해 음수가 될 수 있다.

`AGENTS.md`와 `CLAUDE.md`의 “재고 상태는 여유/소진 임박 2단계” 규칙도 다음과 같이 함께 개정해야 한다.

> 재고 상태는 여유/소진 임박/소진 3단계다. 재고가 0 이하이면 소진이며, 음수 수량은 0으로 보정하지 않고 빨간색으로 그대로 표시한다.

이 문서만 바꾸고 프로젝트 작업 지침을 그대로 두면 다음 작업자가 3단계 상태를 2단계로 되돌릴 수 있으므로 구현 작업과 같은 변경 단위에서 함께 갱신한다.

관련 근거:

- `docs/7h-worklog.md`의 5주기 결함 I: 기존에는 판매 부족분을 기록하지 않고 `0`에서 중단
- `docs/구현-변경점.md` §10: 매출 화면 금액은 판매 당시 스냅샷 기준으로 고정(0058·0059)
- 마이그레이션 0016: 재고가 부족해도 이미 발생한 판매는 막지 않음
- 절대원칙 4: 취소·수정은 삭제가 아니라 반대 부호 이벤트로 기록

## 8. 기존 데이터 처리

- 마이그레이션 이전에 0에서 잘린 부족분은 재고 잔액에 자동 소급하지 않는다.
- 과거 판매 스냅샷이 존재하는 기간의 재료 원가 상세는 판매 기준으로 다시 계산할 수 있다.
- 과거 재고 부족분을 자동으로 장부에 넣으면 이후 실사·입고 기록과 충돌할 수 있으므로 사용자의 재고 실사 없이 보정하지 않는다.
- 신규 규칙 적용 시점 이후의 판매부터 음수 장부를 정확히 누적한다.

## 9. 적용 순서와 롤백

재료 원가 일치와 음수 재고는 독립 변경으로 나눠 배포한다.

### 9.1 1단계 — 재료 원가 일치

먼저 `sales_material_usage`를 판매 스냅샷 기준으로 변경한다.

- `139,853원`과 `159,472원`으로 갈리던 재료 원가를 손익 기준 `159,472원`으로 일치시킨다.
- 재고 제약이나 재고 잔액은 건드리지 않는다.
- 함수 하나와 조회 테스트 중심이라 위험과 되돌리기 범위가 작다.
- 문제가 생기면 이전 `sales_material_usage` 함수만 복구할 수 있다.

### 9.2 2단계 — 음수 재고

1단계가 안정화된 뒤 다음 변경을 묶어서 적용한다.

- `stock_total >= 0` 제약 제거
- 판매 소진 전체량 기록
- 판매 수정·취소 전체량 보정
- 입고 취소 전체량 반대 이벤트 기록
- 식재료·레시피·발주 음수 표시
- 발주 후보에 음수 재고 반영 확인

### 9.3 롤백 조건

이 절은 사용자 영업 흐름이 아니라 배포 후 심각한 문제가 확인됐을 때 개발팀이 기존 방식으로 되돌리는 규칙이다.

1. 음수 재고를 자동이나 일괄 처리로 `0`으로 변경하지 않는다.
2. 남아 있는 음수 재고는 식재료의 `재고 수정`으로 실제 보유 수량에 맞춘다.
3. 모든 음수 재고가 실제 수량으로 정정됐는지 개발 검산을 수행한다.
4. 검산이 끝난 뒤 이전 판매 소진 함수와 비음수 DB 제약을 복구한다.
5. 영업 종료나 매출 입력 중단을 사용자 필수 조건으로 두지 않는다.

재고 원장과 현재 재고의 기술적 일치 검사는 개발 테스트에서 수행하며 사용자에게 요구하지 않는다.

## 10. 테스트 기준

### 10.1 필수 서버 테스트

1. 재고 `750g`에서 `1,500g` 판매 소진 후 재고가 `−750g`이다.
2. 소진 이벤트는 `−1,500g`으로 기록된다.
3. 동일 판매 재호출은 재고를 다시 차감하지 않는다.
4. 판매 취소 후 재고가 `750g`으로 복구된다.
5. 음수 재고에 입고하면 산술 합계대로 복구된다.
6. 재고 원장 합계와 `inventory_states.stock_total`이 항상 같다.
7. 재료 원가 상세 합계와 손익 계산의 재료 원가가 항상 같다.
8. 조리 폐기는 재료 원가가 아니라 폐기 손실로만 집계된다.
9. 발주 추천량에 음수 부족분이 포함된다.
10. 판매 수량·입고 수량·단가 등 사용자의 음수 입력은 계속 거부된다.
11. 폐기는 기록된 재고 범위 안에서만 손실로 잡히며 음수 재고를 새로 만들지 않는다.
12. 입고 취소는 원래 기준단위 입고량 전체를 반대 이벤트로 기록하고 결과가 음수여도 원장과 잔액이 일치한다.
13. 음수 재고 전후에도 기준단가와 대파 검산값 `4.00원/g`이 변하지 않는다.
14. 기존 `refresh_order_candidate()` 공식에 음수 재고를 넣었을 때 구매 옵션 단위의 권장 개수가 정확하다.

### 10.2 필수 화면 테스트

1. 식재료 목록과 상세에 `−750g`이 빨간색으로 표시된다.
2. 재고 내역의 판매 소진량과 잔량이 각각 `−1,500g`, `−750g`으로 보인다.
3. 판매 저장은 성공하고 재고 부족 안내가 한 번만 표시된다.
4. 안내에서 식재료 상세로 이동할 수 있다.
5. 재료 원가 상세와 손익 계산의 금액·비율이 동일하다.
6. 입고 후 재고가 양수가 되면 `소진` 상태를 다시 계산한다.
7. 레시피 재료 검색에 `재고 −750g`이 빨간색으로 표시된다.
8. 해당 식재료가 연결된 레시피 목록에 `재료 소진` 뱃지가 표시된다.
9. 레시피에서 식재료 상세로 이동해도 동일한 `−750g`이 표시된다.
10. 레시피 상세 식재료 행에 `단가 · 재고 −750g`이 표시되고 원가·사용량은 기존 값이 유지된다.
11. 식재료 목록·상세와 레시피·발주 화면이 모두 같은 `out` 상태를 사용한다.
12. 발주 후보 카드의 현재 재고가 `−750g`으로 표시되고 권장 발주량에는 부족분이 포함된다.
13. 영업 시작 시 만들 수 없는 레시피가 있으면 `재고 확인 / 그대로 영업 시작` 안내가 표시된다.
14. 판매 수량 기준으로 재고가 부족하면 `재고 확인 / 그대로 판매` 안내가 표시된다.
15. `재고 확인`에서 레시피별 `부족 재료 N개`가 표시된다.
16. 영업 시작 전 식재료 행에는 `안전재고 · 현재 재고`, 판매 전에는 `필요 수량 · 현재 재고`가 정확히 표시된다.
17. 레시피당 식재료는 최대 3개가 먼저 표시되고 초과분은 `N개 더보기`로 확인한다.
18. 부족 식재료 행을 누르면 입고 등록·재고 수정 선택 메뉴 없이 해당 식재료의 재고 추가 화면이 바로 열린다.
19. 재고 추가 화면의 `현재 재고`와 `기준단가`가 각각 한 행으로 표시되고 음수 재고는 빨간색이다.
20. 구매처 `미선택` 상태에서는 저장할 수 없고, 저장된 옵션 선택 또는 직접 입력 완료 시에만 저장할 수 있다.
21. 재고 추가 후 부족 여부가 다시 계산되고 같은 식재료가 연결된 모든 레시피에 반영된다.
22. 경고 후 `그대로 영업 시작`과 `그대로 판매`가 정상 동작하며 판매 저장은 한 번만 수행된다.
23. 미해결 부족 재고는 매출 화면 상단의 삼각형 경고 아이콘과 `식재료 부족 N개` 안내에 계속 표시된다.

## 11. 변경 대상 예상

### DB

- `inventory_states.stock_total >= 0` 제약 제거
- 판매 소진 RPC의 `least`·`greatest(..., 0)` 제거
- 판매 수정·취소의 전체 수량 보정 검증
- 폐기 RPC는 초과 폐기로 음수를 만들지 않는 현재 정책 유지
- `e11_inbound_reverted`의 전체 기준단위 반대 이벤트 및 음수 결과 허용
- `sales_material_usage`를 판매 스냅샷 기준으로 변경
- `recipe_detail` 식재료 줄에 현재 `stock_total`·`stock_state` 추가
- 기존 `refresh_order_candidate()` 공식에 음수 재고가 그대로 들어가는지 검산
- 기준단가 계산이 재고 잔액을 참조하지 않는지 회귀 테스트

### Core

- 부족량 계산 순수 함수 추가
- 기존 `out`·`low`·`ok` 타입을 소진·소진 임박·여유 문구로 통일
- 기존 발주 추천량 계산식의 클라이언트 검산 동기화
- 음수 재고 표시 포맷 검산

### App

- 식재료 목록·상세의 음수 재고 표시
- 재고 내역 음수 잔량 표시
- 레시피 재료 검색·목록·상세의 음수 재고 및 소진 상태 표시
- 발주 후보 카드의 음수 현재 재고 표시
- 영업 시작·판매 전 부족 안내와 부족 레시피 확인 화면
- 부족 식재료의 `재고 추가` 단일 동작 및 해당 식재료 재고 추가 화면 연결
- 재고 추가 화면의 구매처 옵션 선택·직접 입력 필수 검증과 등록 전후 미리보기
- 매출 화면 상단의 삼각형 경고 아이콘과 미해결 `식재료 부족 N개` 표시
- 판매 저장 후 부족 결과 안내와 재고 확인 이동
- 재료 원가 자세히의 데이터 설명 및 합계 일치
- `AGENTS.md`·`CLAUDE.md` 재고 상태 표기 규칙을 3단계로 함께 갱신
