# 제품 용어 정의 및 영문화 기준

> 상태: **한국어 핵심 용어 1차 확정 · 전체 소스 1차 전수 대조 완료 · 영어 UI 개발 보류**
> 이 문서는 영문 번역표가 아니라 용어 결정 작업표다. 현재 권위는 `ARCHITECTURE.md`,
> `apps/mobile/src/features/README.md`, DB/RPC 계약, `AGENTS.md`이며 서로 충돌하면 번역을 만들지 않고
> 충돌부터 해결한다.

## 1. 목적

같은 한국어가 서로 다른 원장 의미를 가리키거나, 같은 개념이 화면마다 다른 이름으로 보이는 문제를
먼저 없앤다. 공식 한국어 용어와 의미 키가 확정된 뒤 영어를 별도 검수한다. 한국어 표시 문자열을
그대로 번역 키로 삼지 않는다.

적용 프로토타입에는 317개 용어 개념이 있으나 화면 구현과 어긋난 항목이 남아 있다. 따라서
`docs/prototypes/0_full-page-flow-prototype-ui-applied.html`의 용어 사전은 수집 자료로만 사용하며,
이 문서에서 결정 상태가 `확정`된 항목만 영문화 입력으로 사용할 수 있다.

## 2. 결정 단위

각 용어는 다음 항목을 함께 확정한다.

- **의미 키**: 화면 문구가 바뀌어도 유지되는 식별자
- **공식 한국어**: 사용자에게 보여 줄 기본 명칭
- **정의**: 원장·계산에서 가리키는 정확한 대상
- **적용 문맥**: 제목, 버튼, 필드, 상태, 원장 행 등
- **구분 용어**: 섞으면 안 되는 인접 개념
- **내부 식별자**: DB/RPC·라우트·코드에서 유지할 이름
- **결정 상태**: `확정`, `문맥별 확정`, `검토 필요`

영어 용어는 이 표의 결정 상태가 확정된 뒤 별도 열과 검수 이력으로 추가한다.

## 4. 먼저 해결할 충돌

1. **재료 용어의 잔여 표기**: 공식 품목·영역명은 재료, 비용은 재료 원가, MY 화면명은 재료 설정으로
   확정했다. 실제 화면에 남은 식재료·식재료 원가 표기를 의미 키별로 바꾸고 내부 식별자와 원장 원문은 보존한다.
2. **재료비 소계의 범위**: 메뉴 폼 안의 구성 합계는 재료비 소계를 유지한다. 손익 행과 상세 화면의
   재료 원가로 확대하거나 반대로 손익을 재료비로 되돌리지 않는다.
3. **매출과 순매출**: 세금 포함/별도 국가에서 사용자가 입력한 판매가, 고객 결제액, 손익의 매출을
   명확히 분리한다.
4. **전체 화면 대조**: 2026-09-21 기준 Expo 331개 TypeScript 파일, AppMap, 적용 프로토타입,
   현재 프로토타입 규격의 한국어 표시 문자열을 전수 추출했다. 6,896개 출현 문구와 사용자 노출 가능성이
   높은 고유 문구 1,464개를 317개 용어 개념과 대조했다. 아직 사전과 문자상 일치하지 않는 205개 후보는
   금액·날짜·사용자 입력 예시, 완성 안내문, 디자인 수치, 동적 조합 문구를 포함하므로 곧바로 공식 용어로
   승격하지 않는다. 출처와 판정 입력은 `docs/prototypes/terminology-source-audit.json`에 보존한다.

## 5. 전수 대조 운영 규칙

1. `node scripts/terminology-source-audit.mjs`로 Expo·AppMap·프로토타입·표시 계약을 다시 추출한다.
2. 사전에 없는 원문은 독립 업무 개념인지 먼저 판정한다. 금액·수량·날짜 예시, 사용자 입력값,
   확인창 전체 문장, 접근성 설명 전체 문장, CSS·디자인 규격은 용어 개념으로 만들지 않는다.
3. 같은 단어라도 원장 사건·상태·설정·행동이 다르면 문맥별 개념으로 분리한다. 내부 식별자와 과거 원장
   원문은 사용자 표시 용어에 맞춰 일괄 치환하지 않는다.
4. `반영완료`는 Expo와 적용 프로토타입에서 같은 의미와 문맥이 확인된 항목만 유지한다. 사전에 새로
   수록했다는 사실만으로 반영완료가 되지 않는다.
5. 감사 보고서의 미수록 후보가 0이 되는 것을 목표로 삼지 않는다. 모든 후보에 출처가 있고, 사전 개념으로
   만들지 않은 이유를 다시 확인할 수 있는 상태를 목표로 한다.

## 6. 영문화 재개 조건

다음 조건을 모두 충족하기 전에는 영어 탭이나 영어 리소스를 다시 만들지 않는다.

1. 한국어 전체 화면 문자열을 의미 키에 연결했다.
2. `검토 필요` 항목의 공식 한국어와 정의가 확정됐다.
3. 같은 의미 키가 화면마다 다른 회계·원장 의미로 쓰이지 않는지 검산했다.
4. 사용자 입력 이름·메모·원장 원문을 번역 대상에서 제외했다.
5. 영어 후보를 단어 대 단어 번역이 아니라 정의와 문맥을 기준으로 검수했다.
6. 구현은 소스 컴포넌트의 안정적인 의미 키를 사용하고 DOM 문자열 치환을 사용하지 않는다.

영문화가 재개되면 `Menu`처럼 메뉴판 전체로 오해될 수 있는 단독 표현을 그대로 확정하지 않는다.
판매 단위, 재고 사건, 손익 항목은 각 의미 키의 정의를 기준으로 영어 용어를 선택한다.
